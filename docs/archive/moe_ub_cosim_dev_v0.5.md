## 3. 修正资源和等待条件

### 3.1 工作划分与有限资源

以所选源码的 AIV 工作划分为起点。AIV 是执行向量处理的计算核；每个核处理哪些 Token 或专家贡献、使用哪些局部缓冲、何时可以处理下一份数据，应能够逐项对应到来源。

取消将整个 rank 一至两个未完成 SEND 任务作为该通信基线真实资源的默认做法。同时核对每条逻辑发送序列等待上一整份事务完成的依赖，不能只放宽全局配额而保留另一层相同限制。不能直接把配额改为八个，也不能改为无限并发来制造网络竞争。

局部缓冲、搬运或提交资源、协议在途请求池分别说明作用范围、容量、占用和释放事件。下层有限资源保留，避免上下层对同一容量重复计数。核数与分工按固定调用的 tiling 规则生成；缺少依据的硬件容量单独参数化，注明选值和适用范围，不称为设备实测规格。

还要检查全部 COMP 共用一个 rank 计算槽是否会把新表达的独立通信核重新串行化。确有必要时，只拆分本轮涉及的局部处理资源；普通算子继续采用参考成本，不扩展为完整计算微架构。

### 3.2 分别表示不同完成事件

| 事件 | 对执行的作用 |
|---|---|
| 本地缓冲可复用 | 允许使用该缓冲准备下一份数据 |
| 目标业务数据到齐 | 满足对应数据的消费条件，不自动满足所有应用状态条件 |
| 应用计数或完成标志到达 | 满足所选源码规定的同步条件 |
| 发起方协议资源完成 | 释放对应协议请求资源，不能提前回收仍在途的请求 |
| 局部处理或算子完成 | 按实际依赖允许后继工作继续 |

事件是否重合由所选路径的语义决定。核内流水事件不能直接解释成整份网络任务的远端确认；也不能反过来认定本地资源必然在提交时释放。缺少依据时，声明一个可检查的参考关系，并将可能影响研究判断的替代假设留给定向敏感性检查。

必要的本地和网络事件必须来自真实执行对象。不得给导出时间戳添加或删除延迟，不得用单纯推迟应用回调冒充端点内存服务。

### 3.3 准备、传输与归约

所选源码允许部分数据准备好后发送时，模型应当允许这些数据先进入网络，不能统一等待整个 rank 的全部准备结束。某个 Token 的结果已经满足局部归约条件时，不额外等待无关 Token；源码确实要求的核内、跨核和算子完成条件继续保留。

局部 Token 归约可以开始，不等于下一层计算已经可以开始。后继算子仍遵循所选执行方式的实际启动条件，不能自行引入跨算子流水。

量化、打包、重排和归约继续用耗时模型表达。拆分节点后核对实际工作量及各成本的覆盖范围，避免重复计费或漏计。同一语义下应保留原有工作量，执行重叠可以改变总耗时；确实因模型修正改变工作内容时，单独说明差异。

### 3.4 网络假设

保留实际路径、链路服务、排队和流控，不用预先分配端口字节或固定发包时刻替代。STORE/STORE 使用已有原生逐包喷洒能力，明确源出口、交换出口及平面候选范围，不新增 URMA 多 TP 功能。

原生事务粒度、请求池和整包接收后转发等参考行为需在有效配置与模型依据中明确。缺少目标协议或芯片资料时，不擅自改为更有利的直通模型。对这些假设高度敏感的现象应限制结论或暂停候选，不能自动扩展成本版的协议重建任务。

## 4. 解释等待所需的内部事实

优先读取已有任务、回调、资源和队列记录；解释确实缺项时再增加有界记录。以实际数据交付及其接收方为单位，核验数据准备与提交、等待资源及释放、业务数据与应用状态到达、后继具备条件与实际开始四组事实。

现有 `data_ready` 阶段汇总业务、应用状态及同芯片交付，不能直接当成最后一个业务数据包到达。缺少逐数据事实时标明缺失，不能用首次发包、队列为空或另一回调替代。不同核、Token 和传输之间可能重叠，累计等待量不能直接相加为可节省的整轮时间。

新增内部身份与详细状态默认只供核验和评价，不自动开放给测量程序。公开端侧字段另行说明现实采集依据；仿真能记录不表示硬件已有接口。改变旧字段含义时应明确升级格式，不静默替换定义。

正常探索保留操作级事实与端口聚合；详细任务、逐包或信用记录仅对选定范围开放，并设置条数、字节和覆盖上限。启停记录不得改变调度、随机数消耗、发包和完成结果。记录溢出或覆盖不足必须显式报告，不能静默丢弃后宣称完整。

## 5. 保留目标规模的有限层段

复用已有模型与构图代码，支持从明确初态生成有限个连续 MoE 层及其相关计算。目标输入保留 128 rank、256 专家、Top-8、隐藏维度 7168、既有专家放置和参考物理网络。功能测试可以使用小模型；真实路由不得通过压缩专家编号变成小模型后继续称为 R1 场景。

层段的起始层、层数、Decode 步骤、请求及专家选择、上下文长度、KV 初态、相关计算和入口就绪条件均进入有效输入。层编号继续对应原模型与路由文件，不循环、拼接或补造缺失数据。容量仍按声明部署核算，少执行几层不自动意味着模型权重已经释放。

研究方案建议先执行三个连续 MoE 层，主要分析后两层，并用一个较长片段检查初态影响。具体选择属于实验输入，不写死在平台中。首层不自动视为足够的预热，也不据此宣称稳态。

该能力不包括任意中途快照。现有 `slice` 的完整首轮与明确初态约束不能静默放宽。有限层段应走公开准备、运行、记录和校验流程；保存或重放仅接受能够完整声明初态与执行范围的数据，拒绝不兼容输入。具体命令、字段和模块划分由实现统一确定，验收后再写入使用指南。

## 6. 小型验证与验收

先完成以下四类测试，再进行目标规模的短层段验证。

| 测试 | 要核对的行为 |
|---|---|
| 并行与缓冲复用 | 两个独立通信核可按各自条件继续；同一缓冲未释放时必须等待，其他核不被无关任务阻塞 |
| 部分数据到达 | 两个 Token 先后到齐时，局部处理按源码条件启动，必要的算子完成条件仍然生效 |
| 共享出口竞争 | 少量传输共享与不共享出口的对照，核对可手工检查的链路服务、排队、字节与完成事件 |
| 数据晚准备 | 低竞争条件下延后数据准备，延迟应记录在发送前，不误计为网络排队 |

人为竞争和延迟只用于功能验收，不是正常业务存在性能问题的证据。补充检查数据与状态数量、有效字节守恒、同芯片交付范围、资源最终释放、回调次数、前后端计划核对及采集开关的一致性。

短层段接口先以小型输入通过公开流程，再逐步提高规模核对构图、内存、磁盘和记录开销。资源不足时保留失败原因和已完成范围，不以反复放宽上限代替修正。完整 61 块研究验证由实验方案在最后按条件执行，不作为本版开始研究前的必跑项。

本版验收应形成可追溯的来源对应、资源与完成条件、四类测试证据、公开小例及有限层段验证结果，并列出剩余假设。不要求新模型必然更快或产生更多拥塞。

无法核实的容量可以参数化；若关键作用过程本身无法表达或明确，标记受影响部分受阻并记录缺项，继续不受影响的工作，不通过猜测补齐。超出本版范围的硬件模拟和研究方向另行决定，不能静默加入任务。
