# 推理通信脆弱性：模型、改进与条件证明

本文讨论的是有限 MoE 推理依赖图如何受到跨机通信影响，以及本仿真器能保证哪些性质。真实数据分布、硬件精度和生产SLO（服务时延目标）不由下面的证明自动得到。当前实现使用单一原生RDMA ns-3；计算耗时和超时下限仍为声明参数。

## 1. 把核心问题写清楚

一次推理完成通常需要多个通信和计算前驱同时完成。用有向无环图 G=(V,E) 表示这些依赖。对节点 v，若前驱固定、资源串行顺序也固定，则完成时刻满足 F(v)=c(v)+max{F(u):u→v}；无前驱时取明确的就绪时刻。通信的数据到达、源端确认和资源清理是不同节点/事件，不能共用一个“通信结束”。

设一条消息有 B 个有效字节，源实际发出字节的最高连续水位为 H，累计确认是 A，接收端连续接受水位是 R。合法传输满足 0≤A≤R≤H≤B。源端实现只能读取 A、H 和自己的发送时刻；R 及交换机状态只供离线评价，不能让源端提前知道。

数据消费条件是 R=B；正常发送完成条件是 A=B；软件额度归还还要求原生发送QP（队列对）映射已清理。所以 R=B、A<B 时，数据已可供消费，但发送资源仍被占用。这不是矛盾，而是确认路径造成的脆弱点。接收/发送节点各自影响哪些前驱，必须看实际图，不能假设每个ACK都处在业务关键路径上。

若一轮要完成 M 条必要通信，将“在限定运行条件下这条通信无法正常完成”的残余事件记为 E_i，概率为 p_i。只有在这些事件独立时，全部成功概率才是 ∏(1−p_i)；不独立时只能使用相应联合分布，或一般的 max p_i ≤ P(∪E_i) ≤ min(1,∑p_i)。这些式子表达多前驱会放大暴露面，不提供真实p_i估计。不能把逐包丢失概率直接代入：累计ACK、重传和相关拥塞已经改变了通信失败事件。

EP（专家并行）每阶段非空rank对消息数至多P(P−1)，实际由专家选择决定；多层、Decode步骤增加必要交互。batch也会改变消息大小、分包数及原先为空的rank对，不能把所有规模效应简单写成“消息数等比增加”。两组推理副本不意味着实现了训练DP同步。

## 2. 解决方法和本轮落实范围

| 脆弱性 | 方法 | 当前落实 |
|---|---|---|
| 尾包/最终ACK丢失后没有新包触发NACK | 源端ACK进展超时、真实重传；接收端重复包重新发累计ACK | 已有可选Go-Back-N扩展，本轮保留并回归 |
| 固定超时不能同时适合不同反馈时延，短超时会放大重复流量 | 从真实源发送/反馈采样RTT；排除重传歧义，以平滑RTT和偏差确定有界RTO | 本轮新增显式可选Karn估计；固定模式保留 |
| 丢失确认的消息占据源额度，其他通信也无法发出 | 明确输出额度所有者与当前可发条件，区分消息槽、逻辑字节不足及FIFO队首 | 本轮新增离线不等式证据；已有目的端轮转可作对照，不宣称能释放故障额度 |
| “有限重试”被误读为“推理一定及时完成” | 给出无ACK进展时的精确终止界；正常恢复与明确失败分别验收 | 本轮增加可重算的静默区间证书，不将失败当成功 |
| 一个失败终止整个共享执行 | 为请求/副本定义错误传播后再做隔离，不能用伪成功清理依赖 | 当前仍整体失败；单QP错误隔离是后续方法，未实现 |
| MoE短消息每次创建新QP，估计还未收敛通信就结束 | 保守初值/下限；未来可研究按源、目的、plane隔离并带年龄限制的历史估计 | 本轮按QP独立，明确保留冷启动限制；不读取未来路由或接收真值 |

## 3. 状态与转换

纯协议状态位于`SourceRecovery`，组合`RetransmissionTimer`与可选`AckRttEstimator`。ns-3适配层负责真实QP、NIC、包与定时事件；`RecoveryRecords`只保存有界被动记录。Python分别负责配置、RTT重放、协议审计和条件证书，平台不依赖研究脚本。

计时器状态为 (A,H,j,r,d)，其中 j 是上次ACK进展后的连续超时重传次数，r 是当前RTO，d 为截止时刻或未计时标志。原始消息、接收规则和数据包路径保持不变。

实际发出数据后更新 H；若 H>A 且尚未计时，令 d=t+r。新的累计确认 A'>A 时，令 A=A'、j=0、r=当前基准RTO，若 H>A 则 d=t+r，否则停止计时。重复或过期反馈不延后d，也不重置j/r。超时时，若 j<K，则 j←j+1、r←min(2r,r_max)、d←t+r，经原生发送调度从A回退重传；若已达到K，则明确失败，不调用正常完成或提前归还额度。

NACK（否定确认）仍由原生库处理。本扩展不把NACK触发的重传计为“超时重传决策”。PFC、DCQCN、NIC仲裁和物理链路仍决定实际包何时发出；超时决策不是立即交付承诺。

## 4. 安全性证明

命题1：在合法协议反馈、消息身份不混淆、接收端不凭空确认字节的前提下，不会因超时、重复数据或旧反馈提前报告正常完成。

证明：初态A=H=R=0。实际发送只增加已发覆盖H且不超过B；接收端只在连续收到数据时推进R。源确认仅从真实ACK/NACK头获得，适配器校验A'≤H，累计确认单调；在接收规则正确的假设下A'≤R。超时只回退原生发送游标，不增加A；重复数据产生的是R对应的真实反向ACK，重复/旧反馈不推进A。因此对转换序列归纳，0≤A≤R≤H≤B始终成立。只有A=B才调用原生正常完成，继而清理QP；额度仅在清理返回后释放。故正常完成/资源释放不能由接收已齐或超时本身代替。证毕。

该结论依赖原生接收状态机和ACK身份的正确性，纯C++计时器证明不能替代对NIC/包关联的检查。功能门另以真实包、唯一业务字节、完成回调一次及QP清理检查这些接入条件。

命题2：旧反馈不能无限延期故障检测。

证明：A'≤A时，计时器的j、r、d不变；仅实际新确认才建立新的计时区间。因此任意有限或无限个旧反馈都不改变已确定的截止事件。RTT估计器遇到NACK可以作废采样，但不得借此重置计时器。原生链路的正串行时延和事件执行公平性另作为时间能够前进的条件。证毕。

## 5. 自适应RTO与采样无歧义

估计器每条QP最多保留一个待测原始数据包，空间为O(1)。记录其结束序号e和实际发送时刻s；一个真实新ACK覆盖e时取样x=t−s。重复/旧ACK不产生样本。任何重传、NACK或超时都会作废待测包，并设置歧义屏障b为当时已发最高水位；只有确认覆盖b后，随后新发出的原始数据才能再开始采样。保守地连“超时决策后尚未实际重发”的样本也排除。

命题3：按此规则接受的样本不把原始包与重传包混为同一次测量。

证明：采样开始时A≥b，且该包位于此前未发送的字节范围；若从s到确认期间发生重传/NACK/超时，采样立即作废，不能被接受。因此被接受样本对应的字节只存在本次原始发送尝试；ACK可以累计、延迟或排队，样本包括这些真实等待，但没有原包/重传包身份歧义。证毕。此证明不表示未来RTT受该样本上界约束。

首次样本：S=x、V=ceil(x/2)。后续样本先计算 V=ceil((3V+|S−x|)/4)，再计算 S=ceil((7S+x)/8)。基准RTO为 clamp(S+max(g,4V),r_min,r_max)，g是声明的时钟粒度。更新顺序使用旧S计算偏差，整数ns向上舍入。每次新ACK进展使用此基准重置计时，连续无进展仍指数退避。

原理参考[RFC6298](https://www.rfc-editor.org/rfc/rfc6298)及[Karn与Partridge，1987](https://doi.org/10.1145/55482.55484)。RFC6298是TCP规范，本实现不是TCP或生产RoCE复刻：最小超时、采样保守程度和字节序号由本项目明确声明，也未采用RFC建议的秒级下限。

自适应不是无条件改进：ACK反馈尚未返回就超时，可能使所有可用包都变得有歧义；短QP随后结束，就没有新原始包可以采样。它不能自动修正过低初值，不能预测突发拥塞，也不能保证没有误重传。必须同时看无故障重复流量、有效样本、恢复代价和业务推进，不能只比较估计值。

## 6. 有限时间保证究竟保证什么

命题4：在时刻a刚建立一个仍有未确认字节的计时区间，基准RTO为r，最大RTO为r_max，允许K次连续超时重传。若之后没有新的累计ACK进展且模拟器继续处理定时事件，则失败时刻精确为 a+Σ(i=0..K)min(2^i r,r_max)。

证明：第一次到期是a+r；每次未耗尽的到期将下一段长度倍增并封顶。第K次重传之后再等待封顶后的下一段，第K+1次到期失败。旧反馈不改截止时间，实际继续发送也不重置已经运行的计时器，因此K+1段长度相加即得。证毕。

例如r=40000ns、r_max=160000ns、K=2，静默预算是280000ns；r=37566ns、同上限、K=3，预算为422962ns。`rdma-diagnose`在完整记录下输出起点、重置RTO、预测失败截止与实际终态，耗尽重试时核对精确相等。仿真预算先到或其他消息使整个运行先失败时，只报告在界前停止，不能算这条消息成功恢复。记录截断时不重建缺失起点。

该界不是推理完成上界：尚未获准或尚未实际发出的任务还没启动协议计时；ACK只要有真实新进展就会开始新区间；NIC若长期暂停，也不能保证重传在期限内送达。给定消息字节有限仅限制ACK进展次数，不能消除发送前等待。整体请求期限需要组批、资源、前驱及应用错误语义共同定义。

条件恢复结论：若在耗尽重试之前存在一个传输机会，原生调度、数据传递和ACK返回的总时延小于该次计时区间，并且该机会能够交付未确认字节，则出现新的ACK进展。若有限字节消息的后续必要发送都满足相应公平调度/有限交付机会，才可得到最终完成。PFC永久不恢复、反向ACK持续丢失、最大RTO小于必要交付时间等均违反条件；有限重试会明确失败，而不是无条件保证成功。

## 7. 共享额度怎样放大故障

设源端消息槽K_s，逻辑字节额度C，活跃所有者集合O。额度守恒为held=Σ(m∈O)B_m，available_count=K_s−|O|，remaining=C−held；0表示该种额度未设上限。消息q当前可获准至少要求存在空槽且B_q≤remaining。FIFO还要求q为全局队首；目的端轮转要求q为某个目的端队首并参与选择。诊断给出的只是当前时刻这些不等式，不把它当成持续排队时长。

例：C=8192B，已收齐但未确认的消息占6144B，只余2048B。FIFO队首4096B不能发，即使后面1000B可以容纳。轮转可能让另一个目的端1000B发出，却不能让4096B突破总额度，也不能释放6144B故障占用。若消息槽本身已满，单纯换排序同样无效。

可研究的隔离方法是给易受影响的目的端/独立副本设置占用上限或预留健康通信额度。要保证一条大小不超过b*的健康候选仍可发，至少需故障占用≤C−b*且保留一个消息槽，并有允许选择该候选的规则；还要有实际发包调度机会。这个充分条件针对该候选的准入，不能证明整个EP推理成功，因为正确推理仍可能需要故障专家结果。本轮新增不等式诊断，未把该隔离策略实现成既有功能。

## 8. 时延传播证明与实验边界

命题5：固定依赖、固定资源顺序、其他节点时长不变时，只增加一个通信节点的时长δ≥0，则最终完成增量在[0,δ]内。

证明：按拓扑序归纳。该节点前的完成时刻不变；该节点增加δ。任一下游节点的max前驱操作使增量不小于0、不大于所有前驱增量的最大值，因此始终≤δ；非后继为0。多个最终节点再取max仍保持该界。证毕。

真实联合网络的重传会增加流量、改变排队和资源排序，因而可能同时改变许多节点时长；此时不能套用单节点界，也不能把某条被选中的前驱链称为唯一原因。实验必须核对共同任务图、业务量、实际路径、资源释放、独立副本推进和新的流量干扰。观察到“ACK晚52μs而服务只晚9μs”与并行依赖一致，但不自动证明因果影响恰为某一固定比例。

## 9. 如何验证

纸面证明给出所有合法转换的条件论证；有界探索直接调用生产纯协议类，枚举2字节消息、0..8整数时刻、初始RTO 2、上限8（自适应下限1）、一次重试下的发送范围、ACK/NACK前缀、旧反馈和超时同刻顺序。已探索1602个状态、28692条转换，并覆盖正常完成、重试耗尽、有效采样和采样作废。它不等于无限状态机器证明，也不证明ns-3或硬件正确。

真实网络门另外核对身份、源实际字节、重复确认、完成一次、QP/额度、排空、独立RTT重放和真实前端继续执行。固定模式通过修改前二进制比较；有界记录关闭/截断的执行一致性单独检查。复现命令与范围维护在[自适应验收](../fixtures/scaleout_adaptive/README.md)，公开配置见[自适应示例](../examples/scaleout_rdma_adaptive/README.md)。平台与独立MoE研究分别验收，结果不好的条件同样保留。
