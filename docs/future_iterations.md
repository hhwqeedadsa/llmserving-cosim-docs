# 后续事项

这里列出尚未完成、需要按实验目的选择的工作，不代表执行授权或本轮任务。当前工作见[任务记录](tasks/current.md)，已完成的平台能力与证据见[里程碑历史](milestone_history.md)。

[v0.4 平台要求](archive/moe_ub_cosim_dev_v0.4.md)与独立的[映射价值实验](../experiments/mapping_value/README.md)分别验收，进度统一见当前任务。下表保留其他待选事项；各项需明确目标、支持范围和预算后实施。当前参考条件的适用范围见[CM384/R1 场景](scenarios/cm384_r1.md)。

| 待选工作 | 什么时候需要 | 已有基础与仍需补充的部分 |
|---|---|---|
| 有限记录预算下的短等待观测 | 继续设计被动测量机制 | [端侧状态对照](../experiments/scaleup_observability/results-send-state.md)已确认状态信息能缩小检查范围，但周期采样会漏掉短等待。下一项候选是固定可见字段与信息预算，比较状态变化记录、窗口摘要等规则的覆盖和遗漏；尚未实现新算法，也未验证硬件采集成本。 |
| 响应拆分中不同机制的贡献 | 需要进一步区分多路径、流水推进与原生请求资源的影响 | [逐包路径证据](../experiments/scaleup_observability/results-response-paths.md)核对了实际响应与数据到齐时间。可先选择固定选路／逐包喷洒的有依据对照，再按具体缺口补记录；现有结果没有单独量化各机制贡献。 |
| 更长或更多样的服务片段 | 研究跨轮变化、持续到达、补入请求或样本差异 | 连续组批已有小场景验证，目标规模已完成首轮；4/8/64 轮、不同请求集合和热点条件需另定预算并验证。相同首轮的重复重放不作为独立样本。 |
| 补入请求的数据集 | 实验需要超出现有 1024 个来源的请求流 | 当前 1024 请求及其 64 步来源已固定；2048 请求 refill 候选尚未取得并验收。文件尾端不表示请求完成。 |
| 目标 NPU 计算与端侧通信耗时校准 | 需要评价绝对延迟或声称复现目标设备性能 | 现有 A100 小型算子测量与接口可作方法参考，不能代替 DeepSeek-R1/Ascend 的 MLA、量化算子、打包和归约测量。需匹配设备、软件、形状和精度。 |
| 其他 URMA 操作与传输方式 | 选定任务需要 URMA READ 或 URMA/CTP | 当前联合入口已验收 WRITE/RTP 和原生 STORE/LOAD；其他模式仍需单独定义操作和完成语义、字节观测及正常结束。底层存在代码不等于联合入口已支持。 |
| 进一步复现或比较通信库 | 要研究当前 CANN 参考行为未覆盖的机制或另一实现 | 已有固定 CANN A3 路径的贡献、字节、阶段和有限并发模型；原生流水线、MTE 等细节按问题选择。XCCL 或 SimCCL 可另行评估，当前不是必要依赖。 |
| 扩展 P/D 分离场景 | 需要同时研究预填充、KV 交接与解码干扰 | 早期 P/D 小型用例保留；当前 CM384 场景从 KV 已就绪的解码开始。更完整的多层 P/D 组合需独立定义与验证。 |
| 任意时刻状态保存与重放 | 需要从服务中途或跨轮自适应地重启仿真 | 当前保存包只支持完整首轮及明确初态。任意 ns-3 快照、后续请求调度恢复不是已有能力。 |
| 面向更广泛用户的发布准备 | 计划正式分发软件或开放协作 | 许可证、第三方分发说明、版本发布和托管 CI 需明确安排。现有仓库使用流程不等于这些事项已经完成。 |
