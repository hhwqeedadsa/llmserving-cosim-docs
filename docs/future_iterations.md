# 后续事项

这里列出尚未完成、需要按实验目的选择的工作，不代表执行授权或本轮任务。当前工作见[任务记录](tasks/current.md)，已完成的平台能力与证据见[里程碑历史](milestone_history.md)。

本轮已确认的 A3 资源与关键依赖修正、必要事实记录和有限层段入口见[平台 v0.5 规范](moe_ub_cosim_dev_v0.5.md)，正常业务探索见[问题筛选实验](../experiments/scaleup_issue_screening/README.md)。这些不再作为本表的待选工作。下表各项需明确目标、支持范围和预算后实施；当前参考条件的限制见[CM384/R1 场景](scenarios/cm384_r1.md)。

| 待选工作 | 什么时候需要 | 已有基础与仍需补充的部分 |
|---|---|---|
| 有限记录预算下的短等待观测 | 修正后发现有可信业务影响的短等待，且已有采样确实遗漏必要信息 | [旧端侧状态对照](../experiments/scaleup_observability/results-send-state.md)属于原全 rank 发送配额模型。先按新实验确认等待对象及信息价值，再比较状态变化记录、窗口摘要等；不作为默认下一项算法任务。 |
| 响应拆分中不同机制的贡献 | 单独选择拉取式参考通信或原生读取问题 | [逐包路径证据](../experiments/scaleup_observability/results-response-paths.md)保留其请求组织和整包转发条件。需要核实适用语义，再区分多路径、流水与请求资源；不作为 A3 写回式 Combine 的默认研究。 |
| 更长或更多样的服务片段 | 研究跨轮变化、持续到达、补入请求或样本差异 | 连续组批已有小场景验证，目标规模已完成首轮；4/8/64 轮和新的到达过程需另定预算。v0.5 的明确初态有限层段不等于稳态服务，相同首轮的重复重放不是独立样本。 |
| 补入请求的数据集 | 实验需要超出现有 1024 个来源的请求流 | 当前 1024 请求及其 64 步来源已固定；2048 请求 refill 候选尚未取得并验收。问题筛选所需的独立请求组先按实际可用来源选择，来源不足可减少组数，不复制补齐。文件尾端不表示请求完成。 |
| 目标 NPU 计算与端侧通信耗时校准 | 需要评价绝对延迟或声称复现目标设备性能 | 现有 A100 小型算子测量与接口可作方法参考，不能代替 DeepSeek-R1/Ascend 的 MLA、量化算子、打包和归约测量。需匹配设备、软件、形状和精度。 |
| 端点消费与内存服务模型 | 明确选择接收服务不足及其上游影响作为研究对象 | 需先表达有限缓冲、服务和释放对上游的作用，不能只延迟应用回调。当前未建模不能证明该问题不存在；不随 v0.5 自动建设完整 HBM 或缓存模拟器。 |
| 其他 URMA 操作与传输方式 | 选定任务需要 URMA READ 或 URMA/CTP | 当前联合入口已验收 WRITE/RTP 和原生 STORE/LOAD；其他模式仍需单独定义操作和完成语义、字节观测及正常结束。底层存在代码不等于联合入口已支持。 |
| 其他通信库或芯片代际 | 明确需要 A5、XCCL、SimCCL 或当前 A3 范围以外的机制 | A3 基线修正由 v0.5 负责；A5 的分核、局部缓冲和数据标志布局应另建依据，不能混入 A3。其他库可另行评估，当前不是必要依赖。 |
| 扩展 P/D 分离场景 | 需要同时研究预填充、KV 交接与解码干扰 | 早期 P/D 小型用例保留；当前 CM384 场景从 KV 已就绪的解码开始。更完整的多层 P/D 组合需独立定义与验证。 |
| 任意时刻状态保存与重放 | 需要从服务中途或跨轮自适应地重启仿真 | 当前保存包只支持完整首轮及明确初态。任意 ns-3 快照、后续请求调度恢复不是已有能力，也不由有限层段入口隐式提供。 |
| 面向更广泛用户的发布准备 | 计划正式分发软件或开放协作 | 许可证、第三方分发说明、版本发布和托管 CI 需明确安排。现有仓库使用流程不等于这些事项已经完成。 |
