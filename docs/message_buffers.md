# 主服务消息缓冲与逐包字节核查

在持久 ASTRA 服务的 `transport` 下显式增加 `message_buffers`，可以让原消息与备用贡献的标记字节通过实际数据包写入独立目标缓冲。用途是检查迟到数据、重复包、并发地址范围和退出后的复用，默认关闭。它不把备用贡献接入原图的消费条件，不改变原始阶段门限、ACK、专家计算依赖或任务完成定义。

```json
{
  "schema_version": "moe-service-message-buffers/1",
  "content": "deterministic_message_marker/1",
  "capacity_bytes_per_gpu": 2097152,
  "max_retained_bytes": 33554432,
  "max_messages": 4096,
  "max_events": 200000,
  "max_payload_capture_bytes": 33554432
}
```

这七个字段全部必填，不接受额外字段或布尔型整数。每GPU容量为1～64MiB，全部保留的源与目标字节之和为1～128MiB；消息历史为1～131072条，且不少于 `transport.limits.max_work`；事件上限不少于消息上限的7倍且不超过1000000。分包写入会产生更多事件，配置的事件额度仍须足够，否则失败。源端实际包内容捕获上限为1～64MiB，包含重传的重复字节，不是有效载荷去重值。这些是功能模式的支持上限，不是网卡或显卡规格。

每条消息在实际 SEND 提交时原子分配源、目标两个范围。源和目标共享其所属GPU的同一个地址空间，以首次适配方式寻找连续空闲范围；碎片不足或总额不足时明确失败，不隐式排队、扩容或覆盖。地址是模拟GPU内的整数偏移，宿主实际使用每条消息的字节数组；相同偏移在不同GPU可以同时使用。消息身份终身不复用，完成后保留元数据以拒绝迟到旧回调。

字节 `i` 的值为 `((message_id >> (8*(i%8))) ^ (i//8)) & 255`。源字节被复制到传输重传副本，再进入实际 ns-3 Packet。接收端仅使用实际接受的数据包内容；GBN丢弃乱序包，SR仅交付新连续前缀，已接受重复包不重复应用。包可以跨消息边界，接收端按该连接上已提交的消息长度拆分。

接收描述符在 SEND 时直接安装到服务的本地接收队列，配置地址和消息身份不编码为线上报头；控制耗时为零。这是功能接收放置，不是实际RoCE远端地址、MR/rkey、权限认证或隔离机制。标记不表示激活张量、BF16数值或门控权值，也不执行数值专家模型。

源范围在本条消息的实际完整累计ACK后释放；传输的重传字节副本也在完整累计ACK后释放并独立核算。目标范围需同时满足完整接收、实际ACK和所属执行范围退出。原消息的范围退出取实际整图退休，helper消息取其输入确认、结果确认与接收全部完成后的实际退休；不是逐专家消费者，也不证明CUDA可见性。接收就绪、执行范围结束、缓冲回收和整个网络排空分别记录，不得相互代替。

容量字段覆盖模拟源/目标数组；它不包含独立的重传副本、乱序包、包头、宿主元数据和JSON字符串。结果另外报告重传副本的保留量与峰值，宿主总量仍受协议RSS、地址和磁盘预算约束。不要把 `max_retained_bytes` 当作宿主进程总内存上限。源/目标arena峰值按生命周期事件精确重建；重传副本的峰值按实际post/ACK纳秒时间核对上下界。同纳秒ACK先释放副本、后排队服务回调，跨回调顺序未单独记录，因此不要求两个峰值相同，也不声称精确复原副本峰值。

沿用公开 `scaleout rdma-build`、`rdma-run`、`rdma-check`；需要按当前源码构建服务。独立生成、运行和检查见[128端点Clos示例](../examples/scaleout_message_buffers/README.md)。主服务两种前端共用传输和检查接口；本功能的实际网络验收使用LLMServingSim入口，不声称已经实际执行SimAI新模式。

结果在 `result.json.service_transport.message_buffers` 中保存：`messages` 为源/目标偏移、接收字节数、源/目标FNV1a64摘要及各阶段纳秒时间；`events` 为分配、每次实际片段写入、就绪、源释放、范围结束与目标释放；`owners` 和全局字段为当前/峰值保留字节。FNV摘要只用于内容核查，不是安全散列。`native.source_payload_packets` 保存真实源包的十六进制内容；SR的 `payload_delivered` 保存实际交付片段；`native.message_payload` 单列传输重传副本和源包捕获量。

`rdma-check`从源包内容和逐包UID、目的端到达顺序独立重建接收前缀，检查跨消息分片、重复包不重复写入、完整内容摘要、实际graph/helper退出、所有在途范围不重叠以及源/目标释放。报告出现在 `verification.json.message_buffers`。校验成功只能说明这次功能执行符合上述定义，不等于GPU内存安全、真实通信库校准或业务恢复收益。
