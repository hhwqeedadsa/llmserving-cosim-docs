# DCQCN反馈抽象审计

起点`68ad3fe`，上一轮为实质进展。本轮只读核查模型有效性，不做性能优化或新的网络执行。旧Prefill深度8的超时前缀仍保留失败，不能通过更换参数、延时限或生成新成功结果取代。

## 竞争解释及判别

1. 原生逐包ACK中的CNP位与目标DCQCN反馈等价：若原论文允许相同逐包反馈、相同抑制/降速与恢复时序，且源码调用链符合，则未发现此项机制缺口。
2. 机制等价，仅缺硬件参数：若完整生成/抑制机制存在，只是周期、限速等数字未校准，则收敛到参数来源与敏感性问题。
3. 机制本身不同：若论文明确规定NP通知周期或RP事件条件，而固定源码采用不同反馈传输/触发，则参数读回和调整本身不能证明等价。单独写明是模型近似、遗漏还是已证缺陷，不能直接将有意抽象叫软件bug。

读固定ASTRA原生`3964b1d`与Alibaba`3e0c7c1`的ReceiveUdp/ReceiveAck/ReceiveCnp、DCQCN控制函数和有效配置链，按文件Git身份/hash记录。只对当前模式1做结论；stock配置的其他模式不冒称DCQCN校准。阅读DCQCN原论文及该ASTRA后端说明引用的HOTI论文，最多两个既定URL，各4MiB、请求子进程硬限20秒，不重试；失败不替换为未读文献的确定结论。

## 已有输入及允许的分析

读`29f55d4`固定四请求层4/depth1和depth8的已有包记录。将目的端唯一CE数据包和对应源端真实累计ACK关联，按连接统计反馈数量、时间间隔以及每4us/原文定义窗口的密度。独立核查序号、同UID、端点和capture完整性；不把跨交换机的多次观测当多个通知。

若原文有明确通知周期，可对**同一已发生CE序列**作假定周期分组计数，明确初始规则和计时起点；这是输入描述，既不是符合另一模型的新闭环仿真，也不是反事实速率/时延。不同反馈会改变原始流量和CE，不能将过滤结果作为完整模型性能预测。实际ACK-CNP计数、假定分组计数和论文参数分列，不能混成生产优化收益。

新增分析只使用平台公开输出与原始输入，不导入测试fixture或驱动；不读此前分析JSON来代替独立核算。不新造流量、执行GPU、改源码依赖或安装软件。
