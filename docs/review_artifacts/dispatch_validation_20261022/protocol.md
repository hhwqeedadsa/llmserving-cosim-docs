从干净`4ecf681`开始，上一目标轮为实质进展。本轮只检验历史网络现象是否在未用于前四步包级研究的窗口和不同等价多路径（ECMP）选路种子下仍存在；不是新算法、独立请求留出、现代GIN或生产拥塞评测。

固定四个原始请求及此前只读Prefill产生的三种等容量放置：contiguous、prefill_all_lpt、prefill_tail10_lpt。placement文件SHA256固定`dcdf9220498839182591250f114d85f75bbe851e376c9bf828a82c384964d3e7`，不重新训练或调放置。四窗口按顺序为层4/入口5、层4/入口6、层32/入口5、层32/入口6；每窗四源各一个真实Decode token。这些是新包级评价窗口，但此前全量离线统计已看过，不称未见过的数据或独立测试集。

同token按目的rank去重，BF16 fresh/direct布局每份14,464B；只执行跨rank Dispatch数据。EP4逻辑rank→GPU0/2/4/6，四服务器/两Pod。12个持久连接，固定wire_port=21000+4src+dst，depth1；四窗口按前窗全部真实ACK推进，窗口之间不重建QP、不预设未来发送时刻。没有Combine、控制、计算或跨层模型依赖，这不是完整Decode。跨层顺序仅为该数据微基准规则。

网络沿用8端点/4ToR/4Agg/2Core、接入100G/1us；上层全100G或25G。ECMP种子为11、29、47，共3放置×2速率×3种子=18条件。seed配置同时传给每交换机的seed+node_id和全局ns-3 RNG；若没有随机ECN/丢包事件，不能据名称把差异归因随机路由之外；必须独立复核每个数据/ACK包的真实哈希选择。IP、NIC、wire port、输入顺序和放置不变，不挑种子或窗口。显式stream-work/2预算12连接/64工作；协议与旧研究相同，保留真实ECN/PFC计数。若出现分析器暂不支持的控制包，保存该条件，不将其丢弃后声称全量验收。

主要结果为每窗ACK时长、四窗总ACK完成、物理排空、全部物理出口服务量和队列面积。竞争解释：

1. 仅总数据份数决定排序：若同份数或固定输入换seed出现完成差异，削弱该解释。
2. 仅最大GPU输入/输出决定排序：这些计数跨seed不变；若完成或排序改变，应继续检查真实共享路径。
3. 最忙出口总服务量已足以排序：逐窗比较该下界与真实完成，记录一致、并列和反向；出口时序和前驱也可能重要，不把相关性当因果。
4. 单seed偶然：明确报告每个窗口/seed/速率的三放置排序和反向个数，不从四请求推总体显著性。

分析只读observed和实际公开结果；原始请求、Prefill放置及理想工作映射放truth，仅独立核验读取。沿用完整数据/ACK逐包序列化、传播、交换排队、ACK回调分解；完成时间分解应无残余，但不据一条关键包推断可消除的业务收益。保留ECN/PFC、无差异及反例，不因结果弱而扩矩阵。
