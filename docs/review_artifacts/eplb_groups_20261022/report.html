拓扑感知近邻与分层EPLB强基线

本轮补上了更贴近DeepSeek的已知方法：分层EPLB先按逻辑专家组分配节点，尽量保留组内共址。固定容量、没有额外副本时，这一思路的适配基线把普通单专家LPT增加的大部分通信副本消除了，但没有保住LPT在最大计算输入p95上的改善。研究应面对这个已有基线，而不是只与连续放置或忽略分组的LPT比较。

论文目标仍进行中。本轮没有执行官方EPLB运行时、训练、GPU或新网络仿真；五组数字均为四请求上的离线通信与计算输入核算，不是延迟收益。

一、三类方法的动作不能混淆

方法与本轮证据它实际改变什么能否直接用当前冻结R1单层路由公平复现
TA-MoE：NeurIPS 2022官方正文/补充、固定公开gshard gate源码根据拓扑目标调整训练辅助损失，使模型学到不同的token→专家路由；不是只换专家位置不能。当前数据没有完整gate分数、训练数据、梯度和训练过程；重写一个流量矩阵不等于TA-MoE
ExFlow：固定v2作者摘要，全文未取得摘要明确描述context-coherent并行与跨层专家亲和，减少Alltoall次数不能只换owner表后声称复现。具体执行和Top-k边界尚需全文与实现核对
MoETuner：已缓存固定v1全文平衡专家簇负载，再利用相邻层专家关系和GPU对带宽分配簇尚未复现求解器；跨层转换不应替换成同层共选，不能自行补全公式细节冒充原版
DeepSeek EPLB：固定README、完整eplb.py与Git身份链利用估计专家负载，先分组到节点，再在节点内复制/分配；不直接改变模型的逻辑选择其受限分组步骤可以适配，但当前只覆盖零冗余、每节点一个活动GPU的特殊情形
Patterns：固定v5与此前已核对artifactPrefill计数指导专家重新放置或复制，也明确计算/通信权衡单专家计数LPT已作基线；不能把其思想或权衡当作我们的创新

TA-MoE第4节先用α–β模型估计GPU对传输成本，目标为最慢GPU对，约束源端总量与专家接收负载，并对树/环拓扑简化求解。正文将最慢对成本称为通信完成的下界，再通过辅助损失引导路由。固定GShardGate代码确实将topo_scale引入辅助损失。这些事实不支持声称它精确模拟了共享交换机队列，也不能据此断言其全部实现没有其他网络优化。

TA-MoE是训练路线的直接相关工作；冻结模型推理若要改变路由，必须另行验证模型输出与质量，不能只优化通信。ExFlow则改变跨层执行方式，公平比较还必须把Attention、聚合与其他同步一并计入，不能只比较一段Dispatch副本数。

二、分层EPLB适配到底做了什么

官方EPLB固定提交为d52c72d5b2f2fb4c41afbf8eb21366820239913d。官方README明确说明：在节点数整除专家组数时，利用组限制路由，先把整组专家装入节点以减少跨节点流量，然后复制热点专家并分配到节点内GPU；否则使用全局分配。负载如何预测不在该仓库范围内，README给出历史移动平均作为常见方法。

本轮保持四活动rank分别位于四server，对应已有物理GPU0/2/4/6；每server仅一个GPU参加这个EP组，其他GPU不借用。每层E256、8个连续32专家逻辑组，每rank64个专家，共256个物理专家，额外副本为0。每节点恰好容纳两个完整组。

在这个特例中，节点内复制阶段不增加专家，节点内也只有一个活动GPU。因此可将官方流程缩减成“对8个组的负载做等数量贪心装箱”，用独立标准库代码适配。普通多GPU节点内，官方EPLB仍会把同组专家分散到本地GPU，所以不能将本轮rank同址推广成一般不变量。

两个适配条件分别只读全部Prefill的单专家总计数、每请求最后最多10个Prefill token的同类计数。不用源rank、token共选集合、Decode或路径。按组总计数降序，把下一组放入当前负载最小且未装满两个组的节点。相同组计数按组ID，相同节点负载按rankID决胜。

官方torch sort未显式指定stable；新适配显式规定了平局规则。全Prefill有6/58层、尾部有24/58层出现相同组总计数；因此不能声称与任意官方PyTorch运行逐字节等价。下载源码只读，未导入执行。本轮称“分层EPLB思路适配”，不称原版完整复现，也不把这一已知算法作为创新。

三、五条件结果

固定四个原始请求、58个MoE层、128个Decode位置，每条件7,424个四请求窗口。所有条件使用相同原始选择；现代direct语义下，一个token同一远端rank只发一份，多个目标专家去重。下面的计算输入是每rank收到的专家token贡献数，不是GPU时间、FLOP或核函数时延。

与同一Prefill视图的单专家LPT相比，两种分层适配分别减少12.99%、12.63%的副本；但计算输入p95从14回到15。不能将这种已知分组策略相对较弱基线的改善写成新方法收益，也不能从副本百分比推导吞吐或延迟百分比。

配对窗口进一步表明，并非每个窗口都变好：全量分层相对全量LPT有5,459个窗口副本更少、708个更多；计算最大输入却有4,142个窗口更高、1,993个更低。尾部分层对应5,342个副本更少、815个更多；4,005个计算输入更高、2,095个更低。总量和p95都不能代替逐窗口的竞争关系。

这五个点没有证明计算/通信存在不可改善的理论下界，也没有证明贪心分组最优。它们只证明当前这两个已知思路适配未同时取得普通LPT的计算p95与连续放置的低副本；不同组配对、真实GPU成本、迁移和更强已有方法仍可能改变判断。

四、对论文方向的实际影响

第一，应删除“保持逻辑组共址以减少通信是新算法”的候选主张。DeepSeek官方已这样做；之前LPT把组打散所造成的通信增长，不能全部包装成需要新方法才能解决的问题。

第二，后续放置比较至少包含连续、普通LPT、分层EPLB适配，并在合适资源条件下加入官方冗余副本与全局分配。额外副本需要额外权重内存和具体路由决策，不能免费增加。我们的Prefill统计适配也不等于官方历史移动平均运行；二者输入信息和更新时间必须对齐。

第三，在设计新分组算法前，应先算清当前容量与整组约束下还有多大空间，再核实更强已有方法是否已覆盖。若分组层面空间很小，应正常收缩这个候选；若有空间，也必须经过留出请求与真实网络完成验证，不能只依赖四请求上的离线最优值。

第四，网络主线仍需区分“目的副本量”“共享物理端口需求”“实际协议与应用完成”。TA-MoE等已有拓扑感知思想会压缩泛泛的创新空间；只有证明某种具体抽象持续误判真实方法排序，并给出比强基线更可靠的机制或方法，才可能形成论文贡献。当前证据尚未证明这一点。

完整现代通信库语义、可用硬件校准、独立请求留出及千卡完整执行仍缺。EP4在这里是通信研究切片，不是完整R1权重、KV与服务调度能够在四张卡部署的证明。四份推理请求也不能支持训练或生产分布结论。

五、证据与取得范围

独立checker从四原件重数Prefill与Decode，验证五条件37,120窗口、593,920个矩阵项、148,480条token选择，以及116个分层放置的928次贪心决策。旧LPT逐层与固定结果一致；两份规划产物在只含observed的新目录、不同cwd重复逐字节一致。代码身份按commit→完整tree→blob/大小/SHA核对，下载代码没有执行。

本轮取得NeurIPS目录、TA-MoE正文/补充与固定gate源码、ExFlow固定v2元数据/作者摘要、EPLB固定README和源码。ExFlow PDF请求以curl 63因2MiB上限拒绝，保留HTTP200/0B与stderr；没有换源或抬限重试。它的Top-k条件与具体执行仍未知，不能把摘要当全文审计。
