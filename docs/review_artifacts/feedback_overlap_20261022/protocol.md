## 竞争解释与判别

1. 新窗口仍是反馈到达前的短突发：按每连接实际CNP RX与源TX计算反馈后包数/字节。若仍为0，停止该候选，不扩长或重复输入追现象。
2. 控制器状态变了却未限制数据：独立重放NP/RP，关联真实TX采样及后续发送间隔，报告低速发包和等候信用的差别。不能用空闲期最低速率当吞吐。
3. 源信用主导深度差异：跟踪每个等待工作的旧ACK槽占用者和实际发布时间；报告加深额度的业务差与队列压力，不称优化。
4. 静态服务基线足够：从输入/拓扑/哈希独立预测全部数据+必要ACK端口量与最忙出口服务下界。工作/包形状固定但完成差异，才说明时间状态有额外解释价值；不能把下界差当全部可消除等待。
5. 恢复周期有实际作用：固定深度做55/110us两配对，记录源发送时间线、反馈后的真实数据量、ACK与物理排空。相同结果也有效，不扩大矩阵。不作四请求总体显著性推断。

独立checker重读原件、重新生成范围和去重工作，核对实际包端点UID、数据/ACK/CNP、完整端口字节账、NP/RP状态、接收/确认回调和源队列信用。分析只读observed及公开输出；原专家和来源归truth。CNP/ACK是不同报文，最后业务ACK与物理排空分开。只捕获4个活跃GPU端点，不能宣称交换机逐跳包捕获；路径由独立ECMP和全端口总量互证。
