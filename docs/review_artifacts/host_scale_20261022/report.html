千卡短任务已跑通，完整模型规模仍待验证

2026-10-22 · 平台 bc8dd6f · 一次预注册运行

1,024个GPU逻辑端点、50台交换机、1,104条外部链路；256个EP4副本在同一个持续网络中完成512张图、5,490条消息。仿真完成时间44,589 ns；实际宿主约23.07秒，采样RSS峰值2.54 GiB。

这次到底执行了什么

输入是人工MoE层段：隐藏维1024、16专家、每token选2专家，batch/rank=1、已有上下文2048、1层×2轮Decode。每组4张卡跨两个Pod，两张卡在同一服务器。所有副本共用一套ns-3网络、时钟和排队状态。A100只是标签，未运行GPU数值计算。它不是此前48层Qwen模型，也不是EP1024、训练DP或现代DeepEP。

网络执行的实际证据

独立逐token重算4,096次专家贡献，其中3,059次交付到其他rank，Dispatch与Combine合计12,529,664 B。跨服务器8,376,320 B、机内4,153,344 B；同GPU贡献仅保留本地依赖。

跨机3,666条消息实际发出3,666个源数据包，每条消息的首包都核对了GPU→ToR→Agg→Core→Agg→ToR→GPU六跳路径；机内1,824条消息使用显式crossbar，未冒充RDMA包。所有应用提交和完成回调配平，完整ASTRA日志核验19,172个任务节点。

端口记录ECN=0、PFC pause=0，入出队钩子队列峰值118,392 B。这次短任务没有触发ECN/PFC，不能作为拥塞长尾机制或优化收益证据。跨机ready到连续接收完成为6,252—9,808 ns，不能等同请求推理时延。

它支持什么结论

千卡的物理网络和有限任务可以在当前预算内完整执行，不能把历史超时简单解释为“千卡根本无法运行”。短任务中初始化占主导；它与旧48层实验的工作量相差很大，不能据此解释旧超时比例，也不能计算新旧加速比。

研究主问题仍需在代表性通信量、真实热点和共享上层链路中形成可证伪机制，再通过强基线、留出请求和硬件依据验证。当前结果是可用规模与成本边界，尚不是A类论文主贡献。
