1. 最终确认的改变如何传到业务

目标消息1为0→4 Dispatch6144B。接收端11476ns已收齐。首个原始包从4203ns到16725ns取得RTT样本12522ns，偏差6261ns，基准RTO为37566ns。最后ACK进展17486ns后，在55052ns超时；实际重发144B，经真实反向ACK在67160ns确认并释放资源。

固定故障条件在69660ns确认，前端131105ns完成；自适应分别为67160ns与128363ns。两者只重传一次，额外业务payload相同，差异来自超时和随后共享网络时序，不是少执行任务。

目标ACK提前2500ns，整体前端提前2742ns。这已经不满足“只有一个通信节点时长改变、其他时长/顺序固定”的条件，不能硬套单节点扰动上界。

补充两次完整包观察与原执行除包记录外逐字段相同；按实际最后数据包分解后续消息，单位ns。源发出跨度从消息首包发出算到最后原始包发出；链路项含模型序列化/传播，队列项由逐端口入/出队时间直接计算。

2. 过低初值并没有被自动纠正

2μs初值下，固定与自适应消息、端口、服务和队列执行完全相同；自适应有效样本0，作废测量包92。短消息在反馈前已进入重传，Karn规则排除有歧义样本；没有新原始包可测，不能宣称发生了学习优化。

正常源payload 389120B，短初值为1167360B，即3.00倍；产生184次超时重传决策和944次重复ACK响应。没有丢包也会制造协议负担。

短初值前端在122641ns完成，但到128641ns网络才排空，尾部差6000ns。不能把排空时间直接充当请求延迟；已有流量仍可能干扰后续请求，需要持续负载另行验证。

3. 明确失败的形式化界与源额度

fixed-persistent：最后计时区间从17486ns开始，重置RTO=40000ns；两次重试后的无进展预算280000ns，预测失败297486ns，与实际停止精确一致。

adaptive-persistent：最后计时区间从17486ns开始，重置RTO=37566ns；两次重试后的无进展预算262962ns，预测失败280448ns，与实际停止精确一致。

两者源0仍占6144B，8192B额度只余2048B；候选队首消息13需要4096B，故当前不能获准。接收已齐却未确认的所有者就是目标1，槽数尚未满；这里是字节额度阻塞，不能归为“所有消息槽用完”。交换机末态队列为0。较早失败是有界检测，不是成功率提升。

这些证书只保证已启动且没有新ACK进展的协议区间，不覆盖准入/首次发送前等待，也不保证推理在SLO内完成。持续丢失、永久PFC暂停或过小上限仍可失败；当前失败会停止整个共享运行。
