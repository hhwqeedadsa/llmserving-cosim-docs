把本地处理的输入、输出和复用规则说清楚

前轮已验证：收到数据可触发后续put，但本地处理没有保护输入。在处理期间覆盖接收区，后继会发送新数据，模型无法证明用了哪一代输入。

本轮增加显式字节复制模型：任务声明输入区和输出区，入队后保护二者，开始时读取实际输入，完成时写出实际输出，随后允许后继发送。它补齐这个显式功能程序的数据依赖，不是专家矩阵计算、GPU性能或论文主贡献。

服务于什么网络问题

研究目标仍是解释正常MoE推理中实际就绪、连接、队列、路径与共享Scale-Out链路怎样造成等待，再通过强基线、真实输入、匹配测量和留出验证评价优化。若后继发送错误代际的数据，或在输出尚未生成时就发包，任何“更快”都没有业务意义。

本轮先检查数据和资源复用是否成立，使网络时间推进同时保留输入输出约束。实验限定为小型人工程序，无GPU执行、无新增生产数据、无千卡成功或性能收益结论。

实际执行链路

GPU0发出实际字节 → GPU4接收 → 复制到另一地址 → put读取输出 → GPU1接收并复制 → 回传GPU0

GPU4还存在先入队的100,000ns本地工作，使copy在18,138ns就绪后等待到100,000ns才开始。保护覆盖这段排队时间；不能只在开始时加锁。全部阶段共用一个ns-3时钟、持久连接和网络状态。

输入输出规则

阶段实际动作规则
条件满足/入队先检查全部冲突，再消费条件、保护输入和输出禁止部分reset和部分取得资源
本地排队保持输入读和输出独占记录输入可多读，不可覆写；输出不可提前读写
取得串行槽读取当前实际输入字节记录读取快照，不从上游任务表拼值
声明时间到期将快照一次写入目标，释放记录，再标记完成后继put只有实际完成后才可读取输出
截止或冲突保留实际前缀、旧输出和活跃记录不补造输出、释放或本地完成

这是一套显式功能规则：输出写入保护结束前，即使字节已提交，其他读仍被拒绝。源输入和输出必须不同区间。本地copy和远端put分别记录保护，避免将计算输入寿命误归入ACK阶段。

实际检查与发现

  • 仅改变最初输入第8—256字节，operations不变，两次本地copy及4次源put内容同步改变。固定字面量覆写保持原配置；不能说所有包的头部、通知或常量都改变。
  • 排队期输入覆写和运行期输入覆写均被拦住。输出put、输出原子、提前源读、输出条件读、冲突copy入队和本地reset也保留正确部分状态，共8类反例。
  • 本地多个reset有后一项冲突时，前一项也不执行。输出条件不可读时报告保存local_wait_error，不能因报告重读异常丢失原始结果。
  • 共享输入的两个copy可以同时保护同一源，按每GPU FIFO先后执行；完成后输入、输出可合法复用。零时长经过事件调度。
  • 排队/运行两种5ms截止分别保留acquired、acquired+captured，没有commit/release；少计数完全不取得copy记录。

最终29条公开CLI、8条原生检查通过，独立内存核心6,758项断言、14项输入检查通过。5组旧流程、13个固定依赖检查通过；v3新旧逐字节一致，无copy的v4仅多3个说明字段。独立解码包并重放实际内存，不只比较报告字段。

仍不能据此下什么结论

只有显式copy的节点拥有这些输入输出保证。没有copy的节点仍是声明耗时。字节原样复制不等价MoE专家算子；入队保护、开始快照和完成写出不等价真实CUDA访存时刻。MRT1的ACK不等价GIN源安全或GPU可见。

完整现代事件/provider耦合、self-peer物理路径、通知覆盖域、真实专家数值与匹配硬件校准仍缺失。本轮不支持真实长尾归因、策略收益、千卡泛化或A类论文贡献成立的主张。

后续研究的门槛

  1. 按现代真实调用的输入输出布局和覆盖域接入已有事件核心，明确哪些数据只是依赖标记、哪些需要数值；保留不支持边界，不能以人工copy替代真实应用。
  2. 区分源安全、目标可见、应用消费和队列回收，结合明确provider和self-peer资源依据接到共享网络；不凭ACK或全局日志解锁全部数据。
  3. 取得匹配硬件小型测量与独立请求，再选有区分力的多组共享链路对照，检验强基线能否解释长尾。平台功能多少不作为创新性证据。
