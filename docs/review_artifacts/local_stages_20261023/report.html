Scale-Out 平台功能增量 · 2026-10-23 · 仅本地修改

让后续通信等待实际网络与本地处理完成

现在可以在同一原生 ns-3 仿真中执行：接收或 ACK 到达 → 本地处理排队与执行 → 继续发送。本地处理期间，连接、累计序号和拥塞反馈持续保留。本地耗时仍是显式声明参数。

解决的具体问题

只有通信前驱时，不能在持久网络中表达应用处理间隔。将通信拆成独立仿真再相加，又会丢掉间隔中的反馈状态。新增 moe-rdma-stream-work/3，把本地处理作为真实事件驱动的节点加入同一时钟。它为后续分析调用间隔与网络状态的关系提供执行能力。

对论文目标的作用与限制

本轮解决执行语义缺口，没有形成新的拥塞控制、调度算法或论文主贡献。后续须先明确真实调用的就绪与分层完成，再连接现代通信操作和传输；同时取得匹配硬件的GPU/NIC校准及独立请求，才能评价优化收益。

当前每GPU只有一个抽象串行槽；没有CUDA并发、SM/显存、GPU可见性、现代DeepEP在线调用或千卡代表性负载验证。人工ECN阈值只用于触发功能见证，不是生产参数，不据此选择策略。
