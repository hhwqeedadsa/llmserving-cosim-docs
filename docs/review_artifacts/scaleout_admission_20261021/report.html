如何解释

  • FIFO1与轮转1使用同一软件额度；透传与FIFO1/2有意改变软件允许的并发，物理资源保持不变。
  • BE队列积分从完整、有类型事件按原生入出队时点重建，不含NIC数据QP及单独高优先ACK队列；累计量不能当作可消除的业务损失。
  • 数据齐备释放接收消费者，完整ACK后确认发送映射移除才归还软件额度。最终ACK丢失可让源端持续占用额度；另一组是否完成见原始前端历史。
  • 失败运行中未获额度的消息等待是截至5ms的删失量，单独保存在summary.json，不混入成功时延。
  • 本轮不证明新策略贡献，也不依据负收益另造热点。目标库QP复用、硬件共享资源与恢复机制仍需实机校准。
