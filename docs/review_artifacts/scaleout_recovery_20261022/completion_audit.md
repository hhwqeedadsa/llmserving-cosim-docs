# 本轮完成核对

目标：服务于更可靠的仿真器，补齐原生RDMA超时恢复、失败语义及系统推进，不以新策略性能收益为完成条件。

| 要求 | 实施与证据 |
|---|---|
| 源端ACK进展计时、最早未确认字节重传、退避和有限重试 | `retransmission_timer.hh`、专用`rdma/recovery.cc`；真实NIC发送/反馈回调，60项Python与3项纯C++检查通过。 |
| 接收端重复确认必须是真实包 | 重复数据按接收端本地状态生成累计ACK，经原生高优先队列和反向链路发送；最终ACK再次丢弃、尾包、NACK和连续丢失门通过。 |
| 网络与系统完成语义一致 | 接收就绪、完整ACK、QP清理、额度释放分别核验；待准入通信恢复后继续，实际前端在线提交下一轮。 |
| 边界与排空 | 同刻ACK/超时、短超时、旧反馈、双plane独立计时、机内crossbar排除；末尾重复包/ACK排空再结束服务。 |
| 失败不冒充成功 | 两次重传耗尽后明确失败，仿真预算先到另报；QP、额度、未完成消息和图保留。公开流程原结果超额失败也保留。 |
| 默认与观测兼容 | 实际旧二进制默认结果相同，无故障恢复除恢复报告外相同；关闭/截断记录不改变执行，截断不重建缺失历史。 |
| 受影响回归 | 恢复19probe/5服务，原故障11/3、准入11/9、结构11/3及超额拒绝；13依赖检查通过，未升级或修改依赖。 |
| 公共入口可用 | 新拓扑与3个probe；修改包明细上限后的完整2层4步服务、独立`rdma-check`通过，4波/628消息/1512节点/1000615ns。 |
| 平台与实验分开 | 平台`0fb863a`，5组固定MoE对照和报告`210cf69`。实验只调用公开CLI，不导入测试驱动。共同图与首包路径一致；无故障结果相同。 |
| 来源、预算和归档 | 15份构建源码hash一致，106份已有结果重新离线审计通过。原始运行根约143MiB，2823文件hash核验；本机压缩备份11646956 B，hash见archive.json。 |

逐项结论只覆盖已实现的声明协议扩展。自适应RTT/RTO、单QP失败后剩余业务继续、硬件校准、真实通信库分块与QP复用、千卡执行仍为后续建议。报告分别列出，不降低验收条件迁就实现。
