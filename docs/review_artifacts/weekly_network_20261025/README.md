# 本周工作与收益验证网页

直接用浏览器打开 [report.html](report.html)。页面可离线查看，不需要启动服务或加载外部依赖；支持切换通信完成定义、查看故障增量或四条件绝对时刻、切换见证包的正常/故障排队记录、展开原始表格及下载内嵌数据。浏览器打印功能可用于保存 PDF。

页面分别呈现四卡现代单层功能调用、独立通信窗口和旧式完整依赖参考图；三项结果不是同一次实验，页面不把同步次数减少或经典恢复收益当作完整推理加速。所有计划明确标为待验证。

## 修改和重建

- 文案与样式修改 `report.template.html`。
- `build.py` 只用 Python 标准库，读取已有版本化摘要和范围说明，不执行实验，也不导入平台、fixture 或实验驱动。
- 在仓库根目录执行：

```bash
PYTHONPATH=python:. PYTHONDONTWRITEBYTECODE=1 python3 -B docs/review_artifacts/weekly_network_20261025/build.py
```

输出为 `report.html` 和 `report-data.json`。后者与页面内嵌数据相同，保留来源相对路径和 SHA256。保持来源不变时，重建结果逐字节一致。若替换实验来源，需要重新核对输入条件、评价定义和适用范围，不能仅替换页面中的数值。

来源入口和原始四条件数值表均位于页面末尾；仅复制 `report.html` 也能阅读正文与内嵌结果，仓库来源链接需要保留其相对目录。

## 本轮检查

[verification.json](verification.json) 保存交付检查摘要：HTML 标签闭合和 ID 唯一、相对链接存在、六份来源 SHA256、内嵌数据与独立 JSON 相同、JavaScript 语法和确定性重建通过。使用 Node 执行页面实际脚本，在 DOM 替身中核对两种完成定义、两种显示方式、正常/故障队列切换及下载内容；没有安装浏览器，也没有完成真实浏览器布局或截图检查。

页面数值采用纳秒来源并换算为微秒。实验 A 默认展示接收增量下降约87.9%；切换主指标“发送端全部确认”时显示确认增量下降约97.3%。实验 B 的约5.3%指故障任务完成增量下降；约1.71%才是本组故障条件下任务完成时间的相对缩短。上述比例都来自经典机制对照，不是新方法的实测收益。
