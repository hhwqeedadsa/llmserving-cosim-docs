# 同节点服务与远端通信共享内存验收

本轮完成一项平台基础能力：远端真实包与同节点显式服务，在同一ns-3时钟、同一目标内存和现有访问保护下协同推进。它为保留现代通信库必要的self计数/屏障操作提供基础；完整现代DeepEP映射尚未接入，不能据此宣称A类论文主贡献成立。

## 为什么需要这一步

既有源码核查发现，现代DeepEP对self token数据有明确本地旁路，但屏障信号和部分专家计数仍进入provider。旧事务层只支持远端连接；直接删除self会改变完成条件，伪造交换机路径或ACK又会污染网络结论。因此新增明确声明的功能服务，保留必要副作用，同时把未知的硬件成本标明。

普通远端事务继续发送MRT1请求、接收ACK/原子回复并共享交换机队列。self操作使用独立连接FIFO，在实际apply事件按目标NIC权限修改同一RemoteMemory，在complete事件释放源保护和队列额度；不占GPU本地计算槽，不生成包或ACK。不同self连接没有额外全局顺序。输入、命令及字段见[用户示例](../../examples/scaleout_self_peer/README.md)。

混合例正常结束100,000ns，故障结束104,096ns。远端丢包使接收驱动链后移80,000ns；正常时100,000ns声明本地计算决定结束，故障时最后远端完成更晚。不能把这组时长当真实GPU性能，也不能把所有等待直接加成应用损失。

独立oracle从实际源payload解码MRT1，核对端点TX/RX、物理NIC、真实ACK及逐字节内存；同时重建self FIFO、原子旧值、lease捕获/释放和后继读取。它只适用于这些小输入，不是完整transactions/5或现代GIN的通用验证器。8类证据篡改被拒绝。

8项新Python检查与91项受影响回归通过。最初12类native非法输入在Fabric创建前拒绝。代码复核另外发现：旧schema的probe不一定进入v5验证器，可能绕过新增self声明的准入检查；已增加纯输入检查，并验证v1—4各有/无model共8种条件均明确拒绝。修复是本仓库新增功能的输入缺陷，不是上游生产漏洞。

这次补漏仅重编probe消费者并重新链接；核心对象、session程序及8库保持不变。四次正向网络及迁移使用修复前程序，最终probe没有第五次网络；两版源码差异由收尾程序核为新增的纯Fabric前检查，最终native拒绝检查使用修复后的probe。初始运行包与最终交付包分别保留，不能混称同一个程序hash。

## 失败与可复现范围

两次构建准备失败分别为Json隐式转换导致set插入歧义、旧对象/archive缺少当前符号；保存原源码/命令/日志后只修定位原因接续。收尾检查还保留两次错误：帮助文字换行导致子串断言失败、把session的provenance文件误当probe的inputs文件。修复后只复用/重分析已有结果，没有为检查器重跑网络、扩大预算或删除失败。

检查点在`runs/self_peer_service_checkpoint_20261024/`。先验证全部成员hash和安全路径再写入恢复目录，6类不安全归档被拒绝。恢复后的源码离线重算原两组审计，与原verification JSON逐字节一致；第四个独立网络使用包内程序及库。最终包补入入口修复、收尾代码和证据，恢复收据与资源收尾另存。本包依赖同主机Linux/glibc ABI，既不是从零原生构建，也没有跨机校准。

预算保持累计600受监控秒/384MiB、每命令60秒/1GiB RSS/2GiB地址、阶段128MiB、4次1ms网络/result16MiB；最终文件管理预留10秒/2MiB。精确监控、持久副本和归档费用见[收尾](../../fixtures/self_peer_service/closeout.json)，不把复制的历史监控计作新执行。没有下载、安装、GPU执行、依赖修改或push。

## 对研究目标的意义与下一门槛

现在可以在必要self副作用保留的条件下，继续研究远端拥塞/故障如何影响计数和后继通信；当前声明self成本仍不足以评价真实端到端性能。`rdma-context-plan`保持拒绝self，不能删除这些操作后声称现代完整执行。

下一项应先把既有现代context/peer身份、计数和屏障接到共享网络与实际进度，证明完整Dispatch—计算—Combine依赖及有限资源排空。之后才检验“上下文共享是否让局部恢复干扰扩散到健康任务的同步关键路径”，这是待证伪问题，尚非发现或贡献。比较须保留选择重传、合理恢复限速/公平调度、正常排空及provider强退出等基线，并保持连接、队列、内存、带宽和信息条件一致。

已有旧反馈/源空闲候选的反证继续有效，不能改名复活。独立现代工作负载、真实GPU/NIC/provider成本、校准、完整千卡执行和可区别于近邻工作的机制创新仍缺；若强基线解释或消除现象，应结束候选。整体论文目标保持`in_progress`。
