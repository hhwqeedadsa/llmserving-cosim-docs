# 多rail仿真：物理绑定改进前的诊断与要求

本文记录物理绑定实现前的诊断。后续[物理NIC绑定验收](../../fixtures/physical_nic_binding/README.md)已覆盖同plane独立rail与共享Agg；下表和后文“当前”“待实现”均指修复前状态。两项论文创新仍未成立，平台功能完成不改变该结论。

当前发现的是可执行性缺口：生成器能画多rail，持久现代通信入口却未实现同plane多候选NIC绑定。已修复启动前检查；**完整多rail功能和两项论文创新仍未完成**。这改变了研究顺序：先补正确的网络对象，再比较共享上联、通信组织和模拟成本。

## 为什么必须区分

rail表示端点经过哪一组接入网卡/交换路径，plane表示代码中独立的寻址/交换网络域。两者不能仅换名字。此前小场景是rails=1、planes=2：两个plane有各自的交换机和物理端口，因此此前分析得到两个物理交互分量。这不证明“任意多rail都能独立仿真”，也不证明共享Agg或共享缓冲的多rail不存在竞争。

| 网络情况 | 当前持久流/事务/现代入口 | 判断依据 |
|---|---|---|
| 每端点/plane一个可达NIC，交换机内有ECMP | 初始准入支持 | 主机首跳唯一，交换机仍按固定最短跳/ECMP转发 |
| 两个独立plane，每个plane主机首跳唯一 | 初始准入支持；已有单层包级证据 | 声明device/NIC/plane与原生路由匹配 |
| 同plane两条独立rail，同一目标有两个首跳NIC | 启动前拒绝 | 当前原生按目标地址取主机路由，再按QP hash选NIC；持久Open要求声明NIC是唯一候选 |
| 两rail共用Agg/MMU，同时有多个端点NIC | 同样不能直接执行 | 既缺端点显式绑定，也不能靠复制共享交换机绕过 |

这是当前持久传输适配器的范围，不能据此说普通ns-3、ASTRA或其他平台不支持多NIC。拓扑生成、普通SEND/RECV服务和持久现代入口的范围不同；竞品优势和本项目缺项仍见[平台比较](联合仿真的两个创新候选与网络收益判别_20261026.md#3-与其他平台比较哪里值得投入)。

## 已确认的代码原因和修复

`Fabric::RebuildRoutes`按目的GPU/plane计算最短跳，不按带宽加权；`PersistentStreams::Open`要求源、反向路由表分别等于单个source_nic、destination_nic。旧Python只检查端口、plane、端点连通，未检查这个集合约束。双rail单plane最小例0→4有两条6跳路径，主机候选[1,2]，旧前端接受而原生Open规则必须拒绝。没有为证明这一点执行旧原生失败网络。

新增`scaleout_stream_routes.py`按同一规则作纯准入，按目的/plane分组，只保留当前距离表，避免为所有目的保存距离矩阵。三个公开入口均在创建运行输出、调用后端之前拒绝。保留交换机内部ECMP和多物理NIC但唯一最短路的合法输入，未修改选路、报文、计时、协议或固定依赖。8项新增检查与69项回归、64图独立路径枚举及复制源码/空cwd验收见[证据](../../fixtures/stream_nic_preflight/README.md)。

## 真正多NIC支持的实施要求

以下是待实现方案，不能写成当前功能：

1. 用实际GPU/NIC身份区分端点地址或等价的目的定位；不能用请求文件名、研究标签或stream编号制造不同路径。
2. 在固定原生发送QP上显式选择本地NIC。当前GetNicIdxOfQp按目标路由表及hash取值，删除Open断言或临时改全局表都不能保证后续发送仍绑定原NIC。
3. 目的定位、接收NIC、ACK/CNP和原子响应返回路径一致。正反向都须走实际设备与共享交换机，不能用离线完成或零成本控制替代。
4. 共享Agg/MMU只建一次。不能为了让端点NIC唯一而复制交换机、把两次独立仿真相加，或无依据地给两个rail各自整份上联带宽。
5. 路由更新时维护新增目的定位，保留QP序号、拥塞状态和源保护。原NIC失效不自动免费迁移；需要单独定义不可达或恢复行为。
6. 先验证默认单NIC行为不变，再用独立rail、共享Agg、内部ECMP、错误绑定及故障完成小型原生验收；新的构建/网络预算和依赖修改独立规范、提交。

## 对两个创新候选的影响

第一候选要回答“多小的表示仍能选对网络”。前轮普通阶段模型已选对，下一比较必须加入合理的每NIC/链路需求强基线；若只是补充实际绑定或上联容量就消除误判，应归为输入/规则补全，不是新MoE语义贡献。

第二候选要减少包级成本，同时保留跨跳排队、反馈和应用完成。此前两个独立plane的分域不能作为共享Agg多rail的省事件证据。先能在同一物理网络正确表达这种竞争，才有条件检验是否存在跨多跳、反馈边界的实质压缩空间。当前没有新增网络收益或宿主加速数字。
