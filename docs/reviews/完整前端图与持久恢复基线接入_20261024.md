# 完整前端图与持久恢复基线接入

本轮补齐了一个会影响网络研究结论的断点：此前完整前端任务图走一次性消息路径，选择重传等较强恢复参考只接在持久字节/事务路径，两边不能直接连起来。本轮新增公开转换命令，让保存的完整前端图在同一持久网络上按真实接收和确认推进。它是研究基础的实质改进，尚未建立论文主创新。

## 本轮实际完成

新增`scaleout rdma-causal-plan`，读取明确的wave文件清单和连接配置，输出普通v4任务及逐节点映射；之后用已有`rdma-stream-probe`执行。连接明确绑定GPU、NIC、plane、端口和队列深度，多个组和多步仍共享一个原生ns-3时间、队列及连接状态。没有修改固定依赖或构建新原生程序。

每个SEND只发起一次；RECV等待真实连续接收和自己的本地前驱，不再重复发送或当成计算；COMP保留声明时长。图结束必须覆盖全部节点，包括没有被计算节点引用的发送确认，随后才允许同组下一步开始。不同组不新增屏障。此处实现的是原图已经要求的依赖，没有增添现代通信库的屏障或GPU可见性保证。

两组短例的实际包证明了这些区别：数据在6,621ns已到达，接收的本地前驱却到20,100ns才结束；只按数据到达解锁会提前推进。rank0的merge在20,350ns结束，但整组直到32,826ns才结束；若转换只等merge，也会遗漏发送确认。这些是转换必须处理的条件，不是发现原ASTRA或真实通信库存在漏洞。

长例从历史Qwen3-30B-A3B前端group0读取两个完整wave，原rank0/1/512/513明确投影成4端点的0/1/2/3，保留所有消息、任务、时长、依赖及路由选择。独立逆变换逐字段回查，未截层、未改计算成本或按固定通信时刻安排流量。物理拓扑、一次性QP和信用模型已经改变，因此不能与原千卡600秒超时比较加速比。长例是合成专家选择和声明成本，不是数据集的四请求或实机测量。

长例保存全部11,512条端点包事件，逐项重建接收/ACK前缀、发送边界、队列信用、本地串行及组结束；27,192次链路发送由实际端点包和独立最短跳数与全网端口总量核对。没有中间交换机的全量逐包捕获，不能称为实际ECMP路径全还原。此输入没有ECN/PFC，不能支撑拥塞长尾结论。

## 验证与边界

142项相关Python检查通过，包含48层转换、跨rank环、缺失/重复消息、错误NIC和遗漏轮次。首次测试把单向等待误标为环，修正测试输入后通过；没有为此更改平台逻辑。七类证据篡改及八类不安全归档均拒绝，原失败保留。四次实际网络均已用完，没有为检查器改动重复网络。

最后一次执行由已核验v1快照在新Python源码根、空cwd调用公开命令；长图work/mapping与事先转换结果逐字节一致，三个旧例及长例的离线报告重复一致。它没有做第二次长网络重跑，也不是从零原生构建。运行时程序及八库是明确hash的已有外部输入，不包含在本轮源码/证据包中。独立检查器之后增加端点模式和串行槽复核，版本与hash保留。

当前还不能把它称为现代DeepEP端到端复现：该入口不再次运行ASTRA调度；声明串行计算、持久QP、队列信用及同纳秒顺序与旧路径不保证等价。没有张量数值、GPU可见性、self-peer GIN及跨context可见域校准，也没有生产恢复成本或真实硬件验证。使用入口、结果和原件位置见[用户示例](../../examples/scaleout_causal_waves/README.md)与[验收记录](../../fixtures/causal_waves/README.md)。

## 对下一步研究的作用

现在可以在保存的完整应用依赖下使用同一强传输参考，而不再把一段同时发布的通信窗口当成应用。下一步应另行预注册真实路由/完整依赖的网络损失对照，核查故障影响是否越过依赖余量，并比较选择重传、合理恢复限速/公平队列和通用排程；若经典方案已消除实质损失，就结束该候选。

现代通信库的必要屏障、自发请求和可见性仍须按原规范接入，不能用本轮较易实现的参考图替代。独立请求留出、匹配校准、完整千卡场景和有意义的强基线差距尚未成立；整体A类论文目标保持进行中。
