# 强传输基线后的故障外溢：保留现象，收紧创新候选

本轮最重要的结果是：经典选择重传已经消除了此前大部分通信窗口完成损失。故障确实还会让没有直接丢包的流多排队，但这种等待不等于完整应用能获得同样大的优化收益。应据此收紧研究候选。

## 比较了什么

保持四份真实推理专家路由、74项远端写、1,070,336B、12持久连接、所有工作0ns发布、100G接入/25G上层Clos及8—10链路关闭/控制延迟不变。平台固定`2dc9eb7`，用同一二进制执行四次正常/故障×回退/选择重传，不修改平台或依赖。回退两条件的完整原生结果与前轮一致，只有加载库路径不同。

选择窗口261,145B大于每流整个工作量（最大115,712B），因此不可能靠活动窗口限制流量来改变结果。选择模式允许262,144B/连接的乱序payload空间，实际故障各流峰值合计136,104B；它确有额外缓冲与元数据成本。模型ACK从48B变为50B，正常源端数据/反馈/CNP帧合计从1,165,208B增至1,167,428B。没有把这些成本抹掉，也没有声称复刻IRN或生产RoCE。

## 发现和含义

| 指标 | 回退重传：故障增量 | 选择重传：故障增量 |
|---|---:|---:|
| 全窗口最后接收 | 21.058us | 2.547us |
| 全窗口最后源确认 | 19.028us | 0.515us |
| 源重复payload | 566,096B | 459,848B |

最后接收与最后源确认的残余不同，因为反馈传播、排队和决定最后完成的流会改变。不能只引用较小的0.515us当作数据全部就绪的时间，也不能将任一值称GPU可见或完整推理耗时。选择模式正常最后接收/确认也分别慢105/109ns；比较使用各模式自己的正常基线。

预先关注的stream8仍没有直接丢包，路径仍相同。它的最后前缀接收比正常慢61.213us：实际源发送早28ns，逐跳排队增加61,241ns，非排队传输不变。11→8出口仍有50,192B已被源累计确认的重传模型帧排在它前面；源发送这些副本时尚未获得覆盖确认，不能指责发送端明知确认仍发送。

但故障下stream8在132.242us已完成接收，全窗口最后接收在141.539us，由stream4决定；它仍有9.297us余量。选择重传没有消灭共享队列干扰，却大幅缩小了窗口完成差异。这说明“有健康流多等约61us”不足以证明“有约61us整体优化空间”。经典选择重传和依赖余量都必须进入研究解释。

## 证据和下一步

四组全部完成并物理排空，捕获完整；每组74项写、实际源包、每跳TX/RX/丢弃、真实反馈扩展、接收缓冲、FIFO拥有者、队列积分/峰值、末态MMU和完成回调均独立核对。四份原始JSON重新hash并独立抽取路由，5类实际证据篡改被拒绝。完整数字、脚本、归档与边界见[研究入口](../../experiments/selective_externality/README.md)。没有为补充检查重跑网络。

本轮不继续围绕原19us差异开发恢复算法，也不将选择重传计入新方法收益。下一步先把完整Dispatch—计算—Combine依赖和现有现代库的集合屏障接入有依据的实际传输；不能为了让某条流成为关键路径而删屏障或挑选任务。只有残余影响在同资源强基线、完整应用及代表性留出中仍有实质价值，才进入新机制设计。

当前仍缺完整现代provider/self-peer语义、GPU可见性、匹配硬件校准、独立代表性请求及千卡长工作量。这些限制没有由本轮四个小窗口消除，整体A类论文目标继续进行中。
