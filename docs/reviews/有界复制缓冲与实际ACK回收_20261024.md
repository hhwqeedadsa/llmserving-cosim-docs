# 有界复制缓冲与实际ACK回收

本轮补齐一个会影响网络恢复研究的系统问题：源窗口被保护，不代表重传副本已回收；目标已经写入，也不代表源端知道可以释放。现在平台能分别限制并核对这几类内容，失败恢复不再隐含使用无限发送副本。它是研究前提的修正，尚不是论文机制贡献。

## 目标、范围与结果

平台从本地`8ddd2c6`增加transactions/4的可选`bounded_copied_put/1`，不改默认结果。只支持注册源put；注册窗口、每源传输副本、目标请求去重缓存、本地copy快照有独立额度。MRT1副本包含32B功能帧头，队列与副本池都允许后才读取源窗口，完整累计ACK到达才清空实际payload vector并归还空间。编码后清空operation body，本地copy实际完成后清空快照；源lease仍保留至原有事务完成。

人工四次8B写、每源40B池的发布时刻为0、12,060、24,120、36,180ns，48,240ns结束；这是明确容量约束引起的串行反馈等待，不是硬件测量或优化收益。同源另一连接能被ACK释放唤醒，不同源可同时发布。ACK丢失时，目标已应用但失败源的40B副本继续占用；同源后续操作没有提前捕获或发送，另一源仍能完成。80B池还允许健康同源连接使用剩余40B继续工作。源lease引用量与副本占用分开记录，重叠lease不是新增分配。

公开[小例](../../examples/scaleout_rdma_transactions/bounded-buffers.json)完成三次实际写入与一次目标本地copy，36,180ns结束；输出窗口由本次收到的字节形成。所有操作、队列、故障、ACK与控制定时器共用同一原生ns-3时钟和持续存在的网络，没有拼接独立通信耗时。

## 验证与保留的错误

9项新功能条件、1项旧完整结果对照通过；默认结果逐字节不变，足量池除新增报告外相同。10类原生绕过前端的非法输入被拒绝，包含在线超额整批无副作用、已有timer未被无效批次取消。7项新单元检查、34项既有事务检查、持久流/事务/在线会话/显式前缀4组相关流程及13项固定依赖检查通过。

首次中段丢包检查没有产生NACK，检查断言失败。原因是注入规则写了源node0，而数据drop在目标node4匹配；先前tail条件也未命中。保留两份实际网络与原脚本，将它们明确归为诊断执行。只更正接收节点并增加drop次数断言，新执行的tail和middle条件各实际丢一包；middle条件在源端实际收到NACK。未重跑不受影响的成功网络、未放宽断言或增加资源限额。

独立工具对上述全部12份实际结果重放源帧、实收ACK、窗口写入、本地copy与池事件，共核查76次源发送、24次目标副作用、10份启用容量模型的结果；提前释放、虚假峰值和篡改最终内存均被拒绝。恢复验证及资源收尾见[验收记录](../../fixtures/bounded_buffers/README.md)，详细机器可读结果在同目录verification/independent-audit/recovery/closeout JSON。

## 对研究的影响与仍需补齐的证据

目标请求缓存按已接纳帧累计保守预留，实际缓存直到会话销毁；本轮没有发明可安全淘汰的确认，也没有解决无限连续服务。失败源的payload和lease继续保留，控制timer不能使其自动安全释放。当前32项远端/16项本地等工作预算也仍在；不能把小例通过写成千卡或长期吞吐能力。

额度只覆盖命名数据内容，元数据、解码临时对象、包、观测hex及结果副本不在其中。捕获临时向量的峰值单列；本轮不是宿主RSS或GPU显存总量上界，更没有现代GPU/NIC容量和完成语义校准。MRT1副本、普通流ACK与真实RoCE/GIN provider也不能直接等同。

下一研究门槛是连续有限容量下的安全恢复：须明确旧访问何时退出、失败源副本和目标窗口何时能回收，并让同信息操作级重放、独立窗口以及显式静默确认等强基线使用同等资源和可见信息。上一阶段owner保留已与同信息操作重放相同，不能再次当创新。只有机制差异、代表性负载、可信校准和规模泛化获得独立证据，才可讨论A类投稿贡献；本轮不宣称已经达到该目标。
