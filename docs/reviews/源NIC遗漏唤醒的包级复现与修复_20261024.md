# 源NIC遗漏唤醒的包级复现与修复

本轮确认并修复了原生Scale-Out源NIC中的调度正确性缺陷：有些数据已经满足发送条件，端口也已空闲，却没有安排下一次限速唤醒，要等一个无关的ACK到达才继续。这个等待属于仿真器行为，不能当作真实网络拥堵或MoE优化机会。

## 问题怎样发生

源NIC需要从多条队列对（QP）中选择下一包。原生`GetNextQindex`已经检查待发字节、PFC暂停和窗口，但没有可发包时，`DequeueAndTransmit`直接从**全部QP**取最小`m_nextAvail`。一条已经发完、仍等ACK的连接可以保留很早的时间；另一条确有数据的连接虽然稍后就能发，却没有得到定时器。

另一个错误是新加入的连接具有更早的未来可发时刻时，旧逻辑只在“当前没有定时器”时创建事件，因此可能保留一个更晚的旧唤醒。PFC暂停或窗口阻塞连接也能产生类似的错误候选。

这些结论来自当前锁定库的真实队列和事件执行，不是只凭源码推测。正常的物理串行服务、速率约束、窗口和PFC等待仍应保留。

## 实际数据包怎样证明

最小原生网络包含两个NIC和一条100G、单向传播10us的真实channel。连接A发送1,000B，连接B发送16,000B，声明初始QP速率分别100G和10G；没有故障、交换机、MoE任务或人工ACK。两种条件使用相同输入与记录器，只改变原生库。数据包和ACK均由原生`RdmaHw`生成、发送和接收。

| 实际事件 | 旧库 | 修复库 |
|---|---:|---:|
| B首包开始发送/ns | 83 | 83 |
| 此次物理发送结束/ns | 166 | 166 |
| B下一包真实可发时刻/ns | 912 | 912 |
| 166ns检查后的唤醒 | 未安排 | 912ns |
| B下一包实际发送/ns | 20,087 | 912 |
| 第一个实际ACK到达源/ns | 20,087 | 20,087 |
| B最终ACK完成/ns | 51,780 | 32,605 |

166ns时，A已无待发字节但仍未收到ACK，旧截止为83ns；B尚有15,000B、未暂停、窗口不约束，截止912ns。被动记录同时证明了这些状态和旧库遗漏的事件。旧B下一包恰在A的ACK唤醒后发送；修复后在任何ACK到来前已经继续。

两个条件各17数据包和17 ACK，总payload17,000B，所有字节、前缀确认、物理TX/RX配对和端口串行服务独立核对。B完成差值19,175ns对应这个特定功能用例，不能当作完整推理收益或硬件测量。

## 修复做了什么

`QbbNetDevice::ScheduleNextSend`只从有待发字节、未暂停且窗口允许的QP中取最早时刻；没有候选时取消无用定时器。已有更早回调可以保留并重新检查，新任务更早时则提前事件。速率更新也按当前候选重新检查，在变量窗口场景先写入新速率，再计算有效窗口。

修复没有改变ACK高优先级、数据RR选队、PktSent限速、物理服务或应用依赖，没有通过忙轮询、预填未来字节或预设通信完成时刻绕开问题。源补丁在固定原生库上实现，没有升级上游或修改UB、`serving/`、GPU执行路径。

## 额外覆盖与复现

- 11个原生CPU状态条件覆盖单QP、已发完未ACK、窗口阻塞、暂停、全部不可发、新增更早工作、变速和解除约束。旧库5项错过应有唤醒，修复后全部满足；没有候选时不再保留无用定时器。
- 2个实际`ChangeRate`的CPU条件检查变量窗口随新速率解除或产生约束。另2个同纳秒原生事件顺序条件检查暂停先于唤醒、唤醒先于暂停，并通过原生`Resume`恢复。它们使用人工QP状态、零数据包，不冒充真实包级同刻控制竞争。
- 公开v5事务网络首请求包实际丢失一次，5远端操作、3次本地copy和25内存事件由真实交付的MRT1字节驱动，副作用恰好一次。
- 新源码根、空工作目录重新生成拓扑，实际公开默认持久入口完成3次写和1次本地处理，共10,000B；八个ns-3库全部从恢复目录加载。最终两份离线核验在新源码根复算逐字节相同。
- 共四次网络，全部成功，已经关闭，不增加第五次。编译、增量链接和离线检查器的失败版本与日志保留；没有重跑成功网络或扩大预算。默认捕获的message_id为−1，检查器已改为依据实际线上端口/IP关联，未跳过这些帧。

## 对原研究意味着什么

上一轮完整图中的实际包/队列时间核算仍是其旧库下的事实，但源端空闲的机制解释需要重新判断。本轮证明仿真器确实能够产生遗漏唤醒，没有证明旧work99的7.496/11.136us空闲全部由此造成，也没有证明残余8.986us改路逆序一定消失。

下一研究应固定本轮平台，保持原216节点、76次写及全部依赖，另立健康/延迟/立即三个条件，与保存的旧结果比较，不重跑旧成功网络。若异常消失，应结束这个优化候选，不能将修补模拟器当成新MoE算法。

这一步提高了研究结论的可信度，仍不是A类论文主贡献。现代通信语义、独立工作负载、硬件校准和完整千卡应用验证仍缺，整体目标继续进行。
