# 现代通信校准条件与论文验证路线

**当前确实可见A100，但尚不具备所选现代DeepEP分支的实机网络校准条件。** 本轮将“设备信息尚未确认”收紧为可核对的环境事实，并据此明确后续实验的用途。它是论文证据缺项审计，不是硬件性能实验或论文目标完成证明。

只读检查入口为[inspect_calibration_environment.py](../../experiments/paper_readiness/inspect_calibration_environment.py)。结果见[环境摘要](../review_artifacts/calibration_readiness_20261022/summary.json)、[独立核对](../review_artifacts/calibration_readiness_20261022/verification.json)和[执行/检查点](../review_artifacts/calibration_readiness_20261022/maintenance.json)。范围仅为捕获时当前进程/容器可见资源，不是整个实验室或集群清单；不含GPU UUID、网卡GUID、IP或凭证。

## 1. 实际观察到什么

| 对象 | 本轮观察 | 对研究的含义 |
|---|---|---|
| GPU | 6张A100 80GB：4张报告PCIe、2张报告SXM4；compute capability均为8.0 | 可以确定当前可见GPU架构；不能称已取得Hopper现代库测量 |
| GPU互联 | 可见矩阵有PXB、NODE、SYS关系，没有观察到NV#配对 | 不能由“SXM4”名称自动构造NVLink域；矩阵关系也不是实测P2P带宽 |
| GPU到NIC位置 | 矩阵显示某些GPU到NIC为PIX/PXB，另一些跨SYS | NIC绑定与NUMA位置会改变经过的互联，不能每消息随机挑网卡；尚未测其代价 |
| RDMA端口 | sysfs有4个mlx5设备，所见端口均Down/Disabled，link layer为Ethernet | 不具备可见的活跃Scale-Out端口；不能由设备数推断可用multi-rail |
| RDMA用户接口 | `/dev/infiniband`不可见；`ibv_devinfo -l`返回0个HCA | 当前进程无可枚举的verbs设备，不能执行所需网络校准 |
| 端口rate字段 | sysfs报告40 Gb/sec，但端口不活跃 | 只保留为原始字段，不作为链路速率、测量结果或仿真参数 |
| 编译和Python | 当前PATH未发现nvcc；两个明确检查的Python环境均无torch和nvidia-nccl分发元数据 | 仅说明这两个环境及PATH；没有遍历所有环境，也没有证明系统各处都无CUDA/NCCL |
| 已有测量工具 | ib_write_bw、ib_atomic_bw报告6.20；所读help未列出--use_cuda | 工具存在不等于GPU Direct RDMA可用，更不能替代GIN内核测量 |

所有操作都是枚举、版本、帮助、包元数据或sysfs读取；没有发送业务流量、创建CUDA/RDMA上下文、安装包、启用端口或改驱动。perftest的完整help/version在本机返回1，原退出码保留；初版将其help分类为unknown，修正识别后在新目录重做只读检查，未将退出码改写为0。

## 2. 为什么不能把A100测量直接标成现代强基线

选定DeepEP提交`f6aa38fe06cd4a0489e7730365d4e0114970a2f3`的README第49—53行明确要求Hopper或更新GPU、CUDA Toolkit≥13.1、带CUDA的PyTorch≥2.10、NCCL≥2.32.3。原文、SHA256及Git blob见摘要。当前可见A100为Ampere，首先就不满足该GPU要求；驱动版本不能代替已安装Toolkit版本，版本满足也不能证明实际加载了所核对的NCCL/GDAKI构建。

因此需要保留两条证据线：A100上已有的旧算子或兼容通信库测量可用于其明确分支；现代direct的去重、批量计数、GIN信号与持久QP则继续采用固定源码语义，并等待匹配硬件上的代价与可见性验证。不能降低现代基线、把旧版本标成当前最强方案，也不能按峰值算力将A100时间缩放成Hopper时间。

历史22项H=F=256的A100算子测量仍仅覆盖原实现和原形状。本轮没有执行它们，也没有证明其采集机器与当前可见资源完全相同。四份R1-AWQ/MMLU路由仍是Decode观察，不会因发现A100就变成完整四卡R1部署或训练总体样本。

## 3. 校准应验证什么，怎样区分竞争解释

校准对象是网络请求和资源等待。GPU用于产生和消费通信；不能用一个GPU型号字段同时替代GPU调度、NIC选择、库分支、源缓冲和网络参数。下表是待执行的方法，不是已经存在的测量结果或命令。

| 实验 | 保持与变化 | 主要观测与判别 |
|---|---|---|
| 单操作成本 | 固定rank/NIC/provider及路径，分别测8B内联值、512B专家块、14,464B Dispatch、14,400B Combine | 分开提交、目标可见与源可复用；检验仅按字节/带宽估计能否解释成本 |
| 原子signal | 固定同一peer/context，比较signal与普通8B put | 观察原子请求、返回/完成与signal wait，排除“等字节就等代价”；不把MRT1反向普通流当Atomic ACK |
| self-peer | 相同API/context/操作数，比较发给自己与跨rank | 确认self是否占用相同提交/CQ资源及实际回环路径；不预设零成本或经过交换机 |
| AggregateRequests | 同一批操作和依赖，改变合法doorbell聚合边界 | 区分提交次数与工作量；“跳过doorbell”不能解释成跳过操作或合并报文字节 |
| 并发/队列额度 | 固定消息和总量，改变并发工作、上下文数与合法队列深度 | 分开源额度等待、NIC/CQ等待和链路排队；不以测试额度制造网络瓶颈 |
| NIC/NUMA位置 | 先固定网络路径和操作，再改变明确绑定的本地NIC位置 | 核对实际发端端口、PCIe路径和服务时间；不使用ECMP替代网卡选择 |
| 多EP组共享网络 | 相同路由总量与并发定义，共享瓶颈对照分离链路 | 全部组运行于同一网络时钟和持续队列；不能把多次独立运行耗时相加 |

512B是本次声明EP4/E256下每rank64个int64专家计数的块大小，不是所有EP配置的固定值。数据长度来自固定现代BF16/H7168/Top8分支，也不等于线上总字节。

每项先用单操作和低并发确定服务/资源含义，再验证未参与拟合的大小、并发和绑定。测量记录固定库源码/构建、实际加载库、GPU/NIC型号与位置、端口状态、拓扑、时钟域和原始重复样本。报告p50/p95/p99、分布及误差，不只给均值拟合；跨设备时钟须有同步或同端往返依据，不从未同步时间戳直接相减。接受的误差范围须按论文主张预先说明，不能看完结果再选阈值。

还需记录实际GPU内存使用、WQE/CQ模式和provider默认值的覆盖链。目标可见、源可复用、应用完成和物理排空分别核对；包级记录应能还原实际原子/响应、数据和反馈，不用应用操作数冒充包数。

## 4. 当前能做、不能证明什么

| 工作 | 当前状态 | 支撑的主张 |
|---|---|---|
| 固定源码、真实路由操作核算 | 已有证据；本轮未重做 | 有范围的去重、控制请求、连接及布局事实 |
| 现代事件/窗口/源读检查 | 已有平台功能，且可不依赖GPU执行 | 声明事件下的依赖与状态约束；不是传输或GPU观测 |
| MRT1/native功能事务 | 已有独立包级功能路径 | 实际请求字节触发目标修改与返回；不证明RoCE/GIN代价 |
| 现代完整联合执行 | 尚未实现 | 不能声称现代请求已全部在线驱动网络 |
| 匹配现代GPU/NIC的校准 | 当前可见环境不满足必要条件 | 不能报告现代性能精度、优化收益或生产长尾解释 |
| 千卡完整推理与泛化 | 历史1024卡长工作量未通过；仍缺留出数据 | 小场景、512卡参考或四路由不能替代该证据 |

软件后续仍可推进：把应用状态与真正收到的payload关联，验证provider资源和完成回调，并保留self-peer的不支持边界。尚无依据的服务代价不通过任意常量或零时间补齐，功能模型也不被用来给现代方案排性能名次。

## 5. 对A类论文目标的实际影响

网络论文需要在可信现代基线下证明正常真实负载的关键等待及可消除损失；系统论文需要证明端到端服务改进及代价；仿真论文需要独立实机校准、误差/开销和规模泛化。已有功能数量、源码摘录或局部检查通过，均不能替代这些结果。

当前优先级仍是：先使联合执行的语义可核对，同时落实匹配Hopper+和可访问活跃RDMA设备的校准环境；再用留出负载比较强基线和机制，最后扩大组数与集群规模。主贡献与这些验证尚未成立，论文目标继续进行中。本轮不把环境审计包装成研究创新，也不因暂缺硬件而悄悄缩小最终目标。
