# 联合仿真应优先解决什么：平台比较、两项候选和新对照

2026-10-26起持续更新。已交付现代完整调用的选择性重传、物理NIC绑定、显式专家耗时和独立网络判别实验。**普通逐链路基线已解释多组网络选择；固定校验复用的完整流程测量也未达到事前明显收益阈值。两项论文创新仍未成立，不能把常规缓存或额外语义数量当作贡献。**

最终目标是让MoE推理网络研究者可靠地判断：给定模型路由、batch、专家放置和网络资源，瓶颈在哪里、哪种改动有效，以及为得到这个判断需要多细的仿真。首先服务于Scale-Out跨机网络配置和通信组织；不是通用GPU设计平台，也不是以增加仿真器功能数量为目标。

最新[事务载体边界核查](../../experiments/transport_semantics_audit/README.md)调整后续优先级：两份已封存完整执行各140帧/280源包都保持work分包边界；仅删32B功能头并不减少原2000B载荷MTU下的包数，不能由1.493%帧字节比例承诺提速。更实质的边界是48次远端原子各有独立MRT1 Reply和ACK，原子相关源数据/ACK占192/560包；全部操作完成后，Reply确认仍晚约6.0微秒。这是当前功能协议事实，不是实际RC冗余或可消除推理收益。缓存RXE源码的成功原子分支用Atomic ACK携带旧值，不能把两个普通可靠流的网络竞争等同目标RoCE/GIN。

## 2. 新实验真正说明了什么

此前功能小例使用64B分包，其设置服务于正确性检查。此次从原始数据独立选用此前未用于该功能调用的记录下标2/层3，保持原Top8，每rank一个token；采用显式2KB分包、选择性重传和声明计算成本，经公开现代入口完成三次共享网络执行。这个路由条目不同，不把新旧结果的差值解释为分包优化。

| 条件 | 模型应用阶段完成 | 全部现代事件/源保护释放 | 网络排空 |
|---|---:|---:|---:|
| 原网络：各层100G、传播1μs | 57.479μs | 63.523μs | 69.547μs |
| 同拓扑各层200G，NIC额度同步增加 | 53.446μs | 59.468μs | 65.480μs |
| 原100G，各链路传播0.5μs | 33.503μs | 36.547μs | 39.571μs |

按模型应用阶段计，带宽翻倍改善**4.033μs/7.02%**，传播减半改善**23.976μs/41.71%**。按源保护全部释放计，分别改善6.38%/42.47%；按网络排空计为5.85%/43.10%。三者必须分别展示：阶段完成不授权提前复用源地址，排空也不是实测用户请求完成时间。

三条件输入和现代计划完全一致：120个现代操作、576个事件，实际源MRT1帧共271,200B，264个源数据包；均无重复源包或恢复超时，参考控制器没有CNP命名事件。实际端口速率和传播读回符合输入，物理捕获无遗漏；本轮分析没有据此宣称完成全物理路径重建。

其中控制请求及其原子回复共10,848B，占MRT1帧字节**4%**；对应120个源数据包，占**45.45%**。其余144包为token数据。这不含独立ACK/NACK/CNP及所有链路物理头开销，不能改称“全网线上字节比例”。小消息字节少，仍可能引入依赖和往返；仅看All-to-All总字节数不足以描述该调用。

目前支持的结论是：**在这个小batch、声明成本的模型中，降低传播时延比单纯增加带宽更有作用。** 传播变化同时影响控制与数据，不能把41.71%全部归因于控制消息；也不能推导大batch、真实GPU或故障拥塞场景同样如此。它符合多阶段通信的基本规律，是研究筛选证据，不是新网络机制。

## 4. 优先候选一：找出影响网络决策的最小通信语义

2026-10-27新增请求核验：[batch4/8三网络对照](../../experiments/compact_network_choice/results/20261027/report.md)已完成12次现代/通用图执行。仅字节方法的选择后悔值59.94%/52.33%，但普通七阶段operand/帧方法已选对，时延仍有最高23.57%/19.14%的绝对相对误差；因此没有证明新增语义的额外决策收益。完整图在六条件均有行为一致证据，最后一组保留after前驱列表排列的严格检查失败及独立离线解释，不重新执行。后续须先检验共享上联、多rail不均衡、路径/排队变化能否使普通阶段基线发生有实际代价的误判，而不是继续用总字节弱基线支持创新。表示大小下降不是已测仿真加速，当前单层EP4/声明成本和新样本远端版本边界保持不变。

**要实现的效果：避免把钱和优化时间投入模型误判的瓶颈。** 问题不是“能不能画出更多事件”，而是忽略哪些小消息、连接状态或完成条件，会选错带宽、rail数量、专家放置或通信组织。

方法候选是从同一现代操作表示构造逐级抽象：仅字节矩阵；带就绪依赖的DAG；再保留持久连接/控制操作/目标可见与源保护/有限端点资源。按具体决策逐项消融，找到必须保留的条件，给出预测区间；差异小于模型不确定性时报告“无法可靠区分”。不对每个字段都一律使用最细模型。

下一项最小判别必须固定payload、实际端口和ECMP身份、资源和原始路由，明确消融是否还改变消息数或顺序；以现有依赖DAG、profile模型和真实CCL路径作强基线。若通用DAG已得到同样排序，则不能把完整语义表的作用算收益。最终看方案排序错误率、选择后悔值及硬件留出误差，不只看某次时延差。

10月26日的小batch对照仅支持开展验证；10月27日的完整通用图已在两条件给出相同应用/网络结果，没有证明额外现代控制器带来决策收益。下一研究须把完整图作为强基线，检验更精简表示、动态绑定改变及独立请求，仍未证明决策反转或完成真实系统校准。若更简单的模型已稳定给出同样选择，或误差不影响目标决策，应淘汰或降为工程功能。

## 5. 优先候选二：按真实交互范围控制包级仿真成本

**要实现的效果：用更少宿主时间和内存，得到足够可靠的百卡/千卡网络决策。** 它改善的是仿真运行成本，不能写成被仿真的MoE推理加速。

候选方法在保持操作依赖的基础上，追踪共享NIC/交换队列、共享缓冲、PFC/ECN、拥塞控制、重传和应用门槛所形成的交互范围。确认不可能跨越事件/队列阈值的区间才合并或近似；出现新的共享竞争、故障或不确定性时细化。不能只把“非热点专家”降精度，因为非热点的ACK、控制消息或恢复流量仍可能影响热点。

现有回调批次已经减少前后端同步而保持网络内容/时刻；它是基线工程优化。它没有减少全部ns-3包事件，也没有解决千卡完整现代EP。QP复用、并行仿真和多保真也已有先例。论文差异必须落实到交互范围选择、误差/回退条件及实际收益，不能改个名称。

先以完整包级模型核对小规模的应用完成、源释放、反馈状态和方案排序，再分别扩大总GPU数、EP组和副本数；千卡EP4副本不能写成EP1024。评价同时报告宿主加速比、RSS、事件数、精度与选择后悔值。若交互范围闭包总是覆盖全网，或经典事件批处理/现有后端已足够快，就应淘汰这个候选。

本轮未实现此方法，也没有新的千卡性能结果。10月27日的离线核算进一步给出静态分rail的较强基线和具体串行竞争见证：两个条件分别累计排队38.991/20.244us，不能用其差值承诺应用收益。仍须证明未来到达/阈值界及共享GPU、回调、随机数、反馈状态处理；当前正常无反馈记录不能代表故障恢复下的安全抽象。

## 6. 收益有多少、预期空间在哪里

目前有数字的只有明确对象：指定网络升级在这个模型阶段分别节省4.033μs和23.976μs；接入已有选择重传后，一个指定丢包条件的会话增量为6.550μs。**没有已验证的新方法收益，也没有设备价格，不能给商业收益率。** 上述差值不是严格可优化上界，也不意味着软件方法能够实现传播减半。

候选一的收益应是降低决策误差，避免无效网络扩容；候选二是同等决策可靠性下缩短仿真时间和降低内存。以后若提出实际通信优化，再单独报告对较强基线的净推理收益，包括正常情况开销。

推广到整请求还要乘受影响阶段占比和受影响请求比例，再扣除所有请求都承担的开销。比如某阶段占请求30%、只有10%请求受益、该阶段改善7%，整请求平均毛收益只是0.21%；若通用开销为0.2%，净值约0.01%。这是说明稀释作用的假设算例，不是本项目预测。故障出现率和开销未知时，不用故障样本的改善承诺生产平均收益。

接下来先做一项匹配的语义消融与独立路由验证，再决定是否开发上述候选算法。最终学术产出需要一个有用且可证伪的主张、强基线、真实匹配校准和留出结果；当前完成的是可信的平台基线和方向筛选，不承诺投稿等级。
