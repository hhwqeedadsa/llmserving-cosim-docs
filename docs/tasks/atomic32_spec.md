# 32位通知事务与本地等待

服务对象是后续旧低延迟4B通知的功能接入。既有事务fetch_add及MRT1 verb2/reply3为64位，保持不变；新增公开fetch_add32，值范围0..2^32-1，按模2^32更新对齐的4B小端目标内存，负数由调用者显式编码为无符号二补数。MRT1新增verb4请求/verb5回复、4B大端body；它不是RoCE扩展原子线编码或旧库nonfetch原子WQE实现。

目标权限、NIC注册范围、相邻计数器、重复请求缓存和读写lease按实际4B检查。原子回复来自实际执行得到的旧值；请求ACK与回复分别到达后才完成和释放槽，重复/冲突回复需检查宽度。源操作真值不提供目标值，不合并相邻计数器或把4B扩大成8B。默认fetch_add继续8B，旧输入输出保持。

本地local_wait可显式bits=32，省略为64。按对应对齐/边界读取，eq/ge均为无符号比较，value/reset_to在该位宽内；消费清零仅改对应字节。条件来自当前本地窗口，不能由远端元数据代替。两种位宽的同位置重复条件仍拒绝。本地copy/源范围与reset重叠校验也按实际位宽。

先以独立C++检查验证编码/跨包/四字节边界/溢出/邻居不变/重放/lease/注册权限，再核对Python与C++准入。公开新目录流程在128端点Clos内安排稀疏人工事务：相邻计数器、溢出、两连接竞争同一计数器、目标32位等待和消费后后继发送，正常与选择重传条件各一次。逐包重建实际MRT1请求/回复和目标最终窗口，检查源完成门限、丢失/重传与目标只应用一次；不能把128端点称满载或真实MoE。复核旧64位公开流程及固定依赖。完整旧低延迟计划、通知到WQE/硬件ACK的映射和性能收益仍单列未完成。

补充准入核验限于上述新构建二进制：九种非法v5输入分别直调probe/session，必须在其已有`ValidateSessionProgram`、Fabric构造之前按预期原因拒绝，不调用Simulator::Run，不产生结果或网络。检查原子值溢出、未对齐/越界/权限，以及条件位宽、值、reset、未对齐和混合重叠。沿用非构建阶段120秒/RSS1GiB/地址2GiB及累计预算；不新增成功网络、不重跑前三条件。核验器的篡改检查只读现有结果副本，不运行网络。
