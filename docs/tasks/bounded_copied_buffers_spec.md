# 有界复制型事务缓冲平台增量

基线`8ddd2c6`。上一轮确认源窗口lease、重传副本与目标缓存不能混为一项。本轮实现显式有界复制型功能模式，保留默认行为；先验收平台，不执行研究收益矩阵，不宣称论文创新或实机GPU/NIC能力。

## 模式与范围

transactions/4可选`buffer_model`，严格字段：

```json
{"mode":"bounded_copied_put/1","transport_bytes_per_source":80,
 "registered_bytes_per_owner":4096,"target_cache_bytes_per_owner":4096,
 "local_copy_bytes_per_owner":256}
```

- 本模式要求v4、无explicit-prefix、remote全部为引用注册源窗口的put；暂不支持inline put、原子及v5稀疏窗口。拒绝不支持组合，不改变既有模式定义。
- transport cap为每源GPU持久Work.payload的编码字节（包含32B MRT1功能帧头，不是RoCE开销），33—2MiB；其他cap分别为固定注册窗口合计1—1MiB、目标保留请求帧33—2MiB、本地copy快照1—32768B。整数拒绝bool/浮点/负值/额外字段。
- 注册窗口按owner固定核算；目标去重缓存按全部已接纳put的总帧长度保守预留，累计至会话结束，不假造可安全淘汰。在线每批全候选先校验，超额批次不得注册前部操作或修改timer。
- transport pool按真实payload入队占用；不够时该连接暂不捕获/发布后续put，由实际累计ACK释放空间后继续。每个完整工作ACK后清空其真实payload vector并归还占用；超时/重试/目标applied不释放，失败源占用保留。不同源池独立，连接共享同源池。
- 工作只有在自身队列及pool都可用后才读取应用源窗口；复制到帧后不长期保留op.request.body。捕获临时向量的峰值单列，不能把它隐藏进“零内存”主张。应用源lease仍按实际事务完成释放，保持原source_model。
- GPU本地copy快照在实际开始时获取、实际完成写入/解除保护后清空；每GPU串行槽使同时活跃的copy最多一项，单项不能超过其cap。控制timer不占GPU槽或释放任何缓冲。
- 配置及实际pool占用/释放、峰值、未释放持有者、目标缓存、窗口、源lease与本地copy快照分开报告。它们只覆盖所列功能数据内容，元数据、decoder瞬时内存、包、trace和报告副本另属宿主开销，不能称总RSS/HBM上界。
- 延续同一ns-3时钟和QP/反馈状态；实际ACK后的副本回收只保证本功能载体不再访问该副本，不提供对端撤权或GPU可见性保证。未应用旧写仍不得任意覆盖目标区域。

## 验收与预算

最小实际网络覆盖：旧默认完整结果字节相同；足量pool除新报告外相同；单帧pool串行背压后多轮复用；同源跨连接释放唤醒、不同源独立、丢包/NACK/超时重传内容不变；ACK丢失时目标已applied但副本及源lease仍保留；失败源持有空间而健康源继续；相同源pool不足时后续不捕获、不偷发；本地copy完成后快照归零。前端与绕过前端的原生命令必须拒绝类型、cap及不支持组合，在线超额整批无副作用。独立检查重放pool事件、原生包、ACK、源捕获及窗口字节，拒绝早释放、虚假峰值和篡改输出。

只增量重编布局受影响的五个消费者/三入口，复用已锁定对象和八个原生库。每命令60秒/RSS1GiB/地址2GiB/64MiB；阶段累计受监控600秒/新产物256MiB，含失败、构建、归档、恢复及持久副本；目录`/dev/shm/moe-bounded-buffers-20261024/`，tmpfs至少8GiB预留。持久副本另保留根分区64MiB。失败保留，不自动扩限或无变化重跑；不安装下载/GPU/依赖变更，不重跑旧Prefill/千卡失败或旧研究矩阵。平台独立本地提交，不push；论文与整体研究目标仍进行中。
