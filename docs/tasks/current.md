把服务入口中的固定模型、EP4、均匀专家权重及恒等端点映射改为显式配置。根据模型层结构、实际专家放置与每 rank 独立资源预算核算权重及 KV；接纳 ready-KV 请求前预留到最后一次计算输入，实际 UB 完成后继续推进及释放。

## 执行边界与权限

本步新增明确版本的配置服务输入，保留旧服务、P/D、来源索引及多层入口的既有含义。先实现 bias-free GQA/MHA、RMSNorm、门控 FFN 的声明式模型容量，包括稠密层、MoE 路由专家及共享专家、embedding/输出头；不将此结构假定为任意 Hugging Face 模型或目标 R1 的 MLA/量化实现。模型结构或精度未实现时明确拒绝。

模型容量覆盖完整声明模型，执行范围仍为一个 EP 组、一个选定 MoE 层、每 rank 同时一个请求，每轮一个本地 Decode Token。其他层及 embedding/输出头明确列为未执行，不伪造完整模型 ITL/TTFT。跨层执行组合、连续组批及多请求容量等待验收留到 M7/M8；本步验证最终容量拒绝、预留不改变计算进度、结束释放与排队请求随后接纳。

服务中的 rank、专家数、Top-K、非均匀放置及非恒等 UB 映射沿用上一任务规则，后端按配置查实际端点，不将逻辑 rank 用作网络索引。模型的其他层可以有不同静态放置以正确核算权重，不因此执行这些层。容量属于独立 rank 端点，不能以整芯片重复预算。芯片本地性分类、场景 YAML 导入、完整 CM384/R1、CANN 及其他事务模式不在本轮。

允许修改主仓库 `python/moe_ub_cosim/` 的服务与模型容量适配、`backend/cosim_service.cc` 及直接依赖、对应 `tests/`、小型 `fixtures/`、入口与记录文档。不修改子模块、锁文件、gitlink 或技术定义。沿用原生环境，允许审阅后编译和执行必要测试；不安装软件、初始化或升级依赖、下载模型或大数据。

## 实现与验收

- 模型、精度、层范围、注意力/KV 维度和逐层放置显式校验；权重按每 rank 实际专家数加共享权重，KV 不除以 EP。工作区和通信缓冲区计入独立 rank 的预算，并核验通信缓冲区下界与整数范围。
