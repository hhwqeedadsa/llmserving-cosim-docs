## 目标与范围

在已有数据服务中按请求、Token、层读取明确的连续路由。一个解码步生成含多层的每 rank Chakra 图，层间只增加本 rank 前一层末节点到下一层根节点的依赖；不通过逐层全组握手增加屏障。全部层和真实通信完成后，原 Scheduler 才完成一次 Token。所有层和步骤使用同一 ASTRA/UB 进程、网络与仿真时间。

保留单层入口与校验，新增多层计划的原子校验、局部节点映射和运行内唯一身份。各层路由分别导入，禁止复制第一层；省略旧单层 next_layer 占位计算，由实际下一层计算接续，不重复计时。端侧操作仍逐 rank/逐层来自 ASTRA 阶段事件，正式导出沿用 M5.1 的字段与访问边界。

最小主样例使用已核对的 Mixtral 结构和容量、一个四成员 EP 组、三个相邻 MoE 层及三个连续解码步骤；不同请求保留独立索引。使用明确标注的合成路由和逐层参考计算，不下载数据、加载权重或声称真实路由/目标 profile/完整模型时延已校准。进一步覆盖稀疏成员、动态请求及更长层段，只限检查本步连续执行边界。

允许修改根仓库 python/moe_ub_cosim、backend、tests、fixtures 的必要文件及 README、backend/README、环境记录与当前任务。依赖源码、gitlink、锁文件不变，不引入关联算法或新通信模板；如确需依赖修改，先说明原因和范围。新构建使用 build/m5-multilayer，最多八个作业，保留旧产物和原生 launcher 配置；不安装系统软件或修改全局配置。
