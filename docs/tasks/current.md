## 目标与边界

创建最小联合计算执行程序，使用锁定 ASTRA 的 Sys、Workload、HardwareResource 与 Chakra reader，实际执行一个 COMP。通过 AstraNetworkAPI 的 `sim_schedule` 将原完成回调放入 ns-3-UB 的事件队列，`sim_get_time` 读取该队列的绝对纳秒时间。检查起点 0 ns、耗时 1,000 ns、完成 1,000 ns，资源在执行中占用、结束后释放，完成通知仅一次。

锁定 Chakra 的 `duration_micros` 字段名与该分支的实际纳秒语义不一致：读取器原样读取，Workload 按纳秒调度，源码已注明纳秒修改。本轮明确记录此事实，输入使用整数 `duration_ns`，写入时不乘除 1,000；不修改 schema 或技术定义。正的接口相对耗时向上取整，零保持零；拒绝负数、非有限值、错误单位及超出 ns-3 有符号时间范围的输入。

保留 M0 的联合链接探针。只用 ns-3-UB 一套 ns-3，不编入 ASTRA 的其他网络入口或时间队列。关闭 roofline 和全图 replay-only，COMP 使用显式 runtime，经原资源及完成路径执行。未实现的 SEND/RECV 明确报错，不使用固定通信时间代替。

不实现 UB 收发、请求调度、专家路由、连续图控制协议、CCL 或正式观测导出。固定耗时仅是功能输入，不是目标硬件校准数据。M1.2 及后续任务不得自动开始。
