## 目标与依据

依据 v0.3 第 3、4.1、5、6 节及 v0.2 第 4.3 至 4.6、5、7、9、10 节，将 Token 到目标 rank 的贡献明确分为同 rank、同芯片不同 rank、跨芯片。前两类不创建 UB fabric 事务；所有专家输入、Combine 贡献及生产者到消费者依赖保留。每个 rank 继续独立占用计算与容量资源。

## 执行范围与权限

同芯片跨 rank 通过源 rank 的本地准备计算及独立的本地交付完成回调推进，不创建 WQE、不模拟 die 间链路或协议，也不伪造 UB WriteCommitted/TransactionDone。本地交付沿用 ASTRA SEND/RECV 节点表示跨 rank 依赖，使用现有发送槽发起限制；计算准备占用源 rank 的唯一计算槽。跨芯片保持真实 UB WRITE/RTP 事务。

覆盖单层、固定两轮及上一项配置服务入口；本轮不扩展旧来源索引、P/D、跨层组合的输入含义。部署在运行中固定；配置服务仍是一组、一层、每 rank 同时一个请求。场景 YAML 适配、MLA/R1、连续批处理及校准不在本步。

允许修改主仓库 `python/moe_ub_cosim/`、`backend/` 的本地性交付及直接依赖、对应 `tests/`、小型 `fixtures/`、已可用入口和任务/环境记录。不得修改子模块、锁文件、gitlink 或技术定义。不安装软件、初始化或升级依赖、下载模型或大数据。
