## 目标与依据

依据 v0.3 第 3、4.1～4.5、4.7、5、6 节及继承的 v0.2 第 4.5、5、7～10、11.1 节，把 M7 多请求批次用于显式配置的连续 MoE 层段及多个不重叠 EP 组。每组在同一套持续存在的 UB 网络中独立推进，完整层段结束后才回报一次批次完成；层间只加 rank 本地依赖，不加全组逐层或组间逐轮屏障。

## 范围与权限

使用明确版本的组合服务与层段输入，保留旧服务/单层/多层 schema 的原行为。各组声明模型、容量、调度预算、成员、端点映射和逐层静态放置；本轮限相同模型结构与所选层段，允许各组放置、容量及批次预算不同，不建设任意异构模型服务系统。所选连续层段须为已有 MoE 执行类型；稠密层等仍保留完整容量核算和明确未执行清单，不伪装成 MoE，不声称完整模型 ITL/TTFT。

复用原生 Scheduler 的选择/逐请求完成和唯一 KV 块池；一次选批在本轮各层保持成员与 Token 位置相同，逐请求逐层消费自己的路由。按完整模型逐层放置核算权重与 KV，通信缓冲覆盖层间可能重叠的在途输入。保留 M6 的本地性及 WRITE/RTP 场景参数和 M7 的上下文/逐专家形状、等待/释放规则。每 rank 一张活动图和一个计算槽，跨芯片时间由本次 UB 完成事件产生。

允许修改主仓库 python/moe_ub_cosim 的配置服务、组合计划、容量、场景与直接相关输出，以及 backend 的计划/部署校验和相关直接依赖、小型 fixtures、单元/集成检查、入口/环境/任务文档。锁定子模块只读，不改源码、gitlink、锁文件或技术规范；不安装软件、不改全局配置、不初始化升级依赖、不下载模型或大型数据。

真实路由/profile 属于 M9，CANN/新事务模式和目标规模属 M10。本轮不增加多层 P/D、抢占、重算、swap、混合 prefill/decode、中途迁移或完整 CM384/R1 场景。
