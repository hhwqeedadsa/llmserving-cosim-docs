# 依赖驱动的前端唤醒：先做离线判别

平台前置能力，基线 `cec7313`。上一轮现代接入有实际进展，但四请求完整调用在 256 次宿主交互处失败，原阶段四次网络预算已经关闭。本阶段不重跑网络，不提高交互上限，不将离线回放写成网络验收。

先用已保存的正常、丢包及四请求失败前缀，检验以下方案：前端声明“任意一组已提交工作回调全部发生时唤醒”，原生端仍保存每条回调及其实际时刻；排空、首次交互和控制闹钟必须唤醒。每组条件只能引用已提交的工作，不能预测未来完成或删除必要操作。

条件来自当前真实的应用依赖，包括 Dispatch 同 token 全部 slot 分配、动态 Combine 通道顺序、计数源准备及本地完成；只看静态计划或 `ready()` 不够。区分两种候选：推进任一现代事件，或推进下一项原生任务提交。后者可能推迟纯前端记账，必须单独量化，不能把它称为完全保持原执行。

离线核验逐轮重建前端，首先对照原记录确认原控制器生成的全部提交内容、批次、顺序、提交时刻及完整现代日志相同。再按条件积累原回调，唤醒时一次交付全部积累项，核对全部提交及完成语义；任何遗漏、提前或推迟提交、批次及顺序变化都保留为反例。原来的四请求记录只有失败前缀，不能据此外推剩余调用或声称已通过。必须说明同纳秒 ns-3 调度顺序尚不能由离线记录证明。

本阶段交付可重复的离线工具、必要的只读依赖接口、最小功能测试、三份原记录的哈希和判别报告。只有证据支持后才另行登记 native 接口实现、增量编译和实际网络验收；本阶段不做研究收益实验，不声称论文创新。

运行目录 `/dev/shm/moe-dependency-wakeup-20261024/`，最多 240 受监控秒、96 MiB 新增存储，含阶段目录、版本化新增代码/证据及 1 MiB 最终收据预留。每条检查最多 60 秒、RSS 1 GiB、地址空间 2 GiB、阶段产物 32 MiB；保留失败，不自动扩限或重跑成功检查。tmpfs 预留 8 GiB，根盘预留 64 MiB。只读原阶段记录，不复制大型包；不构建、不运行网络或 GPU、不安装下载、不改子模块、不 push。原有 256 次上限保持不变。
