# 原生显式修复段执行

目标：在现有独立Scale-Out RDMA共享网络内执行上轮规划的无环段，补足原ECMP候选为空时的成熟绕路基线。属于通用功能，不将常规封装/绕路称为论文创新；真实MoE收益须另立研究方法。

公开协议增加`local_failover: {"mode":"explicit_prefix/1","max_events":100000}`；限单个交换机边故障、单plane0、单NIC、128/256/512端点Clos。默认与live_ecmp/1保持。仅故障两端根据本端物理坏出口激活预先计算的静态段，原候选仍存活时保持原顺序/哈希；远端不提前改路。普通LFA或安全合流段由旧图严格检查；中间节点只能依据实际包携带的段转发。

使用项目定义的实验IPv4封装（项目内协议号250，非IANA标准或RoCE线上标准、MPLS/TI-LFA）。封装包含完整原包、版本/段/游标，并通过原生SwitchNode、MMU、优先级队列和Qbb链路，真实增加GetSize与串行化开销。合流交换机拆封并将外层CE传到内层。原始RDMA序号、选择性重传、ACK/SACK和应用门限/资源释放不变；不复活已丢包，不重置QP，不以接收代确认。封装不能递归、GPU不能中转，段长最多16跳。协议号不与固定后端ACK/NACK/CNP/PFC冲突。

观测同时保留内层流身份/有效字节与实际线上尺寸，逐转发记录包UID、节点、动作、物理出口、段游标、封装长度及原始目的；完整性单独报告。已有逐包格式保留，新增修复元数据说明外层协议与开销，独立核验物理TX/RX、包尺寸、路径、有效字节和原ACK。控制面延迟仍由已有显式日程给定，本地检测/封装处理暂不另建硬件成本；不能宣称生产性能或完整现代RoCE支持。

验收：CPU算法/序列化/非法输入检查；独立公开128Clos功能例，不依赖真实数据或旧测试驱动。一次全新公开完整构建；最多六个网络各一次：旧/新默认正常、旧live故障、新显式故障、链路提前恢复、零延迟全局更新。覆盖DATA和ACK、在途修复段及持续QP，正常默认记录除库路径外一致。失败保留，不扩预算或按结果调参；确认功能后再执行真实MoE研究。
