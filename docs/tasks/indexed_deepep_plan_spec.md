# 完整低延迟计划的流式索引格式

服务对象是固定DeepEP v1.2.1、计算流等待/no-hook、单NIC、RDMA-only的完整操作计划。EP32/E256、4 token/Top8一轮有16,448操作和66,144事件；旧flat格式16,384操作/65,536事件上限保持不变。新格式解决表示和检查开销，不新增网络、GPU、WQE执行或性能模型。

公开`deepep-plan --format indexed-jsonl`显式选择新输入schema，默认仍为flat。`deepep-check`按保存清单分派。新输入沿用模型、执行、调用的所有旧约束；limits改为`max_logical_events/max_logical_operations/max_index_bytes/max_input_bytes/max_output_bytes`。逻辑上限由已有最大维度（4 calls、32 ranks、256 experts、每rank16 token、Top8）推导为394,624事件/98,304操作，索引内存最高64MiB、输入1MiB、累计输出16MiB，单行64KiB。逻辑数量不等于内存占用；满维度输入仍可能因输出或索引预算拒绝。

事件/操作采用带列定义的JSON数组行，依赖及操作事件使用从0开始的索引；保留原始事件ID、操作ID和所有属性。逐项生成，不保存完整事件/操作数组；索引只保留事件ID到序号，闭包每事件一个字节。依赖严格指向更早事件，故一次拓扑扫描可得到与旧图广搜相同的暂扣闭包。声明索引预算核算Python映射、键、序号及闭包的浅层大小，不等于全部进程RSS；外层RSS预算另行限制。阶段矩阵、前一QP通知及数据关系仍在生成时保留，不能称常数内存。

写前执行计数、hash和输出预算预检；正式写入重新流式生成并核对，目录已存在不得覆盖。检查器从原输入重生成，每次只读取一行比较，核对全部原件hash、行数、依赖及清单；不把重生成称独立语义验证。暂扣未知ID拒绝、不写成功结果。没有删除零通知、推断物理QP、制造CQ/ACK或承诺源缓冲可释放。

验收：旧格式产物与改动前相同；在支持的多rank/多call/空rank/BF16/FP8输入上逐项反解等价，独立闭包核对数据、零count、flag和sender_done暂扣；EP32完整计划独立枚举全部操作及事件数、全完成与暂扣传播；拒绝逻辑/索引/输出/单行超限、重复JSON key、未知ID、重新计算hash后的内容篡改、尾部额外行及路径覆写。新目录公开CLI不读取旧runs/fixture，记录资源和失败；旧CLI完整流程回归。
