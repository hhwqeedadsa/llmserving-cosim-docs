# 失败源隔离后释放本地复制副本

基线`ac413a3`。前轮完成可选终态缓冲快照，属于实质进展。本轮针对有限复制池的局部故障隔离，不做论文收益矩阵，不新增物理故障或放宽远端写入顺序。

当前复制型事务将注册源字节复制到`Work.payload`，原生`Packet(buffer,size)`又复制到包内；失败源已移出NIC调度并取消发包/重传计时器，但仍永久持有重传副本。若该GPU的共享池只容一帧，其他健康连接也不能发布。需要显式建模本地复制副本可回收的时刻，避免把这种保留当成不可消除的网络损失。

## 可选语义

`buffer_model`可选`on_source_isolation="release_copied_payload/1"`，只接受既有transactions/4复制型source-window put、显式`transport_recovery.on_exhausted=isolate_stream`。不提供布尔开关或其他模式，缺省行为及结果保持。

源端真实重试耗尽后，必须先冻结该源、从NIC集合移除QP、取消源计时器；随后清空该stream中仍持有的所有真实payload vector，按工作记录归还源池，每项写`discarded_on_source_isolation`事件。没有ACK、工作完成、队列信用、源窗口lease或目标缓存释放。原生包保持独立字节，仍可在失败后到达并产生原有目标副作用。目标不查源失败状态，不撤回旧写，不复用其地址。

此模式下失败stream后续工作不得再捕获/消耗副本池；保持原应用操作待发布和lease保护。健康连接依赖真实池归还继续，不增加软件时钟或模拟完成。报告明确副本丢弃时刻与未完成/未确认状态；原有`failed_resources_released=false`仍表示没有整体回收。

## 验收

1. 旧/新默认完整结果逐字节相同；健康开启条件的原网络行为保持。
2. 一帧共享池、同GPU两连接：旧连接ACK丢失或数据丢失后隔离，健康连接已就绪但先被池阻塞；开启后真实发布/完成，默认仍阻塞，失败lease/ACK/目标语义保持。不是论文速度收益对照。
3. 短RTO功能条件：失败前已发出的原包在释放后仍到达并应用，证明副本回收不伪造远端撤回；失败后无源TX/复活，源lease仍在。
4. 连续健康复用、失败stream后续操作不捕获；CLI/native非法policy/不支持组合拒绝；在线会话整批校验及受影响stream/事务回归。
5. 独立重放真实池事件、源包内容、失败/ACK时刻、目标窗口；拒绝提前丢弃、伪造确认和丢包内容篡改。公开可运行小例及离线检查点。

这是当前功能复制载体的生命周期修正，不是GPU DMA、现代GIN的内存注册/撤权保证，也不是新的恢复算法。目标退出、去重缓存、源窗口释放及代表性MoE研究仍是独立未完成事项。
