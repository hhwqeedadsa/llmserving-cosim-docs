# 完整旧低延迟计划的原生执行

本轮从已验证索引计划连接到同一原生ns-3网络，保留全部逐专家数据、零token count/flag、自rank操作及跨调用双buffer清理。不是现代GIN或CUDA性能实现。源输入仍为固定DeepEP v1.2.1的RDMA-only、单NIC、无hook/compute-stream-wait模型；真实路由研究另行执行。本轮不以删通知、合并不同专家QP或缩EP代替完整执行。

专用入口接收已验证indexed计划、显式rank→物理GPU/NIC映射、队列深度和单静态注册跨度。复用PersistentStreams、RemoteMemory与LowLatencyPostingQueue；现有小型事务入口的连接/窗口上限不扩大。EP32/E256逻辑跨rank上下文7936，请求及功能回复双流共15872；新入口据此显式支持至16384流及既有65536工作，SR记录至500000。已有通用公开stream/transaction校验上限保持，缺省行为不变；这是新功能维度要求，不是失败后扩预算。

补充准入要求：每个远端请求与反向原子回复按工作边界独立分包，每次实际源发送均占一条参考拥塞控制日志。Python及直接原生入口须在Fabric创建前检查这个无重传下界；不能把必要检查称为全部恢复/拥塞日志容量保证。原示例继承10,000条记录，本轮完整计划必需32,464条，首次网络因此失败。失败保留，不自动修改配置；用户已明确授权适度提高限额，采用100,000条记录的新显式分配，其他原预算保持，使用新目录保留原失败。

公开`--validate-only`复用执行入口的全部Python与源计划检查，在调用原生后端前返回，仅保存拟执行输入、命令及显式未运行摘要。不豁免容量或损坏计划，不生成完成结果；必须区分Python检查通过、原生准入通过和完整网络完成。待确认配置可在独立目录准备并检查，不激活、不改写原失败输入，不作为预算变更或重跑批准。

远端issued由真实依赖和槽可用后完成同步发布调用；每第四个put的调用方message index或通知推动前缀发布，未发布工作不能进入载体。远端accepted来自实际请求字节目标应用；visible仅显式零成本功能内存可见，不是GPU一致性。远端sender_done须实际请求ACK、原子旧值回复及本QP前序退休。目的端只从收到的地址/值修改内存。局部操作不发网络包，由本地copy/store应用推进accepted及sender_done；专家阶段只对收到的数据作声明的功能拷贝，不是数值专家。

远端队列深度须容纳规范单WQE顺序中的下一个发布跨度，Python和原生均在Fabric前检查；未发布工作不可能通过ACK释放槽位，不能靠超时等待掩盖这类自等待。本地copy/store按固定源码直接执行，不进入远端队列，不产生票据、发布或网络ACK；其上述输出时间为−1、返回值为null。远端原子返回值只有实际反向流回复到源后才可填写，目标内存应用不替代源反馈。旧失败记录中的本地队列/ACK字段属于修复前行为，不按新语义重新解释。816种CPU队列情形只能证明相应核心行为，不替代完整网络验收。

控制事件按原DAG推进。目标通知按对应4B槽读取，清理只在本rank既有clean_next事件发生；同一上下文跨Dispatch/Combine/call持久存在。实际内存、回复和实际源回调分别核对，不从离线闭包制造通信完成。每个context独立注册一个不重叠窗口，数据put在该单跨度内为一条WQE；跨key拆分不是本入口隐含能力。源捕获副本保留至实际退休，不能据此宣称GPU源buffer寿命/硬件provider已验证。
