# 完整旧库通信的共享网络执行

## 目的与边界

为检验局部恢复是否干扰其他MoE任务，先支持两个独立完整旧DeepEP v1.2.1 BF16组共用一套原生ns-3 Fabric、时钟、交换机和可靠传输控制器。各组保留原EP/专家数、全部数据与零token通知、发送发布、32位目标窗口、实际ACK/回复、源退休与清理；禁止把单组改成双倍EP或拼接独立运行时间。

这是平台增量，不预设多任务一定有显著收益，不实现新恢复算法。实际网络仍选128端点Clos；功能检查可用该网络上的小EP，不代表128卡满载。原单组接口及限制保留；无现代GIN、RoCE线协议、GPU/数值专家或服务调度性能主张。

## 输入与资源

新增公开`scaleout deepep-shared-run --config CONFIG --topology DIR --protocol JSON --transport JSON --backend LEGACY_EXECUTABLE --output NEW [--validate-only]`。CONFIG采用`moe-legacy-shared-input/1`，groups包含1或2组，各有唯一id、完整索引plan目录及binding文件，路径相对CONFIG所在目录解析。绑定的GPU必须组内、组间均不重复。单组维度和准入沿用原接口；整个输入核验全部源计划，任何失败拒绝整体。

原生输入采用`moe-legacy-shared-execution/1`，每组保存原执行数组，不改变逻辑rank、专家或局部事件索引。按组顺序分配连续、互不交叠的全局stream区间和全局work ID；这些标签仅用于传输匹配，不改变包优先级或定时。每组独立窗口、事件队列和功能专家状态，一个PersistentStreams拥有全部网卡回调。只在所有组的操作、源退休及整个网络排空后关闭共享传输和Simulator；同时保留各组实际kernel完成时刻。

共享总上限65,536操作、280,000事件、32,768有向流、65,536请求/回复工作、2,000,000逐跳观测、64MiB源包载体捕获；wire port从20,000开始并检查16位边界。SR事件仍最多500,000。新共享驱动允许显式最多200,000条参考日志，以容纳双组；原单组及通用公开入口仍最多100,000。这是经用户允许适度提高限额后的独立有界容量，不删除通知来降低工作量。

单次CLI仍限120秒、RSS2GiB、地址4GiB、结果256MiB；共享结果超过预算应失败，不截断作为成功。本轮实现根`runs/legacy_shared_20261031`：累计1800受监控秒、2GiB新增产物、卷留8GiB；构建外层900秒/内层600秒/RSS2GiB/地址4GiB，其他阶段120秒/相同内存。无安装、下载、依赖升级或GPU；失败保留，不自动扩限或重跑成功网络。

## 验收

公开只读`deepep-shared-audit`核对全局逐包传输与组区间覆盖，并逐组复用原完整DAG、内存、32位通知、源退休与排空审计。审计的组投影仅过滤/重标识实际记录，不能把未完成组投影成完成；保存共享全局执行身份与物理完成时刻，不声称独立隔离收益。

先CPU验证输入、容量及非法重叠、ID/路径/界限，再用全新目录完成最多四个128Clos功能网络：共享单组正常、共享双组正常、共享双组一次精确通知丢包、原单组接口回归。功能数据为显式人工输入，所有组完整调用，故障仅一次而非持续黑洞。核查共享单组与原单组的执行/传输一致，双组同时就绪且各自状态独立，坏包恢复不重复应用，全部源捕获与网络排空；篡改全局stream/组映射/完成状态等应拒绝。

保存平台源码与验收后，仅发布已有授权的user分支，不发布origin。本轮不自动执行EP32双组真实数据研究；该研究先独立固定来源划分、共享/直接故障路径、竞争解释与强基线，平台成功不等于研究成功。

## 2026-10-31 用户授权后的宿主容量修订

共享入口可显式配置至180秒、RSS3GiB、地址6GiB、结果512MiB；共享审计同步512MiB读取上限。配置不自动提升，原单组上限不变。只改变宿主停止条件及结果读取容量，不改变C++、记录条数、模拟网络与通信语义；原实现轮的预算与实际资源仍按上文历史记录。后续实验需独立声明累计预算。
