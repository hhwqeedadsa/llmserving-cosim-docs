# 单边故障的无环备用与显式修复规划

目标：为已有128Clos共享上行ACK故障补强现成改路基线。先核对普通LFA（Loop-Free Alternate，无环备用下一跳）能否覆盖唯一坏出口，再规划必要的显式修复段，避免把邻居按旧表送回来的包当成成功绕路。本轮交付静态公开规划与独立核验，不将计划路径当已执行网络收益；后续原生接入仍待完成。

## 公开接口和语义

`scaleout repair-plan --topology DIR --src SWITCH --dst SWITCH --output NEW_DIR`读取生成的物理图，保护一条实际双向交换机边。限单plane、每GPU单个实际NIC、128/256/512端点、最多256交换机/16384边；只计算故障边两端至各GPU的覆盖，所有边使用与原生一致的hop计数，其他GPU不得作中转。拓扑/参数全部验证后才创建输出。不读取包路径、路由原件、故障持续时间或未来恢复结果，不改变平台选路。

1. 计算故障前所有等价下一跳。剔除本端已知的坏出口；仍有活候选则沿用，不重排现有出口。
2. 若原候选全失效，按RFC5286严格条件`D(N,D) < D(N,S)+D(S,D)`检查同plane交换机邻居N。使用故障前图，禁止在计算邻居旧行为时偷看失效后的全局图；比较不能写为小于等于。这是链路保护，不宣称节点故障保护。
3. 普通LFA不覆盖时，规划已删除本条边的最短简单路径，按节点/端口顺序固定选择；找到首个“其旧最短路均不会回到保护点S、也不经过坏边”的合流点Q，在Q以前形成显式修复段。Q之后恢复旧转发图。验证每个可能的旧ECMP后继均安全，不只选择一条有利后缀。无安全合流点或无剩余路径则如实报告。
4. 显式段是需要后续逐跳携带/执行的规划，不是“重新设置两个端点路由”就能完成。输出明确计划边、合流点、正常及故障图hop距离、普通LFA的候选/失败不等式和状态。不得把它称为完整RFC7490或TI-LFA实现，不假定零线速字节或零控制开销。

输出plan.json、summary.json及输入hash；状态为planned_not_executed。示例独立生成128Clos输入，不依赖历史运行或真实路由账户。指南/命令帮助/架构/输出说明与实际能力一致。没有新增ns-3模式或修改第三方依赖。

## 验收和资源

- 单元覆盖严格不等式、原ECMP存活、普通LFA可用、无LFA但显式修复可用、真正分区、GPU不能中转及非法规模/多NIC/跨plane/非实际边。小图仅CPU算法检查，不是新网络运行。
- 公开命令在独立128Clos输入上执行；独立检查器用另一种距离算法、旧转发表闭包及删边后路径核验全部256个端点/目的组合和所有显式段，不导入规划实现。
- 保留已有后端/协议默认行为，无构建/安装/大数据下载/GPU/新网络。最多300受监控秒/128MiB产物/卷留8GiB；每阶段60秒/RSS512MiB/地址1GiB。研究解释与平台功能分别交付，整体目标active。

后续原生修复路径必须真实经过队列/链路、保留QP和原ACK，显式修复段需要计入线上头部与序列化/MMU开销；只能本端故障激活，远端不得凭全局物理真值提前更新。没有完成这些要求前，不声称修复收益。
