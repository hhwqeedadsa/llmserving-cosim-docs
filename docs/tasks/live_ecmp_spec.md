# 本地失效端口的等价下一跳剔除

平台阶段，基线`7077530`。上一目标轮完成四条件研究与独立复算，属于实质进展；当前从干净工作树和原始包复核出：声明4–16us的路由滞后期间，63个数据包及1个ACK的本地转发丢弃来自旧表选择已断端口，另9次是关闭时清队列、3次是物理到达丢失。本地QbbDrop绑定入口端口，不可按其port字段直接称失效出口。本阶段补经典强基线，不开发论文算法、不开展应用收益实验。

## 行为与边界

公开RDMA协议可选`local_failover: {mode: live_ecmp/1}`，必须显式配置`link_failures`。缺省完全保持旧行为；不自动改变已登记研究。native/Python在分配网络前拒绝未知模式、额外字段、空值、错误类型及无故障日程。

故障实际发生后，只在该边两端交换机，将旧全局路由表已有的候选中、该交换机本地`IsLinkUp=false`的端口剔除。下一跳顺序不变，继续原生五元组/ECMP hash；若没有活的候选，则该目的在本交换机无路由，仍本地丢弃。不得增加非原候选的绕行路，不改变其他交换机的表、主机QP、包标识、速率或重试机制，不提前通知源GPU。

全局收敛仍只排除本次已到期故障；如果另一已发生故障还未全局收敛，重新建表必须保留那个交换机本地的失效剔除，但不能让远端全局表提前知道它。只依赖已实际发生的本地link状态，不读取未来日程。候选缓存不在缺省模式分配，不更改ns-3或依赖版本。

该模式是理想立即本地响应参考：从TakeDown事件到本地表调整没有额外模拟耗时；不代表实测检测、ASIC编程、FRR/LFA、分布式控制收敛或现代GIN校准。不将其收益当创新。保留在途/清队列丢失与必要恢复；不能取消已丢包。

仅显式模式新增`link_failures.local_failover`，含配置、边界说明和每次本地调整的time/node/触发事件/被移除候选/安装候选/空目的数。全局route_epoch、pending事件和原events缺省格式不变。独立核验按拓扑BFS（仅使用届时全局已知故障）和本地已发生link状态核算候选；比较记录不能替代真实包。对全节点捕获核对失效端口不再物理发送、后续源包沿存活既有等价路转发、旧单候选被删时仍丢弃、队列/物理收发/实际接收ACK及排空。
