# 可选交换机终态缓冲快照

平台基线 `311c427`。由原生关闭探针暴露的队列/MMU不一致驱动，新增诊断能力，不加入物理链路故障、恢复算法或占用清零。

协议可选 `mmu_snapshot={"nodes":[8,9],"max_ports":128}`。显式选择1—16个不同交换机，每个交换机必须存在且有物理端口；总物理端口数不超过声明预算1—1024。Python共用验证及原生构造器都在网络分配前拒绝非法选择、类型、未知字段或预算不足，禁止静默截断。GPU、布尔节点、重复节点、空选择均拒绝。

只在原有 `Fabric::Report` 时刻读取所选交换机的全部物理端口；不增加模拟事件、定时器、回调、随机数或改变包/路由。输出每端口8优先级的入口、headroom、出口MMU、实际BEgressQueue字节和MMU PFC状态；附共享占用、reserve、真实时间、完整选择范围和link状态。控制队列0不参加MMU守恒，序列化中及在途字节也不属于队列。终态一致不证明历史从未不一致，不证明网络排空或硬件准确。

`rdma-diagnose`仅在快照存在时增加离线诊断：q1—7逐端口出口与实际队列相等、逐优先级入口+headroom与出口总和相等、共享占用与sum(max(ingress-reserve,0))相等。异常明确输出节点/端口/优先级及两侧计数，不更改仿真passed。未选交换机不作判断；三种计数不可相加成实际内存。旧配置的完整结果/诊断保持原值。

验收：边界单元；旧/新关闭/新开启的公开小网络完整执行字段对照；有效非空队列终态及正常排空分别诊断；从真实快照有意篡改验证异常检测，不能冒充实际链路故障；绕过CLI的原生非法输入；事务入口受影响回归；独立包级队列重建及空cwd离线复算。原有失败研究不重跑。

资源：独立目录 `/dev/shm/moe-mmu-snapshot-20261024/`；每命令60秒、RSS1GiB/地址2GiB、产物64MiB；网络仿真最多5ms/终态16MiB。新产物累计192MiB、受监控450秒（含失败、持久保存、离线复核），tmpfs8GiB/根盘64MiB预留。不安装下载、不改固定依赖/GPU、不抬限重试。仅增量编译Fabric及小probe，重用身份核验后的固定对象/八库；按实际受影响对象链接，不全量构建。平台与研究独立本地提交，不push。
