# 按调用与rank声明专家阶段成本

2026-10-27，平台起点`8c06c79`。上一轮EP网络投影改变了后续判断，属于实质进展。本轮补平台输入，不执行新的研究收益实验，不把profile接口或声明成本当作论文创新。

## 问题与支持范围

当前`expert_stage_done`对所有调用和rank都使用同一个`costs.expert_ns`，因此原始路由中的专家负载差异不能通过计算就绪时间反馈到网络。新增公开输入`moe-modern-native-input/2`，必须显式填写`expert_stage={mode:per_call_rank_declared_ns/1,durations_ns:[[...]],source:...}`。外层索引对应`modern.calls`的输入顺序，内层索引为逻辑rank；必须完整覆盖，纳秒为0到原协议仿真期限内的整数。`source`为非空有界说明，只记录假设来源，不接受隐式预测、未来网络真值或硬件校准标签。

v2的`costs`只含`source_prepare_ns/reduction_ns/local_copy_ns`，不含`expert_ns`，避免两种来源的覆盖顺序。v1字段、默认行为及输出保持；不允许把v2字段塞入v1。每个专家阶段仍在实际Dispatch完成后提交到同一原生会话的每GPU串行lane，以实际local_started加声明duration结束，并以真实completed回调推进现代事件。矩阵不是绝对通信时刻，不改变任何屏障、计数、slot、连接、源保护或网络恢复语义。

v2快照增加完整`expert_stage`说明；`hardware_calibrated/numeric_expert_computation/gpu_visibility_modeled`继续为false。不自动由GPU名称、专家数或token数生成成本；本轮不加入未经测量的专家调度、SM并行、填充或真实GPU kernel模型。新的profile生成器和研究对照需另定输入/强基线。

## 验收与停止条件

- 单元检查固定模式兼容、矩阵隔离、完整覆盖、非法类型/负数/超期限、未知字段、两成本源混用拒绝，以及没有真实回调不产生专家完成。
- 提供独立于真实数据、旧运行目录的小例及公开命令，更新使用/字段说明。
- 固定最多4次新网络：v1固定成本、v2等值矩阵、v2跨调用/跨rank异值矩阵、复制源码与固定运行时/空cwd的异值迁移。前两条件实际网络result（仅允许运行库根路径变化）、完整control及现代事件相等；v2新增说明字段单列。
- 异值条件逐专家节点独立核对实际local_started、completed、duration、对应现代事件与前驱，全部后继不能提前；同时独立核对原始操作、MRT1负载、计数、自发操作、窗口/源保护/消费清零和应用完成。不能只断言最终时延改变。
- 拒绝对duration、实际完成时刻、前驱、成本来源的篡改；至少6类非法输入经公开入口在创建运行目录/启动后端前拒绝。所有原输入及固定session/8库身份核对。
- 每个网络条件执行后核验再推进；任一网络、语义或预算失败保留原因并关闭剩余额度，不自动重跑、提高限额或减少必要操作。迁移前先逐成员hash归档恢复并离线重算；恢复比较只允许库根目录位置改变，不删除执行字段。
