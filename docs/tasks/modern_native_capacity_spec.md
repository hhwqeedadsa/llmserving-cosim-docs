# 现代原生入口的完整工作量容量检查

目标是推进同一128端点Clos上的真实EP32连续两调用，不把计划保存成功当作原生执行成功。当前入口限制散落于现代布局、控制器、事务和会话，部分完整调用直到执行中才触发远端/本地操作额度。先交付完整调用的静态容量核算和启动前拒绝，再按明确需求扩展执行能力。

本平台增量提供公开`scaleout modern-deepep-native-capacity --config MODERN.json --output NEW.json`。输入沿用现代计划的完整配置，不要求后端、GPU或拓扑，不运行回调。枚举全部操作、必要本地工作、按实际/所有可能slot绑定的连接身份，以及不可变输入的稀疏初始化；保留self、零值计数、屏障及跨调用控制。列出当前静态容量逐项需求与上限，并说明未检查的物理部署、动态前驱宽度、回调/控制交互、记录容量和宿主运行资源。通过只表示所列静态条件满足，不等于执行准入或成功；超限保存报告且退出1，非法输入不产生成功报告，拒绝覆盖已有结果。

布局准入在启动后端前核对完整调用的确定性远端/本地节点数量，而非等执行途中才失败。复用同一连接枚举函数，现有合格输入的连接顺序、编号、计划字节、成本及网络时序不变。此项不提高任何预算、不改C++/依赖、不进行新网络，不将预检能力称为算法或时延收益。

验收用独立手算及合成完成回调的控制器闭包核对实际节点数和初始化字节；回调是功能测试声明，不能作为网络证据。覆盖动态slot可能连接、self和零token、超限完整计划在启动前拒绝、非法输入及覆盖拒绝。公开CLI在新目录完成正例、容量反例及重复复现；不依赖历史runs或研究驱动。平台验收与真实两组配置容量研究分开提交。

平台预算根`runs/modern_native_capacity_20261031`：累计600受监控秒、256MiB新增产物、卷留8GiB，每阶段120秒/RSS1GiB/地址2GiB；最多五阶段，不自动重跑失败或提高限额。真实配置研究另立方法和预算。此增量完成后，EP32网络能力仍待按逐项需求实施与验收，整体目标保持active。
