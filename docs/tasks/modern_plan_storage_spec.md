# 现代操作计划的有界压缩存储

目标是让合法的现代direct EP32两调用计划通过公开保存/检查入口，不改变通信语义或旧默认输出。真实容量诊断中两组分别12,508/12,478操作、51,308/51,154事件，在原逻辑上限内，但约21.8MB明文超过16MiB保存上限。压缩后约1MB；这是表示瓶颈，不是网络执行证据。

新增显式`modern-deepep-plan --format compressed-json`，默认`flat`保持schema、字段和逐字节输出。新格式以标准zlib压缩同一规范JSON，保存`plan.json.zlib`，manifest/3记录固定文件名、编码、压缩文件字节数/hash及原规范计划字节数/hash。input原样保存。原计划的全部ID、依赖顺序、屏障、零计数、self-peer、符号slot和scope不变；物理存储顺序不成为调度顺序。

原逻辑上限65,536事件/16,384操作、输入1MiB、总保存产物16MiB不变；新格式独立限制解压后规范JSON64MiB。仅新格式允许此展开容量，旧flat读写仍16MiB。编译时先检查展开界再压缩，检查时有界解压，拒绝截断、多流/尾部、超展开界、不符长度/hash及非法文件名，不从manifest任意路径读取。

`modern-deepep-check`先读取清单自动识别格式，验证存储与展开身份，再逐字节对照同一编译器、检查闭包。检查结果语义与flat相同；未解析动态slot，也不证明GPU、GIN或原生网络完成。现代native仍消费原输入配置，本增量不改变其同步次数、逻辑节点或运行期预算。

验收：独立新目录公开流程，默认flat与改动前原件相同，解压后与flat规范计划相同；压缩检查与flat同一暂扣事件的闭包相同。按重算hash后的截断、尾部、多流、超展开容量、路径/编码/声明长度、规范内容篡改及未知格式拒绝。格式不能通过截断或省略操作满足预算。真实两调用研究在平台验收提交后单独使用，不以其收益作为功能通过条件。

预算根`runs/modern_plan_storage_20261031`：累计300受监控秒/256MiB新增/卷留8GiB，单阶段120秒/RSS1GiB/地址2GiB。只用Python标准库，不构建、下载、安装、改依赖、执行GPU或新网络；失败保留，不自动扩限。平台和研究分开提交与验收。
