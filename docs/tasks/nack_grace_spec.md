# 基于实际NACK的有界乱序等待

平台阶段，基线`474d4e7`。上一目标轮为清理授权核对，未改变研究证据；本轮重新核对干净主仓库和子模块后，继续当前任务指定的经典强基线。它用于排除“已知乱序触发过早重传”这一竞争解释，不是论文创新或RACK/IRN复现。平台验证完成后才能另立研究协议比较应用收益。

## 接口和因果边界

`transport_recovery`的`selective_repeat/1`可选`reordering: {mode: nack_grace/1, wait_ns: W, max_events: N}`。三个字段严格匹配，W为1至initial_rto_ns的整数，N为1至100000的整数；拒绝bool、其他模式、额外字段及go_back_n模式。Python和三个native入口在创建Fabric前校验此新增字段；构造器再次检查。省略字段保持完整默认结果。

每条持久连接只维护一个等待事件。只依据源实际收到的累计ACK/NACK和源时钟：同一当前缺口的第一个NACK启动固定W等待，重复NACK不延长；旧前缀NACK不触发。累计确认推进取消旧等待，并允许新缺口的实际NACK启动新等待；单纯ACK推进不凭空推断缺口。到期核对源累计前缀且仍有未确认已发字节，才调用既有RecoverQueue及SACK跳过逻辑、Pump，不造反馈、不读接收端或未来路由。

同一前缀至多一次等待重传。RTO始终独立工作，触发时取消等待并将该前缀标为已恢复，之后同前缀NACK不能再次启动等待；累计进度可重新允许。若等待到期与RTO同一ns且源RTO已到期，等待让位给RTO，避免同刻重复恢复。先执行的真实ACK依原生ns-3 FIFO顺序取消定时器。RTO退避、重试上限和流隔离均不更改。Close、析构、单流耗尽或全局停止取消相关等待；未结束的时间预算结果保留pending状态。最多一timer/连接，事件有硬上限，超额报错，不丢弃日志继续执行。
