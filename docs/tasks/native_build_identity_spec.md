# 原生Scale-Out构建的固定版本一致性

2026-10-27，起点`b27f008`。平台修复，与研究收益实验分开验收、提交；不涉及新网络算法。

## 发现与目标

为多NIC支持检查构建路径时发现：`scaleout_rdma.py`仍将原生ns-3固定为`6088174`，而父gitlink和`deps.lock.json`已共同锁定`68a07f7`。当前干净、正确的依赖检出会被公开`scaleout rdma-build`误拒绝；普通probe输入收据也一直写旧常量。此前从归档恢复并增量编译的结果不因此失效，但不能作为当前公开构建可用的证据。

本阶段以锁文件的`ASTRA-original-ns3-backend.checkout_commit`为唯一预期版本，核对该条目的路径、完整提交格式、直接父gitlink、实际HEAD和源文件干净状态。不能读实际HEAD后直接当成预期，也不能退回旧版本、更新上游或放宽脏工作区检查。函数只在需要身份时读取，不能使纯输入校验在导入模块时依赖外部Git或锁文件。

构建与resume收据用本次固定版本；probe的该字段说明当前源码预期，不冒充被传入任意二进制的编译身份。保留旧收据原件。无外部下载、GPU、系统安装、推送或依赖内容变化。

## 验收

1. 人工构造独立小Git父/子仓库与锁文件，验证合法版本、缺条目/重复条目、路径错误、提交错误、锁文件与父gitlink不符、HEAD偏离、源码变脏和resume旧身份的拒绝；不得用真实依赖checkout切换来做负例。
2. 运行构建相关Python回归，确认纯校验导入无需读取锁文件。公共构建从全新输出目录执行，不从旧对象或恢复二进制中取成功结果。
3. 使用本机已有CMake/Ninja/Protobuf；构建只链接锁定原生ns-3，没有UB。通过公开topology/rdma-probe执行一次小网络，独立核对完整完成、源/目的字节和链路端口。此处仅功能验收，不作性能研究、不重复既有研究条件。
4. 若原生全新构建暴露另一个错误，保留退出与产物，先定位原因；不提高预算，不以增量归档冒充从零构建。阶段可交付已验证的修复与实际未通过边界，不自动扩研究条件。

## 预算和交付

独立目录`runs/native_build_identity_20261027/`。累计900受监控秒/1GiB新增产物（含归档和2MiB收据预留），卷预留8GiB。配置每命令60秒、编译每命令300秒（固定两并发）、其他命令60秒；构建RSS2GiB/地址4GiB，单网络RSS1GiB/地址2GiB、60秒/64MiB产物，协议原5ms模拟上限。最多一次configure、一次完整compile和一次实际probe；不同源修复后只重做失效步骤，保留首次失败，不重复成功网络。

交付函数、独立检查、小型公开操作记录、源码/依赖身份和用户指南。结束后再独立规范实际多NIC绑定；本阶段不解除持久传输的现有限制，不宣称论文创新成立。研究整体保持`in_progress`。
