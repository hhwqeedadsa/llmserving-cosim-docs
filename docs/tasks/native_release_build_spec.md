# 原生Scale-Out Release构建修复

2026-10-27，起点`3e047e1`。这是平台构建修复，先于后续宿主性能研究独立实施、验收和提交。

## 问题与实现范围

已验收的437个编译单元实际均为`-O3 ... -O0`。固定原生ns-3的`NS3_WARNINGS`分支把`-O0`与告警一起追加；仅指定Release不足以启用优化。旧网络结果仍保留，但宿主性能不能作为优化后的强基线。

公共`scaleout rdma-build`在不修改任何锁定依赖的前提下，关闭这个捆绑分支，通过显式C++告警参数保留`-Wall -Wpedantic`。启用编译数据库输出；配置成功后、编译开始前，核对每个实际编译单元的有效优化参数、告警、关键原生/会话源码覆盖及开发全量progress校验宏关闭状态。遇到响应文件、无法解释的命令或不符合条件的单元明确拒绝，不能只检查Release名称。

构建provenance及backend.json记录编译数据库hash与核查摘要。新增显式`--compile-wall-seconds`允许为全新构建事前选择60—1800秒，默认仍300秒；不得把失败后的加限或resume当作本阶段授权。保持固定两并发、构建RSS2GiB/地址4GiB、512MiB构建产物与8GiB空闲保留。UB入口、依赖源码/gitlink、网络模型、调度和计时均不改。

## 独立验收

1. 输入真实形状的小型编译数据库，检查最后一个优化选项覆盖、缺告警、未知/缺失优化、响应文件、开发校验宏及关键源码缺失，公共帮助对应新预算参数。保留原有固定源码身份和RDMA输入回归。
2. 全新目录公开构建一次，配置后先核对全部单元，再编译全部五个程序；不能复用旧对象或复制二进制冒充构建成功。记录实际二进制及加载库hash。
3. 最多两次新网络：一个公开普通probe小例；一个已验收物理NIC功能用例中的共享Agg/双NIC、两rank两调用modern小例。后者与旧固定归档中的完整result、control和应用快照逐项比较，仅允许经hash验证的加载库路径差异。此处不启用宿主计时、不作加速排名。
4. 独立核对包/端口与modern数据/事件，通过复制源码/空cwd从成员hash归档恢复核验，不再执行网络或构建。旧归档只作为只读参考，旧阶段预算不重开。

## 新阶段预算

独立目录`runs/native_release_build_20261027/`，累计2400受监控秒/2GiB新增产物，含归档、恢复及2MiB收据预留。一次配置60秒、一次完整编译900秒（全新优化构建，显式公开参数），外层构建监控1000秒；保守重复计算内外监控。其他命令60秒，RSS1GiB/地址2GiB。网络沿原小例5ms/既有捕获及结果限制，不增加逻辑工作量。

不重试失败、不提高本阶段预算；失败保存并停止后续网络。零下载/安装/GPU/依赖更改/push，只做本地提交。修复常规编译设置不是论文创新；若通过，再另行预注册优化后宿主成本，不能在本阶段追加性能样本。
