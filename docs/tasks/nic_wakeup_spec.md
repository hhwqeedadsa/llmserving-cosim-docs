# 源NIC限速后的自动唤醒正确性

上一目标轮为实质进展：独立经典等待对照完成、完整原件封存，但剩余源空闲的调度原因未证实。本轮是独立平台正确性阶段，不重跑已关闭的研究网络，不把修复本身作为论文创新。

## 问题与竞争解释

当一个QP已发完本次公布字节、仍等待ACK，或因PFC/窗口不可发送时，它的旧`m_nextAvail`不能阻止另一条有待发字节、未暂停且窗口允许的QP在限速截止自动唤醒。另一个候选是新工作/速率变化使可发时间早于旧定时器，但旧事件未提前。这两类若存在，模型可能依赖额外ACK/控制包才能再次发送。正常的端口串行服务、速率约束、PFC和窗口等待不是缺陷，必须保留。

先用当前固定原生库及QbbNetDevice真实事件选择核查。测试可以人工设置QP状态，并在选择到可发送QP时停止，不能将这种CPU状态核查写成完整包级运行。必须记录旧库的正负条件，不预设缺陷，也不从该小例直接解释上一研究的全部闲置。

若缺陷成立，修复锁定原生ns-3中的唤醒候选/重排，保持ACK高优先级、数据RR、窗口/PFC、真实PktSent速率和物理端口服务。只做本地源码补丁，不更新上游版本、不改UB或serving。按内到外保存native、ASTRA、LLMServingSim及主仓库gitlink/锁文件；用户禁止push优先，补丁和本地来源记录须保留，不声称远端可获取新提交。

## 覆盖与验收

- CPU真实原生事件：单独未来QP；已发完但未ACK的旧QP；窗口约束QP；暂停QP；全部不可发；新增更早工作；速率提前/推后；同ns控制事件；暂停恢复/窗口解除。独立预期来自有待发字节、未暂停、窗口允许的最早时刻，不从旧实现复制期望。
- 若修复，核实际底层事件，不用忙轮询、填未来字节、重置连接或固定通信起始时刻替代。
- 最多四次小网络，分别用于最小实际双QP复现/修复及公开持久/事务路径回归；先保存所有输入和旧新库身份，成功网络不重跑。CPU用例不计为网络。
- 原生及项目回归分开。独立核实际物理TX/RX、包与反馈、源速率/间隔、后继和资源完成；恢复新源码根/空cwd离线核验及一个公开小型实际执行必须在四次网络名额内安排，不额外补跑。
- 旧研究原件保持；只有平台验收并独立本地提交后，才另立研究协议生成受影响完整应用结果，不混合本轮功能样例作研究收益。
