# 持久连接丢包恢复与副作用安全

平台增量，基线256dfc2。目标是让在线持续追加的字节流和远端事务能在真实包丢失后恢复，并保留真实未完成/失败状态，供后续MoE系统鲁棒性研究使用。不是新重传算法、生产漏洞证明或硬件校准。

新增可选工作根字段`transport_recovery`，stream v1/v2/v3及事务v1..v5均适用。模式`go_back_n/1`，显式initial_rto_ns、max_rto_ns、max_retries、max_events；可选rtt_estimator采用已有Karn规则。未声明保持默认行为。protocol继续拒绝旧recovery/admission/drop_once/lifecycle；显式恢复才允许protocol.faults。故障规则message_id在此模式明确指stream ID（事务connection*2为请求，+1为响应），sequence为整个连接累计偏移，不是操作内偏移。不得套用描述符1B校验或假造故障命中；实际命中单独报告。

每个连接保持一个QP及累计序号。只发布实际入队work；发布扩展计时器的合法范围，不启动计时。首次实际发包启动，源端实际TX更新高水位，真实ACK/NACK更新确认；重复/旧ACK不延期，迟到ACK允许超过重传游标但不能超过实际TX高水位。ACK释放每work一次，已确认前缀可以空闲后追加；idle没有重传计时器，估计器证据保留。不读取接收真值作源端决策。原生队列、PFC、路径、DCQCN和同一时钟保持。

重传仅回退源发送游标，保持真实调度与pacing。接收端根据本地连续已接收序号识别完整重复包并补发实际ACK；重复字节不得再次送入事务解析器或执行原子/写入。源端载荷仍由原work提供。接收完成、ACK、远端副作用、事务完成和资源释放继续分别记录，不以网络idle冒充会话结束。

所有物理TX/RX/drop均计入在途量，故障必须走实际链路错误模型。尾部ACK丢失后也要实际重传、重复ACK、物理排空。超出重试上限保存失败ID/时间及部分结果，不能伪造完成或自动增限。未完成连接不得Close。恢复计时器在排空/关闭后取消；独立CNP与恢复可同时工作。

验收覆盖：纯源端状态扩展及非法ACK/时间；旧默认逐字段差分；中间/尾数据、最终ACK丢失；多work跨边界、空闲追加、短RTO导致实际误重传/迟到反馈；耗尽与真实截止；重复事务原子只执行一次、实际源字节与最终窗口；在线会话后继；独立CNP组合；CLI/native非法参数及未知stream；现有stream/事务/会话回归。包、源端计时器和内存副作用由独立检查核对，并拒绝篡改。功能验收后本地提交，研究实验独立预登记；论文目标仍须代表性负载、强基线、现代事件语义和硬件校准。

执行预算由当前任务维护；每命令60秒/1GiB/地址2GiB，仿真5ms，结果16MiB，累计受监控600秒/256MiB及tmpfs8GiB预留。失败保存原因，不抬限重跑。归档含实际运行入口/库和验收输入，成员128MiB/压缩40MiB，恢复使用新源码根和空cwd。
