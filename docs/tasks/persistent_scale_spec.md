# 持久共享网络的千端点容量阶段

平台阶段，基线`99ab5f1`。前阶段已关闭，不追加旧网络。旧完整模型的1024卡执行在600秒内未完成（256/512已完成）；不重跑该失败、不比较不同工作量的加速比。本轮解决持久入口仅128连接/8192工作及强制1GiB宿主限制，使1024端点×EP4组的明确功能程序能在同一网络运行。不是完整推理、生产路由或现代GIN接入，不消除self-peer/GPU可见/校准门槛。

1. 新`moe-rdma-stream-work/4`保留v3实际事件驱动的write/local语义，要求显式`limits={max_streams,max_work,max_link_transmissions}`。上限4096连接、65536节点、2000000个全网物理链路发送事件；旧v1—v3计数、200000发送事件和宿主夹限不变，事务缺省不变。v4沿用协议已经验证的RSS/地址预算（壁钟仍≤60秒、单次产物≤64MiB）。所有范围/类型在CLI与native一致拒绝，native计数错误应在Fabric分配前拒绝。
2. 全部GPU/连接/后续轮次共用一个Simulator、持久序号和拥塞/队列状态，不拆组后相加；不重置连接、不省略ACK。实际完成与源信用保留，配置/回归不改包或时间。明确公开计数和实际链路发送数，保护元数据、字节、观察及文件预算仍独立生效。
3. 公开例和可复现生成器区分集群端点N、EP组R、组数N/R、轮次及字节；每组执行所有有向非self对，前后两次All-to-All与声明local工作由实际接收/ACK推进。下一轮不得固定ready时刻。它是合成通信/依赖压力程序，没有MoE数值、真实路由、self-peer或生产屏障保证，不可取代旧完整模型千卡目标。
4. 六次网络最多：同小v3输入的旧/新完整差分；新v4小例；128端点v4；1024端点v4；新源码根/空cwd公开小例回放。先检查小/中场景，再执行目标。目标1024、EP4×256、2轮、每对每阶段768B，全部3072向QP及16384节点（12288写、4096本地）；所有端点完整抓包（预算100000），无需扩大捕获上限。独立重建全部源包/端点接收与ACK、每连接字节/工作前缀、就绪/本地FIFO及末态端口/排空；篡改拒绝。历史完整模型不重跑，不从本次工作量给推理加速比。

阶段预算600累计受监控秒/512MiB累计新增存储，含原件、两包、恢复、持久副本及2MiB源码/收据预留。每命令≤60秒，编译/普通检查RSS1GiB/地址2GiB，目标网络及其核验RSS4GiB/地址8GiB，单命令新增产物64MiB，网络5ms/result32MiB（小例16MiB），最多六次实际网络。tmpfs预留8GiB/根卷64MiB。不改固定依赖，不安装下载/GPU/push，不自动扩限或为修checker重复成功网络；失败保留并停止依赖它的目标运行。按新header布局重编全部三个入口及消费者，复用固定Fabric与八库。
