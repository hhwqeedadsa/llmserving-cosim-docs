# 持久RDMA的物理NIC寻址与绑定

2026-10-27，起点`b78aa59`。这是平台功能增量；共享链路优化、通信表示决策与省包事件研究另行设计，不以本功能验收证明论文创新。

## 要解决的问题

现有持久流/事务/现代入口只支持每目标GPU/plane唯一最短首跳NIC。同plane多rail即使可生成拓扑也不能执行。删除Open断言、临时修改全局目标路由表或依赖QP hash不能实现连接绑定；把共享rail复制为独立plane还会删除真实Agg/MMU竞争。

本阶段在一套锁定原生ns-3和同一时钟中实现：

1. 每物理GPU/NIC有确定的端点地址。同GPU/plane仅一张NIC时沿用原`11.x`地址；有多张时使用独立`12.x`地址，按`0x0c000000 + GPU*2048 + NIC`编号，支持GPU0..1023、端口1..1024。地址不含stream、请求、专家、优先级或研究标签。原普通SEND/RECV地址/选路保持。
2. 原生`RdmaHw`增加可验证的本地地址到物理NIC注册：实际接口必须拥有该地址、必须是实际Qbb NIC、必须在QP创建前注册且不得改绑。发送QP按其稳定本地源地址选NIC，接收QP按本地地址选择ACK返回NIC；未注册地址沿用原先目标路由/hash行为。清空或重建路由不清除物理绑定。
3. 新别名的最短跳路由只允许从声明目的NIC进入GPU；不能把GPU当中转，也不能从另一个同GPU网卡提前终止。交换机内部ECMP保持。源NIC可不是全GPU最短首跳，只要其接入交换机能到达目标NIC。Python在输出/启动前按相同约束拒绝不可达或错误plane/端口；距离表只缓存一个目标，避免保留GPU×节点矩阵。
4. 新增绑定只在持久模式启用；共享Agg、端口与MMU不复制。数据、原生ACK/NACK、独立CNP及MRT1请求/原子回复均走实际链路。加强实际端点TX/RX绑定断言，初始绑定与故障重建后不随流ID迁移。
5. 故障仅沿用现有永久交换机链路关闭/显式延迟重建和既有恢复。别名路由参与重建，保留QP、序号、拥塞状态与源保护。没有可用路径时按有限重试失败/隔离，不免费更换网卡；不新增NIC失效、跨NIC迁移或生产路由协议模型。

## 分层验收

- **原生API**：实际Node/IPv4/Qbb对象检查错接口、未分配IP、loopback/不存在NIC、重复/晚注册；构造发送/接收QP，证明两张本地网卡到同一个远端IP仍分别绑定，路由表反向设置及ClearTable后绑定不变，零字节创建的实际QP所属队列与初始速率来自正确NIC。只检查对象，不运行网络。
- **纯准入**：四交换机64子图、两个方向及四种NIC配对共512个组合，以独立简单路径枚举核对；补边顺序、GPU不作中转、plane隔离、无路、选择较长的合法首跳。旧最短首跳查询接口可保留，其历史限制验收不改写成新功能证据。
- **缺省兼容**：在修改前以现有已核身份的公开构建运行一次单NIC持久小例；修改后同输入再运行一次，完整结果（排除实际程序加载路径，如有）逐项一致。不重复既有研究网络。
- **实际多NIC**：各一次独立rail字节流、共享Agg拥塞/独立CNP字节流、跨NIC真实put/fetch_add事务、共享Agg现代两轮完整调用、具有替代路径的交换机故障及无替代路径的有限失败。后两条件验证重建、源保护和不自动迁移。至少一个共享条件让同源GPU的两张NIC访问同一个远端NIC；不能用每目标全局首跳替代绑定。
- 完整包捕获独立核对端点、正反向和逐跳链路，端口字节/共享交换机排队/反馈与模型内存副作用；来源、功能、性能与硬件校准分开。现代执行仍为功能MRT1/声明成本，不声称现代GIN或LLMServingSim全服务。
- 错误绑定通过公开CLI在输出/后端启动前拒绝；假marker仅作负向启动检查。受影响Python回归、13项固定依赖检查和复制源码/空cwd离线核验通过。
