# RC操作包接入：独立小型网络验收

2026-10-27，起点`48d84eb`。平台增量，非研究收益实验；既有网络条件保持关闭。

目的：在同一锁定原生ns-3 Fabric中，用真正携带操作字段和数据的包推进WRITE、fetch-add及携带旧值的Atomic ACK。目标内存只能从收到的字节改变，源完成只能从实际反馈产生；不再为Atomic ACK创建反向可靠流或额外确认。不更改MRT1、modern或UB入口，不把本增量称为创新或性能收益。

范围：一个已建立QP、顺序提交且每次仅一项WQE在途，固定单注册区/rkey、24位无回绕PSN，非空分段WRITE及对齐64位fetch-add。沿用独立Python RC参考的操作、重复及返回值安全约束，原子重放缓存容量1。最多64操作、64KiB累计WRITE和64KiB内存、合法256/512/1024/2048/4096载荷MTU。明确该范围不能评价多QP竞争或现代MoE完整执行。

线格式：IPv4/UDP4791，BTH、所需RETH/ATMETH/AETH/Atomic ACK旧值、4字节对齐及4字节ICRC位置；ICRC仅占位不计算，IPv4 UDP校验和为0。PPP开销与尚未建模的以太网开销分别说明；不添加work/task关联字段。固定原Linux头文件用于独立字段核对，不称可直接与RNIC互通。默认关闭的原生解析分支只由新入口启用，退出复位，旧SeqTs路径保持默认。所有请求采用优先级3，所有反馈显式高优先级；不依赖误读BTH选择队列。拒绝INT修改型拥塞模式。

发送由既有物理NIC调度和包长决定节奏。原生QP仅提供调度容器，其计数单位为待发包数，明确不代表RC字节窗口或硬件NIC信用。本阶段固定速率，不声明DCQCN反馈。实际源发送才启动固定RTO；超时重发当前未完成WQE，最多3次。序号NAK保留记录，恢复只在RTO触发，不新增恢复算法。物理接收错误模型丢包；反馈不再产生反馈。

事前固定公开小例：2服务器各1GPU、2pod各1ToR/agg及1共享core、单rail、100Gb/s、每链路1000ns；MTU256。1024B目标区，768处初值41；先写0..599的确定字节，再fetch-add(768,+5)。四个新网络条件各执行一次：健康；目标GPU1丢WRITE_MIDDLE/PSN1一次；源GPU0丢ACK/PSN2一次；源GPU0丢Atomic ACK/PSN3一次。RTO100000ns，最多3重试，最大模拟5ms。最终600B内容一致、目标46、返回41、原子仅应用一次；丢反馈不能提前源完成。另一次新legacy最小发送检查默认解析未改变。失败条件封存，不改条件重跑；仅可离线定位。

验收：公开CLI/配置/独立例；严格输入拒绝；操作包逐字节解码；从实际收包依序重放独立Python参考并核目标效应/完成；全部物理TX/RX/损失守恒、真实路径和队列事件；新旧解析分支分别检查；复制源码/空cwd离线核验和带hash归档。测试不作为研究驱动。功能记录与评价真值分别存储，不注入报文。
