# 有界选择性重传参考基线

目标：为链路失效共享队列研究提供比回退重传更强的公开基线，避免把经典传输能力误写成论文创新。本平台阶段不执行研究收益矩阵，与研究分别提交。基线`c01cf2d`，不修改外部依赖，不安装下载或执行GPU。

## 范围与协议

独立持久字节入口的`transport_recovery.mode`新增`selective_repeat/1`，保留现有timer字段，增加显式`receive_buffer_bytes`和`inflight_bytes`。必须同时配置独立DCQCN参考控制器；不支持事务payload、在线会话或生产RoCE/IRN复刻。已有go_back_n及缺省行为保持。

1. 接收端只保留实际收到的乱序数据包，按其payload字节限制缓冲；相同包重复到达不重复占用容量，缺口填补才推进累计接收前缀和工作回调。满时不假装接收或ACK该范围。
2. 每个实际数据到达产生一个真实ACK/NACK，保留原IP/端口/优先级，并携带16B `MSR1`扩展：magic、被接收包起止偏移及有效标志，均为32位大端。累计前缀仍放原ACK序号。扩展随真实网络传播/排队，源仅解析实际收到的反馈。丢失反馈由后续重复包重新产生。
3. 源保留有限窗口内已获得选择确认的区间，发送/重试跳过这些区间。一个累计缺口最多快速重试一次，之后依赖实际累计进展或有界RTO，不用每个NACK反复触发同一缺口。超时继续使用已有固定/Karn计时，累计ACK才释放工作信用。
4. 使用原生固定字节窗口；按包起点判窗，最后一包最多越过`inflight_bytes`边界`payload_bytes-1`字节，因此要求接收容量至少`inflight_bytes+payload_bytes-1`。不把此数当校准BDP。发送前缀、实际发送高水位、选择确认与累计确认分别记录。
5. 所有包和控制器共用原有ns-3及时间；不清队列、不撤回已发送包、不读远端状态替代反馈、不绕过实际完成。窗口内区间/重排包和事件有明确上限，失败保留，不自动扩限。

## 验收

纯状态机用独立逐字节oracle核验乱序、重复、满缓冲、缺口、多窗口、选择确认丢失/迟到、跨工作包边界与非法区间；双侧配置校验包括bool、额外字段、容量和不支持的入口。小型实际网络覆盖：正常、头/中/尾数据丢失、选择ACK丢失、真实链路失效、空闲追加和窗口反压。独立重放真实数据到达与反馈扩展，核对累计回调/发送范围/容量峰值、物理包和队列退出，并拒绝反馈或前缀篡改。原go_back_n完整结果与旧二进制比较保持（除加载库路径外）。新目录公开流程及离线检查可重放。

实现与构建阶段预算600累计受监控秒/256MiB（含恢复、持久副本及1MiB收据），每命令60秒/RSS1GiB/地址2GiB/产物64MiB；网络最多12次功能/回归执行、5ms/result16MiB，tmpfs预留8GiB/根盘64MiB。只增量构建本阶段消费者，固定八个原生库只读复用。编译或运行失败保留原因，修具体实现后才接续；不扩大预算或重跑未改变的失败。若预算/实现证据不足，本阶段保持未完成，不宣称已提供强基线。仅本地提交不push。
