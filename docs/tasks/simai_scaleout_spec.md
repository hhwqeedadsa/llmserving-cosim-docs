## 部署与输入

目标320GPU/40台八卡服务器：主EP256域rank0..255（每rank每层1个路由专家），次EP64域rank256..319（每rank每层4个路由专家）。两个域承载不同请求，不是训练DP AllReduce。第一域使用按文件数字排序的前12请求，源rank为floor(i×256/12)；第二域使用余3请求，源rank为256+floor(i×64/3)。这是声明部署，非真实运行时采集位置，不声称流量已充分覆盖全部GPU。

参考网络为前轮已生成的Clos-320与HPN-inspired-320。Clos单plane/各层400G；HPN启发结构8 rail/2 plane、每plane200G接入和400G上层，总400G/GPU。它们交换机与上联资源不同，不能把差异直接归因于拓扑形状。机内消息仍走声明网络，不补造NVLink旁路。

SimAI每个EP域使用原生Cluster创建相应数量的TP1/PP1 Replica；仅对有请求的源Replica初始化实际Orca调度器。初始KV状态通过上游Request生命周期显式建立，保留不同前端/网络时间原点转换。初始条件不计为实际Prefill执行。

平台需要新的稀疏路由输入与独立校验，保留旧`rdma-run`要求每rank提供完整请求的严格语义。按所选请求的原索引生成All-to-All-v的Dispatch/Combine消息及Chakra依赖；不使用标量均匀All-to-All替代原矩阵。
