# 源端流失败隔离

平台增量，基线 `7d5d468`。为后续局部恢复研究提供真实网络继续执行能力，不将原先全局停止与本模式的差别作为算法收益。研究问题仍是有限状态下健康贡献能否安全保留，并须与等待旧写退出、独立窗口等强基线比较。

持久 `transport_recovery` 新增可选 `on_exhausted`：`stop_simulation`（默认）或 `isolate_stream`。适用字节stream和MRT1事务/在线入口，仅隔离实际检测失败的**源端单向stream**，不是双端连接销毁、成员移除或远端已获知错误。响应流失败不能冒充请求发起端已收到失败通知。

源端计时器耗尽时，只从本地NIC调度集合移除该QP并取消其源端速率/重传计时器；保留QP映射、真实序号、工作记录和未确认源租约。其他QP的计时器和发包继续。失败源不再发布/产生新数据；此后才就绪的工作（含在途请求触发的新回复）仍可在原有有限预算内入队，但保持未发布，不能以提交异常停止其他流；已经进入物理网络的包继续传输，目标不得查询源失败状态来阻止应用。迟到ACK/NACK/CNP只记录，不复活失败状态、不释放工作信用。接收端已有NP/CNP机制保持，不能把取消源端工作当成撤回旧写的保证。

新增显式隔离结果区分线端空闲与应用成功。失败运行始终为部分结果、退出1；`passed/closed/事务完成`不得伪造成功。默认配置完整result保持逐字节一致。当前没有源重连、跨代际复用或新的恢复调度器；声明失败不是旧写退出证书。

验收：默认新旧差分；一条流耗尽后延后启动的健康流继续；健康流在另一条流失败后仍能执行自身超时恢复；两条独立失败均保留；短RTO导致在途请求在失败后实际应用而源端ACK/完成仍未发生；源租约保持、健康租约正常释放；独立CNP与隔离共存；CLI/native严格拒绝非法policy；原stream/事务/在线及准备顺序回归。捕获包、源TX上界、ACK和目标副作用由独立程序复核，不把检查器输出当实机证据。

目录 `/dev/shm/moe-source-isolation-20261024/`。每命令60秒/RSS1GiB/地址2GiB/产物64MiB，仿真5ms/结果16MiB；本阶段累计监控450秒/新产物192MiB，含失败和检查点，内存盘保留8GiB。隔离构建五个受影响源文件及三个入口，固定依赖和旧runtime不变。归档/解包分别有界，不安装下载、不运行GPU或旧Prefill/1024失败用例。失败保留，不抬限重跑。验收后独立本地提交，不push；论文整体目标保持in_progress。
