# 持久连接NIC可执行性：纯输入准入修复

2026-10-27，起点`2180762`。这是平台缺陷修复，与网络收益研究分别实施、提交和验收；不把准入检查当作论文创新。

## 问题和范围

拓扑生成允许rails>1且planes=1，每端点同plane有多个NIC。当前`scaleout_streams.validate`只检查端口存在和plane匹配；事务/现代入口复用这项检查，因此可在Python端接受此输入。固定`Fabric::RebuildRoutes`为每目的GPU/plane反向最短跳BFS，GPU不是中转；`PersistentStreams::Open`要求源和反向路由表都恰好是声明的单个NIC。多候选会在原生Fabric已分配后失败。不能把双plane示例成功称作同plane多rail已实现。

本修复仅将已有原生限制提前到公共Python入口：按同一初始路由规则计算所有最短首跳NIC，源和反向都须是声明的唯一端口；报错包含stream、方向、候选和声明NIC。复用事务/现代已有校验链，不添加接口字段、不选ECMP hash凑绑定、不修改图/网络/恢复/包/原生或依赖。不声称实现了同plane多rail或故障后的NIC重绑定。普通SEND/RECV路径不受影响，交换机内部ECMP在端点NIC唯一时保持合法。

## 验收和停止条件

1. 修改前保存最小2rail/1plane输入及旧校验接受事实，独立手算两条等长、首NIC不同的路径；核验固定原生源码的BFS和Open要求，不冒充已执行原生失败。
2. 新检查拒绝源或反向多NIC、声明端口不是唯一最短路、无可达路；接受双plane、单NIC多核ECMP，以及虽然有多个物理NIC但只有声明端口是最短路的场景。不得一律拒绝所有多NIC拓扑。
3. 独立枚举四交换机的64种无向子图，以简单路径枚举的最短首跳集合核对BFS；补GPU不得中转和plane过滤反例。检查原有stream/transaction/modern相关单元回归。
4. 从新cwd通过公开topology、rdma-stream-probe和modern-deepep-native操作验收。后两入口使用写marker即退出的假后端，证明不创建输出/不调用后端；该脚本是负向启动检查，不是网络执行或仿真结果。正向输入只作纯准入，不伪造成功result。
5. 保留原输入、命令、失败、stdout/stderr、源码hash和单元/公开操作摘要。零新网络/构建/安装下载/GPU/依赖变更/push。失败不加限或偷偷放行，必要时回到输入定义核对。
