# 交换机间物理链路失效与路径更新

基线`a89f007`。上一轮通信域适用性核查是实质进展，整体论文目标继续进行。本平台增量解决此前原生端口关闭的排队/MMU不守恒，以及网络入口不能表达真实链路失效的缺项；不把修复或经典重路由当论文创新。

## 范围与不变量

- 仅显式选择实际switch—switch物理边，双向永久关闭；不实现NIC失效、rail重绑定、链路恢复、CUDA或MR退出。
- 原生`TakeDown`释放每个实际出队丢弃包的入口/出口MMU与私有转发计数；不调用含ECN/发送统计副作用的正常dequeue回调，不读评价种子清单。控制优先级0不计数据MMU。健康入口满足恢复条件时发送真实PFC resume。
- 关闭接收端丢弃此前已发送的在途包，走真实接收丢弃回调；排队/无法转发丢弃不递减物理在途计数。不得撤销已发送的包、制造ACK或重置源QP序号/拥塞状态。
- 故障时保留旧路由，延迟后使用存活同plane图重新计算最短路及ECMP；旧路由选到已关闭出口或没有路径时真实丢弃，不再为死端口分配MMU。路径选择仍使用原生头字段哈希。
- 路由更新是声明的集中控制事件，未模拟控制报文/分布式检测，延迟不能当实测成本或优化收益。源恢复仍由真实ACK/超时推进。
- 默认未配置故障时保持旧执行；依赖只从固定提交建立本地补丁分支，不升级、安装、下载或push。保存原始源码/库身份及新补丁，逐级本地提交gitlink。

## 验收

Python/native在建网前拒绝非法事件、非交换机边、重复关闭和越界时间。公开CLI最小流程核对真实排队丢弃、在途到达丢弃、MMU守恒、路径更新前后实际包端口、ACK/重传完成及未受影响流。独立按真实入出队、发送/接收/丢弃重建字节，拒绝足以改变结论的篡改。缺省旧/新对照及受影响回归；新源码根/空cwd公开重放与离线复算，持久保存失败、命令和预算。

阶段`/dev/shm/moe-switch-link-failure-20261024/`；每命令60秒、采样RSS1GiB/地址2GiB/新增产物64MiB；累计600受监控秒/256MiB，含恢复/持久副本。网络≤5ms、单result≤16MiB，tmpfs预留8GiB、根盘64MiB。复用固定其他库和未影响对象，只增量编译必要消费者。失败保留，不抬限、盲重试或重跑旧失败研究。
