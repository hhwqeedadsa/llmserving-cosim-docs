# 临时交换机断链与恢复上线

目标：让128/256/512端点Clos能够明确表达交换机间链路短时关闭、物理恢复及延迟路由通知，保留同一Simulator、QP序号、重传和实际缓冲生命周期。它是研究可信度所需的平台能力，不是新RDMA协议。

## 支持范围与状态

1. 保留`switch_links/1`永久失效的输入和输出。新增`link_failures.mode=switch_links/2`，每条事件严格为`src/dst/time_ns/route_update_delay_ns/restore_time_ns/restore_route_update_delay_ns`。关闭与恢复时刻严格递增，四个实际/通知时刻都早于max_sim_ns；每条实际交换机边最多一轮关闭/恢复，1..8边。不支持NIC、rail重绑定或反复flap。
2. 新模式仅为指定物理边实例化项目内的QbbNetDevice派生类，使用原生QbbChannel和BEgressQueue。关闭继续调用原生TakeDown；恢复只设置同一设备上线并唤醒发送。不得重新Attach、重建QP/网卡、重放清空队列、清除当前发送状态或伪造ACK。恢复发生在原在途发送完成前时，原TransmitComplete继续负责该发送。
3. 物理恢复和路由获知分别推进。每条边关闭/恢复通知分别携带版本1/2；集中路由只读取已经到达的通知及已知版本，禁止读取其他端口实际状态提前传播故障或恢复。若版本2已到，迟到版本1只记录忽略，不改变路由。若版本1在物理恢复后、版本2通知前到达，仍按当时控制面已知状态排除，不能凭物理真值取消。
4. local_failover继续只过滤自己旧等价候选。恢复时可重新安装当前全局候选中的本地活端口；已被全局排除的边等恢复通知再加入，不凭空生成新路径。本地动作仍是无检测/编程成本的功能参考。
5. 四个事件均计入pending，当前工作已ACK也必须等待未来恢复/通知处理及物理排空。记录link_down/link_up、有效/忽略的路由通知、版本、已排除端口及本地变化；原在途包按实际到达时端口状态接收/丢弃，不取消或补造。

## 验收

- Python及原生整表拒绝非法恢复范围、类型、字段、重复边和非物理交换机边；非法原生输入在建网前失败。
- 所有实际网络均128端点Clos。人工持久字节例验证：恢复先于旧断链通知且恢复通知也先到、关闭通知在物理恢复后但恢复通知前合法生效、恢复晚于关闭通知、本地候选恢复、极短窗口跨在途发送、空闲后追加工作及未来事件防提前退出。
- 独立逐跳匹配全部实际TX与对端RX/物理丢弃，重建源字节与ACK，确认关闭区间无新TX、上线后实际复用原边、每连接最多一个QP、最终缓冲/在途归零。核对旧通知不能撤销新恢复状态；检查器不得导入平台状态实现。
- 同一个新128Clos缺省输入在旧/新后端各一次，除库路径外原始结果一致；不重跑已成功的旧研究。公开示例/指南/输出说明同步，平台与后续研究分别提交。
