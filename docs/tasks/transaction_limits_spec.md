# 持久事务的显式执行额度

目标：去掉现代应用接入前的8连接/32远端操作硬上限，让同一有界原生运行容纳EP4全互通和较长的计数/通知序列。本阶段只实现平台容量与一致性，不把功能扩容称论文创新，不执行性能研究。基线`fd3b714`，不改固定依赖。

`moe-rdma-transactions/5`可选`execution_limits`，必须完整填写`max_connections`（1—64）、`max_remote_operations`（1—1024）和`max_local_operations`（0—256）。整数不接受bool、额外字段或未知schema；缺省保留8/32/16，不接受其他schema携带该字段。连接id须小于声明连接上限；远端/本地生命周期累计数分别限制，总节点数为两者之和。显式声明不改变源QP/请求序号、线上字段、深度、时延、信用或释放语义。

Python、原生离线/在线准入、实际事务队列、持久载体及目标请求上下文/序号使用同一有效额度。载体连接数为2×max_connections（请求/回复），工作上限2×max_remote_operations；源读保护记录上限为总节点数（旧缺省48），是有界元数据数量，不是硬件并发额度。已有队列深度1—32、窗口≤16、稀疏页、32个依赖/8个条件、观察和资源预算保持。可选queue_fence最多覆盖max_connections项，必须源拥有。保留64位MRT1请求序号与32位载体字节序号的线格式及原子返回值；目标重复处理和所有权限/范围/并发写检查不放宽。原有16个并发本地写lease仍是独立约束。

只在显式配置时增加有效额度输出。在线追加必须整批验证总生命周期额度，超额不执行候选前缀，合法后续仍可继续；不能把批次数当总数或自动提高额度。普通旧配置完整结果与旧二进制比较；新目录公开流程和离线恢复均可复核。

验收：纯状态核对目标第32个之后的请求/回复、重复和配置拒绝；Python/原生非法条件；12连接且超过32远端/16本地节点的同一运行、单连接长序列和实际丢包恢复、在线追加及旧缺省回归；独立实际包负载/内存/回调/队列检查，不以仅返回0替代。最多8次实际功能/回归网络（含新目录流程），不重跑成功网络修checker。若发现语义缺陷，修最小功能例，不借本阶段开展现代收益矩阵。

首次expanded因遗漏原有48个源读保护记录于0ns、48项已准入后失败；同步发送回调已发两帧、无事务完成，保留部分结果。修正同一执行额度派生的读保护记录上限；不放宽独立写保护数或内存字节数。该失败计入8次预算，取消独立健康长序列网络，仍以丢包长序列核对全部64项实际返回，并以CPU oracle核对正常序列，不追加第9次网络。

预算：600累计受监控秒/256MiB新增磁盘（含恢复、持久和1MiB收据），每命令60秒/RSS1GiB/地址2GiB/产物64MiB；网络5ms/result16MiB，tmpfs预留8GiB/根盘64MiB。只增量编译事务消费者，复用已验收持久对象和固定八库；无安装、下载、GPU、依赖变更或push。失败保留，不自动扩限。现代self-peer、真实GIN可见性、应用桥接和硬件校准仍需另行完成，本阶段不能宣称已接通现代完整应用。
