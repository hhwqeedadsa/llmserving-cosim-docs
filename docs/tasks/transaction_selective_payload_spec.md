# 选择重传的实际事务字节交付

平台阶段，基线`aff6f9a`。上一轮事务额度阶段已经关闭，不追加其网络。当前纯字节选择重传明确拒绝payload receiver；乱序包仅更新字节前缀并被释放，没有事务字节交付。事务输入也不能配置选择模式必需的独立DCQCN参考。这阻止把已采用的强恢复基线用于地址写、原子回复和事件驱动应用。修复此缺口，不设计新恢复算法或开展性能收益矩阵。

1. 选择接收前缀推进时，严格按字节序号从本次实际接收包和此前实际缓存包提取payload，交付连续前缀，随后释放已消费缓存。不能从发送方Work/操作表重建内容，不能因选择ACK提前交付有洞数据、重复交付旧包或丢弃已接收内容后只更新计数。实际交付在同一ns-3时钟回调中推进MRT1解码。
2. 允许`SetReceiver`在选择模式使用。新增`payload_delivered`选择事件包含实际包UID、序号和hex，共用已声明的max_events；无receiver的字节模式保持原全部输出与时序。源信用仍只由累计ACK释放，目标原子仍按MRT1请求恰好执行一次，目标应用、源ACK、回复和完成分开。
3. v5事务可选`dcqcn_reference`，由已有Figure7参考控制器解释，配置在建连前生效。Python和两个原生入口一致验证；选择模式必须显式配置它。允许同一参考配合回退模式作为基线。非v5拒绝新字段，现有有界payload池与选择模式仍不兼容并明确拒绝，不扩大其范围。普通配置结果不增加字段。
4. 公开配置、输入帮助、输出解释和小型例必须交付。实际执行覆盖请求乱序与原子恰好一次、末尾回复丢失依赖超时、跨包MRT1写/本地copy/转发、在线按真实返回值追加、显式前缀发布、旧缺省完整差分及新源码根/空cwd公开重放。独立解码实际包、选择反馈、缓存前缀、交付和目标最终状态，篡改应被拒绝；不以程序返回0替代核验。

预算：600累计受监控秒/256MiB累计新存储（原件、归档、恢复、持久副本及1MiB收据），每命令60秒/RSS1GiB/地址2GiB/新产物64MiB，网络5ms/result16MiB，最多8次实际网络包含新目录重放。tmpfs预留8GiB/根卷64MiB。增量构建消费者及修改的持久载体，复用固定八库和Fabric静态库；不安装、下载、执行GPU、修改固定依赖或push。失败保留，不自动扩限或为修checker重复成功网络。

MRT1/选择扩展是功能格式，不是RoCE原子或GIN校准。现代self-peer、实际目标GPU可见性、完整MoE接入和千卡仍未完成。本阶段只补使强基线可以进入真实事务链的必要能力，不能计作论文创新。

验收执行安排更正（最后一次网络前）：前七次已经覆盖五个新事务条件及同库默认旧/新差分。第八次改为从已核hash的新源码根、空cwd公开执行旧纯字节选择模式healthy输入，与原保存结果全量比较（只规范化已核同hash的八库路径），检验无receiver行为不变；该目录同时运行新事务preflight并对五条件作离线重算，产物逐字节比较。这样既检查公开迁移流程，也保留纯字节兼容门槛；不另加第九次网络，不用第二次新事务网络代替旧字节路径回归。
