# 用户入口与可复用交付要求

2026-10-05 用户要求按可复用研究软件的标准交付：用户应能通过仓库内的文档、配置和命令独立完成操作，不依赖 agent 的会话记忆、本机历史目录或临时开发脚本。本文保留实现前的交付方案与静态审查记录；统一命令、隔离用户流程及目标首轮验收现已通过，实际接口见[用户指南](user_guide.md)，证据见[首轮交付记录](../fixtures/m10_research_slice/README.md)。下文“拟议”“待新增”等描述保留设计当时的含义。

## 实现前的基础与缺口

| 对象 | 已有基础 | 本轮需要补足 |
|---|---|---|
| 核心执行 | Python 计划/服务/导出与 ASTRA/ns-3-UB 已有实现和实际回归 | 用户操作调用同一实现，避免为每个实验复制执行逻辑 |
| 命令 | 已有 `service`、`scenario`、`research`、`bounded_export` 等模块入口及 argparse | 统一发现方式、帮助、参数、路径和错误约定；将当前研究流程包装为稳定入口 |
| 安装与构建 | 固定依赖、CMake 注入、构建记录与依赖检查脚本 | 主项目无打包元数据及统一安装/构建入口；新环境不能依赖现存 `.venv/llmservingsim-native` 或里程碑 build 目录 |
| 文档 | 根 README、backend README、夹具说明、技术规范及环境日志 | 根 README 主要按开发历史组织；需要从用户目标出发的快速开始、操作手册、配置与输出说明 |
| 目标规模流程 | 首轮图、原始事件与研究输出已有归档和证据 | 部分探针引用本机历史路径，例如 `scripts/probe_network_initialization.py` 引用 `runs/v03-target-fabric/...`；正式流程不得依赖这些路径或忽略目录中的脚本 |
| 数据与结果 | 已有 schema、摘要、observed/truth 分离、压缩记录及预算 | 明确用户输入位置、路径解析、数据包可移植性、派生结果和临时副本生命周期 |
| 检查 | 已有大量单元及真实 UB 集成检查 | 增加从安装和公开命令出发的最小完整流程验收；不能只证明内部函数可调用 |

设计审查时的主仓库尚无 `pyproject.toml`、主包 `__main__.py`、主仓库 LICENSE、CONTRIBUTING 或 `.github` 工作流。该事实不否定已有子模块许可证或功能测试；公开发布条件与本次用户可用性交付分开处理。

## 用户操作集合

拟议主命令为 `moe-ub`，同时提供等价的 `python -m moe_ub_cosim`。下表保留初始接口草案，具体已实现参数与限制以用户指南和实际 --help 为准。

| 操作 | 拟议形式 | 行为与输出 |
|---|---|---|
| 查看环境 | `moe-ub doctor` | 检查工具、固定子模块、Python 依赖、后端及可用资源；说明缺失项，不自动安装或下载 |
| 构建后端 | `moe-ub build --build-dir build/default` | 封装已有正确 CMake 路径，保存配置及构建日志，联合程序只链接一套 UB/ns-3 |
| 执行配置 | `moe-ub run --config CONFIG --output RUN` | 调用已有服务/后端，提供可随仓库运行的小型合成示例；配置明确模型、请求、网络、观测与有限预算 |
| 固定研究切片 | `moe-ub slice create --from-run RUN --output SLICE` | 按版本化清单固定来源、图、配置和必要记录；首版覆盖已知初态的完整首轮，历史归档迁入不依赖原绝对路径 |
| 查看数据包 | `moe-ub slice inspect --slice SLICE` | 显示范围、来源、覆盖、版本、校准状态、实际文件大小及完整性；说明该操作是否扫描大文件 |
| 重算观测 | `moe-ub sample --slice SLICE --config OBS --output RUN` | 重用事件生成新的周期、窗口和既有时钟观测，保存派生参数与独立核验，不运行前端或网络 |
| 重放后端 | `moe-ub replay --slice SLICE --config REPLAY --output RUN` | 直接装载既有图，在本次网络上按依赖执行；配置可固定基线或选择已验证网络扰动 |
| 核验结果 | `moe-ub validate --run RUN` 或 `--observed DIR` | 分别核验完整运行与仅公共观测；前者可读内部真值，后者不得要求或读取真值 |

这些命令是同一项目的薄包装：先盘点并调用已有模块，再补缺少的输入转换、校验和流程组织。已有模块入口暂保留兼容，旧模式的范围和限制明确记录，不承诺本轮把全部历史调试程序改成公共子命令。离线采样的顶层帮助不应先导入 Scheduler、构建后端或要求真实数据账户。

Python 命令可通过 `pyproject.toml` 的命令入口安装到用户选择的虚拟环境；原生后端仍按锁定源码单独构建，不能将安装一个 Python 包描述为已经具备整个仿真环境。是否发布 PyPI 包不是本轮条件。采用标准库 argparse 即可，不为包装入口引入插件系统或服务前端。

## 命令与配置约定

- 每个操作有 `--help`、参数含义、默认值、单位、必需条件、示例及输出说明；顶层提供版本信息。帮助中区分仿真纳秒与宿主耗时、GiB 内存/磁盘与模型中的 HBM。
- 用户通常编辑版本化配置文件，运行命令只指定配置、输入和输出。配置内路径相对该配置所在目录；命令行路径相对当前目录。两者解析后记录实际生效值，不隐式搜索某个旧任务的产物。
- 同一参数的默认值与覆盖顺序只有一处定义。记录有效配置、来源摘要、版本、随机配置、退出状态、资源峰值及日志位置；不凭历史日志推定运行成功。
- 输入错误在大规模工作开始前尽量拒绝，给出具体文件、字段及修正方向。运行失败返回非零退出码，保留失败目录；输出目录已存在时默认拒绝覆盖。不存在的续跑或恢复能力不能用成功消息掩盖。
- 常规实验变化通过已支持的参数或配置完成。没有覆盖的新行为作为显式开发任务处理，不能由 agent 每次写一个新脚本来替代公共操作。

## 目录与输入输出

沿用现有源码和产物边界，不整体搬动依赖或历史夹具；用户需要了解的角色如下。`examples/` 和用户手册是待新增交付。

| 位置 | 角色 |
|---|---|
| `README.md` | 项目用途、限制、安装、最小运行、结果在哪里、进一步阅读 |
| `examples/` | 可复制修改的小型用户输入；无真实数据账户也能运行的完整示例 |
| `docs/` | 用户指南、命令/配置说明、开发文档；日常使用无需读 current.md 或完整环境历史 |
| `python/moe_ub_cosim/`、`backend/` | 可复用实现，用户改实验配置时通常不用编辑 |
| `scripts/`、`tests/`、`fixtures/` | 仓库维护工具、自动检查和开发夹具；不作为隐含的用户安装前置流程 |
| `third_party/` | 固定版本依赖 |
| `data/` | 本地来源数据和研究切片包，默认不提交 Git |
| `build/` | 编译产物 |
| `runs/<实验名>/` | 一次实验的配置、清单、观测、真值、指标与日志，默认不提交 Git |

每个公开操作说明其实际目录树。已有研究输出的 `observed/`、`truth/`、`metrics/` 与 `logs/` 含义保留；原始事件和执行图只存一份公共来源，采样实验保存引用、参数与派生结果。数据包应有明确的迁移/打包方式，失效的本机链接必须报错，不能将硬链接本身视作跨机器分发方式。

主 README 改为面向当前可用能力；里程碑历史移到单独说明并保留链接。用户指南至少覆盖安装构建、小例完整流程、已有切片的重采样/重放、真实数据的单独准备、结果读取、资源预算和常见错误。命令参考来自真实接口并持续核对；尚未实现的设计只保留在本文等计划资料中。

## M10 的交付验收

在原首轮切片任务内增加用户入口整理，不新增研究模型或长场景。开始后先明确操作/配置合同及最小示例，再实施数据包、采样和重放；每项功能通过同一个用户入口交付。

1. 在不继承开发机 `runs/`、`build/`、`.venv/` 的干净检出或等价隔离环境中，按文档创建环境、构建并执行随仓库提供的小例。固定依赖可以复用经过核验的本地源码；这样检查的是无历史产物依赖，不冒充联网获取或跨发行版验收。
2. 只用公开命令完成小例运行、固定切片、重新采样、后端重放和结果核验；全过程无需临时 Python 脚本、源码编辑、AGENTS.md 或 agent 补充步骤。新输出目录可重复运行，已存在目录不得被覆盖。
3. 将文档中的最小完整流程纳入自动检查，核验帮助、配置路径、坏输入和无后端时离线操作的行为；已有功能回归继续复用。重型目标运行按当前任务只在最终执行一次，不放进每次快速检查。
4. 真实目标数据单独取得或导入，明确其来源、访问条件及校验方式。最小示例不要求下载真实路由或模型；首轮大包不写入 Git。
5. 完成首轮目标验收、用户说明和资源报告后再结束 M10。项目功能正确性、用户可用性及硬件校准分别报告。

公开发布前的许可证选择、第三方分发说明、贡献指南、版本发布及托管 CI 可另行安排；当前没有改变仓库可见性、发布软件或授权分发受限数据。M10 优先完成上述用户工作流与本地自动检查。
