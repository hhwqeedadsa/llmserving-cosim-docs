# 源确认超时联动完整备用：执行前方法

问题：上一轮127µs整段备用在局部故障中没有收益。首先把已有源确认超时与完整备用真正联动，比较“同一早时刻直接启动”和“确认超时才启动”，分清提前启动与判断信号各自的作用。这是成熟机制基线，不把新增平台能力或超时本身称为创新。

仅用既有两步control-normal中目标primary全部消息的实际post→源完成跨度，令T为最大跨度按1µs向上取整；固定早启动基线D为该正常原件最早post+T。原完整兜底沿用127µs，不扫描、不读故障记录决定参数、不按新结果调整。当前只有一个正常样本，故障旧结果已知，不是盲测或p99，不估计生产误启动率。

固定128端点Clos、16服务器、8接入/8汇聚/4核心、单rail、400Gbps和每链路1µs。四组EP32，每rank每层8专家；15份不同R1-AWQ/MMLU路由（目标4/健康11），E256/Top8/H7168，原层3/4、连续两个Decode入口，不克隆原件。真实的是专家选择；计算、BF16布局、预先存在的等价完整模型/KV副本是声明，不是完整671B推理或硬件校准。来源身份沿用既有清单，新增十一份的远端版本未知。

normal不额外注入故障；local仍只在前20µs丢弃到GPU28的DATA，控制保留。故障由前轮最多首Dispatch接收字节目的地事前确定，SR和参考DCQCN不变，不按新结果增强故障。healthy备用仍4ms，两份原control只读并记录逐文件SHA。

至多四份新网络：fixed/guarded × normal/local，各一次。fixed用原格式/4在D启动完整备用；guarded用/5的源确认轮询，T为消息期限，127µs为绝对兜底。平台实现、原生后端、调度器、拓扑、全部primary图和传输配置一致；格式带来的guard记录/定时预算差异明确列出，不把它们说成纯单一时间参数。guard仅读取实际已发生的发送与源完成回调，不读故障、包路径、truth或未来完成。

轮询复用一个原生控制定时器。post不额外打断网络，故检测时刻可能晚于各消息自身期限；记录名义期限、实际检查时刻及延迟。全段结果提前完成才跳过备用；第一步完成不能代替结果。启动后必须完成两步、ACK、原图退休、真实KV释放；输家不取消，不伪造接收或确认。

竞争解释及判据：

1. 若guard正常不启动而fixed启动，分别报告节省的额外字节/声明计算/健康等待；这是信号相对于无条件早启动的作用，不能归为重传创新。
2. 若二者故障启动同刻且结果相同，故障加速来自早启动；若时刻不同，保留轮询延迟及实际竞争过程，不把效果都归给信号。
3. 即使目标更早，健康或网络收尾仍可能更晚。独立配对健康DATA逐跳驻留、全部阶段与必要前驱；包驻留总量不当作业务收益。
4. 源确认超时不证明专家算错、数据未到或硬件故障；输出检测事实，不推断未模拟的故障类别或安全保证。

独立检查从原件重建所有图、矩阵、计算、依赖和门限，核对实际源发送/接收/确认、逐包与队列完整性、原生定时/决策前缀和真实KV释放。guard检查另以不导入平台策略的读取器重建；对已保存原始事件和配置作篡改拒绝检查，不重跑网络。旧只读分析器的代码不改，扩展读取器保留复制来源SHA。性能正负均接受，不能弱化基线维持收益。
