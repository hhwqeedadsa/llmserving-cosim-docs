# 正常样本校准的完整备用：执行前方法

问题：上一轮两步任务在正常条件也于70µs启动完整备用。这里先建立正常样本校准的固定延迟基线，检查避开该误触发后，是否仍能更早交付故障任务，以及健康任务和网络收尾承担多少代价。不将门槛标定本身称为创新。

唯一规则：读取既有两步control-normal中目标call的完整结果时间T，门槛为`((T+999)//1000)*1000`ns，即按1µs向上取整；不读取故障结果来求门槛，不扫描候选、不调整余量。当前正常样本只有一次确定性执行，不估计p99、故障概率、分布稳健性或生产最优门槛。取整仅留不足1µs余量，不代表硬件时钟粒度。已有故障结果已知，不能声称盲测或独立留出集；规则与新执行前冻结，禁止结果后调参。

保持旧四条件的128模拟端点Clos、16服务器、8接入/8汇聚/4核心、400Gbps/链路1µs、单rail、四组EP32、E256/Top8/H7168/每rank每层8专家。15个不同真实专家选择原件，目标4份/健康11份，原层3/4、连续两个Decode入口；真实的是路由选择，BF16传输布局及计算成本是声明，不是完整671B推理或GPU测量。原四份固定修订与新增十一份用户目录确认/本地SHA分别记录，后者远端内容身份未知。

正常无额外故障；局部仅前20µs丢发往GPU28的DATA，控制保留，故障位置在前轮由第一步首层Dispatch接收字节选定。原SR和参考DCQCN不变。健康备用仍4ms，control两call仍4ms。平台继续在原生同一时钟上使用完整多步尝试；启动备用不等于业务完成，第一步不能当整个结果，输家实际完成并释放KV，不虚构取消或数值等价。

只新增校准门槛normal/local两次网络，各一次；旧control及70µs条件只读复用并冻结原文件哈希。准备通过公开`examples/scaleout_multicall/prepare.py`，正式网络通过公开`scaleout rdma-run`，独立分析读取保存结果。除目标门槛及来源清单路径重定位外，校准配置必须与旧输入一致；两种条件的协议/拓扑必须一致。全部图、原件矩阵、计算、阶段门限、包、源确认、原生定时/决策与KV由既有独立分析逐项复核，不用历史测试驱动流量。

竞争解释与判据：

1. 正常误触发解释：正常目标应早于门槛结束，备用跳过。实际包、健康任务时序、字节和收尾是否与control完全相同须检查，不能只看完成时间。
2. 完整重执行来不及解释：故障备用可能正常启动但比已推进的原尝试更晚。分别保留每步提交/完成、赢家、全部尝试结束和网络排空；不以某一层提前当作整任务收益。
3. 额外流量干扰解释：对照实际健康消息及包逐跳驻留、全部阶段门限，区分真正拖延与有剩余容量/活动无重叠。健康完成时间和全网包累计等待不是同一指标。
4. 单纯启动较晚可能减少健康干扰，却延后输家收尾；同时报告有效字节、含重传源字节、声明计算、备用KV及任务完成，不把不同单位加成净收益。

预算：新根`runs/calibrated_hedge_20261030`；累计600受监控秒/新增768MiB（运行与发布摘要合计）、保留8GiB；CPU每项120秒/RSS1GiB/地址2GiB。至多两个新128端点Clos网络，native各60秒/RSS1GiB/地址2GiB/模拟5ms/128MiB/包与队列各200000条；准备2048流/4096消息工作/131072执行事件。复用同二进制与8库，零构建/依赖修改/下载/安装/GPU。失败保留，不自动扩限或重跑成功网络。结果可为零或负；整体研究不以本轮交付标完成。
