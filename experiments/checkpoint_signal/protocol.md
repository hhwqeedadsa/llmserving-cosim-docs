# 在线检查点信号：执行前方法

承接正常完整两步门槛127µs无收益的结果。本轮仅检验更早的、正常样本校准的检查点是否已经能区分这两条历史轨迹；不据此宣称新算法、可达收益、生产故障检测准确率或最优门槛。旧故障结果已知，不是盲测。

固定读取`sequential_externality`的control-normal/control-local，128端点Clos、15份不同真实路由原件（目标4/健康11）、四组EP32、原层3/4、两个连续Decode入口，协议SR及参考DCQCN不变。不新增网络、缩小拓扑、修改故障或使用人工回放代替原始结果。旧四份策略对照及新增127µs条件不作为校准样本，不重跑成功网络。

三个检查点在查看本轮测量前固定：`g0.w0`首层Dispatch的完整EP GATE、`g0.w0`整图退休、`g0.w1`最终整图退休。每个deadline只从正常control的对应完成时间T计算`(T//1000+1)*1000`ns，确保严格晚于正常样本并消除同纳秒事件顺序歧义。只用一个确定性样本，不拟合分位数或生产概率，最多不足/等于1µs余量。只使用初始配置、初始已提交图中的节点身份和已知步数；不查看后续图的路由、未来字节数或计算时长来决策。

准备器按严格`event.time_ns < deadline`导出完整过去前缀`observed/`及最小过去事件子集；完整原始记录和事后完成时间留在`truth/`，判断器不得读取。两种观察比较：完整阶段所有32个成员的完成；一个执行前固定（最小rank）的相同GATE完成。图级检查点均只需已有`graph_retired`。另保留只看最终完整结果的简单判断，在同一个更早deadline比较正常误触发。判断输出仅为“检查点是否已完成、是否尚值得考虑备用”，没有发包或执行效果。

当前`ep_transport_flush/1`由原生服务在全EP成员到齐后零协调时延同步释放所有GATE，因此一个rank的GATE完成在本模型中即可代表这一已定义阶段完成。必须通过原始节点和阶段报告核对这一事实，不能将模型定义造成的等价称为新遥测压缩、分布式检测或节省生产监控成本。控制管道等待不推进仿真时间，缺少实际遥测/决策传递开销；这一检测结果仍是建模下界。

决策代码不得读取评价指标。事件前缀缺序、时间倒退、重复、未来/同刻事件或无效身份明确拒绝；最小过滤视图允许源sequence间隔，但保留顺序与真实身份。以移除无关过去事件、追加未来事件及关键事件篡改检查判断器的依赖范围。评价沿原始控制日志核对过去前缀、初始图身份、门限真实释放和整图退休；只有同纳秒未来事件被排除的结果才有效。

竞争解释：

1. “需要更复杂网络信号才能早判断”：若一个已有阶段完成标志与全成员视图一致，则本场景无需额外逐包资料即可做同一判断，不能把收益归给复杂映射。
2. “更早判断一定更快”：本轮不执行新增策略，任何deadline提前量仅为检测时刻差，不能当推理收益；原生网络竞争、完整备用成本和迟到工作必须后续实际对照。
3. “正常阶段已完成就永久不需要备用”：每个检查点只针对当前时刻；正常早阶段通过不代表后续不会故障，未来在线策略仍需完整任务或后续检查点的回退门槛。
4. “实时OBSERVE可用就能即时提交备用”：OBSERVE仅观察，不是DECIDE；现有定时唤醒可在预设时刻进入决策，未实现的阶段策略不能写成已有功能。
