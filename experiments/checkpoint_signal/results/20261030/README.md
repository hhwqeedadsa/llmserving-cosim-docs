严格只用检查时刻之前的回调，正常已完成/故障未完成可作不同判断。19µs比完整任务检查早108µs，但这不是推理收益。本轮不执行备用，不产生实际watchdog通知，零新增网络、构建、平台修改或GPU执行。

19µs时两条件32个pack均完成、26条首层Dispatch均已post。正常26条均接收/确认完成；故障有3条未接收/确认，消息37/68/99从rank4/8/12发往GPU28，各14,464B，post均为1.030µs。这证明已有已提交通信的等待信号，不证明仅凭超时能区分丢包与拥塞。

加强基线后，正常首层消息最大post到源确认跨度17.347µs，严格取整得到18µs消息超时；名义截止19.030µs，仅比阶段检查晚30ns。文档20µs示例则为21.030µs。两种参考都是正常0条、故障3条满足超时条件，无同刻歧义。它们是旧回调的已有机制触发条件核对，不是原控制真实发出的通知。当前完整备用禁止直接并用watchdog，通知本身不是DECIDE；真实联动仍需独立平台实现。

18次独立判断进程只获得计划与`observed/`，从不读取`truth/`或未来包路径；42项同刻/未来、重复、缺序、倒退和身份篡改拒绝通过。6种检查中，一个已知完成标志与全成员判断一致。首阶段单rank标志足够，是当前全EP到齐后零协调时延同步释放GATE的模型定义，不能当新遥测机制或生产监控成本收益。生产遥测延迟/丢失与真实完成语义仍待校准。

两份原控制的公开rdma-check通过、所有文件SHA保持。128模拟端点Clos，15份不同专家选择原件（目标4/健康11）、四组EP32、E256/Top8/H7168、每rank每层8专家、原层3/4、两个Decode入口。4份固定修订与11份目录用户确认/本地SHA分别保留；后者远端内容身份未知。计算、BF16传输布局、现成模型/KV为声明；不是完整671B、满载128卡、GPU实测或生产分布。没有p99、检测准确率分布、吞吐、经济收益或新算法收益。

下一步以成熟源确认超时/进度标志为基线，解决同一原生时刻的完整备用准入、一次触发、后续回退与资源清理，并实际比较目标、健康任务和额外流量。若已有简单方法足够，不再为检测信号开发复杂方案。检测提前量不能代替共享网络中的实际业务收益。
