# 源端确认超时参考：补充方法

检查点研究的原规则与判断器保持冻结。本补充只加强基线，依据现有`source_ack_watchdog`源码与文档，读取同两份控制的首个Dispatch消息，不启动或伪造通知，不作为新策略网络实验。

两个参数在计算本补充的结果前固定：一是现有用户文档给出的20µs示例期限（不是默认值）；二是仅以control-normal中首层Dispatch各消息的实际SEND post到源确认跨度最大值D为依据，按`(D//1000+1)*1000`ns得到正常样本校准期限。后者不读取故障跨度，不扫描余量，也不是p99。

对每条消息使用实际post时间加期限，检查严格早于该时刻的源确认是否已经发生。同刻确认单列为原生顺序歧义，不擅自认定会触发。比较两种期限下的资格、首个名义超时时刻及19µs阶段检查的时刻差。只计算已有机制的历史触发条件，不称实际发出SOURCE_ACK_TIMEOUT或能在过去提交完整备用。现有whole-call模式明确禁止直接并用watchdog，通知也不是DECIDE；真实联动需要另做平台验收。

完整控制没有启用watchdog，所以上述条件不能替代真实通知或恢复收益。参考只统计首个Dispatch的26条消息，不冒充整个778消息服务的通知计数/预算验收。源码、文档SHA及原始回调身份保留；与前轮CPU预算共用，不新增网络、构建或下载。
