# 单个备用提前与完整消费收益空间

研究对象为上一轮消息缓冲验收的两份128端点Clos结果：四份真实R1路由及独立人工输入。固定原执行，不新增网络或把改变策略后的时延补算出来。公开诊断工具见[接口说明](../../docs/contribution_frontier.md)。

初步查看真实首调用后已知，备用贡献比原件早62.002µs，而所有贡献到齐仍为93.669µs；这轮不是未见数据的事前研究。全面核查覆盖每份记录的16个层步调用，研究问题是：在原专家执行与其他通信时间保持为本次记录值时，已有备用是否改变最后结果就绪条件？若没有，则不支持“仅接入这个备用消费者就取得相应62µs加速”的主张。

方法为对全部预期贡献取原件结果时间最大值，以及对各贡献实际赢家再取最大值。必须保留并列尾部，检查与原生回调、实际GPU FIFO、阶段门限、实际merge及缓冲释放对应。单贡献提前、全集合提前、消费者合并时间、图退出分别解释；不累加不同请求的时延，不把固定记录的差值写成新策略反事实耗时。

`analyze.py`只调用公开`contribution-frontier`，再从其稳定输出独立核算最大值和缓冲缺口，生成精简的派生证据、PNG/SVG和HTML。输入仍为标记字节、声明计算、两层两步、四个稀疏源请求，不代表完整R1或硬件校准。生成方法：

```bash
PYTHONPATH=python OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  .venv/frontend/bin/python -B experiments/consumption_value/analyze.py \
  --real-run /path/to/real-route-run --artificial-run /path/to/artificial-run \
  --output /path/to/new-analysis
```

输出目录必须为新路径；子目录`diagnostics/`保存公开命令的完整派生输出，`delivery/`为可分享的精简结果。精简文件不复制路由原件或完整专家选择。

本轮绘图与解释程序按`PINNED_RESULTS`固定这两份已登记网络的结果SHA256，输入不匹配即拒绝，不把本轮文字套到不同实验。研究其他输入时直接使用通用公开诊断工具，再为新研究维护自己的方法和解释。

本轮结论见[网页](results/20261030/report.html)与[结果说明](results/20261030/README.md)。下一候选必须处理阻塞组的原始Dispatch完成条件，成熟SR/尾包探测及完整早备用均需保留为强基线。通用尾包探测或简单调低RTO获得的收益不得称新机制贡献。新的流式通信与原消费者不同，若研究该方向须明确新增库接口及正常/故障对照，不能通过删除既有门限获得“收益”。
