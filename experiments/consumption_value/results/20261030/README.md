# 固定记录中的贡献消费空间：本轮结论

[可读网页](report.html)、[派生证据](analysis.json)、[图](readiness.png)与[矢量图](readiness.svg)。平台工具提交`916038c21d`，开始方法`f1a7b54ed8`；输入为`98d5a10b95`消息缓冲验收的两个128端点Clos结果。初步数据已看过，不称为盲测或未见数据的事前实验。

**已有的单个备用没有提前完整贡献集合就绪。**人工与真实条件各16个层步调用，全部调用的固定记录前沿差为0。真实例备用r32在26.073µs返回，原件r32在88.075µs返回，单份早62.002µs；最后贡献是r68，93.669µs才返回，所以有无采用这个提前结果，固定记录的完整集合均需等到93.669µs。它不是移除备用后重跑的时延结论，也不证明所有未来策略都无收益。

两个条件都实际观察到备用赢家；它只是没有成为完整集合的最后决定项。真实条件R1/H7168/E256/K8，每rank每层8个专家；源层3、4及两个Decode步。128模拟GPU标签H100，20交换机、400Gbps/1µs逐链路，机内旁路关闭。真实的是四份R1-AWQ/MMLU专家选择，计算为声明值、字节为标记，没有真实H100执行、完整671B或生产吞吐验证。

真实首调用r68的输入10.146µs到达，实际专家任务85.504µs才入队并立即开始。其Dispatch门限晚于全部其他直接前驱，GPU FIFO等待为0；r56/r64/r72/r76也受同一门限限制。备用计算/结果没有替代原Dispatch的源确认，因而没有解除组门限。全记录111份贡献包使用位置均核对该门限为最后前驱，这个计数不是111个不同GPU或111段可相加的独立损失。

备用结果目标范围28.075µs按既有helper退休规则释放，完整集合93.669µs才齐。现有功能模式没有消费数据，释放合法；未来若到集合汇合时仍读取该范围，至少需多保留65.594µs，后续排队与计算还未计入。立即复制或增量归并到独立累加器也可改变原范围寿命，但需单独建模容量、归并成本、数值顺序和回收。这不是已发生的越界读或上游漏洞。

首调用全部贡献到齐与原merge开始之间还有6.328µs，但它是实际依赖/同步间隔，不是已证明可消除的收益。独立消费者若改变此间隔，必须对有无备用采用相同消费者作比较；不能把消费者或新的通信语义带来的效果归给这次单备用。

本轮没有继续增加一个预计无前沿收益的单备用消费者。下一步先补齐成熟的快速探测/较短RTO参考，检验直接推进原始Dispatch确认是否已经解释主要空间，再判断按通信组完成进度分配恢复预算是否有额外价值。任何改进都要同时报告正常误触发、目标请求、健康任务、字节、计算和缓冲开销；通用重传提前的收益正常归于强基线。新流式库可作为独立方向，但需要明确协议与安全消费接口，不能删既有门限来制造加速。
