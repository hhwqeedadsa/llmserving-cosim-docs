# 链路失效是否拖慢没有直接丢包的专家通信

状态：执行前登记，2026-10-24；平台基线 `c8627e8`。本阶段为研究，平台不改，不导入测试、fixture或历史实验驱动。

## 问题与竞争解释

在常规最短路/ECMP收敛及原生NACK、固定/Karn超时恢复下，链路关闭是否仍延迟没有直接丢包的流？如果有，先辨别路径改变、共享队列/流控、拥塞速率历史和源端重传。普通改路、经典重传或定时器调参不是创新。

1. 直接丢包足以解释：只有丢包或经过关闭边的流变慢，其他流没有额外等待。若不直接经过故障边且无丢包的流也变慢，此解释不足。
2. 共享网络外溢：未直接丢包的流也改变完成时间，并实际共享积压端口、收到拥塞通知或PFC。共享/相关性只是机制线索，不能直接算作可消除损失。
3. 超时误判：无故障也重传，或固定/Karn改变健康流的重复字节及完成时间。必须同时报告无故障强基线，不能把假超时收益当故障恢复收益。
4. 人工源额度：深度1024大于全部每流工作数，检查每工作ready=published=0；若不成立，不把发送前等待当网络排队。

## 观测、独立检查和停止

全图全时段包钩子（最多100,000条，必须完整），包含实际包头；全部端口队列积分、末态MMU、源速率（最多20,000条）、真实ACK/接收回调、恢复和独立CNP事件。按列名读取，UID仅为谱系，不能当独立传输；TX/RX必须按物理边、包与出现顺序配对。丢包流、无丢包但路径改变的流、基线路径不含故障边且无丢包的流分开报告，不把“没有数据丢包”等同健康路径。

## 判定边界

本轮可证实小窗口内的事件与差异，不能证明生产收益、主贡献、控制延迟真实性或千卡扩展性。若出现外溢，后续必须有更强机制消融、完整业务依赖及代表性/校准证据；不能直接开发一个只对当前参数有利的策略。
