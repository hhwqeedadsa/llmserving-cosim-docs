## 背景：MoE 推理通信的丢包恢复方法谱系

| 层次 | 代表方案 | 丢包处理机制 | 与本实验的关系 |
|---|---|---|---|
| 链路/网络层：无损化 | InfiniBand credit 链路流控；RoCE 用 PFC（按优先级暂停）+ ECN 阈值 | 设计上假设"不丢包"：接收 buffer 满前反向停发，把丢包当硬件错误而非常态 | 本实验直接注入丢包，正是检验无损假设失效后的协议行为；PFC 自身有队头阻塞/死锁/风暴问题，是"无损化"路线的已知代价 |
| 传输层重传：Go-Back-N | InfiniBand RC、RoCE RNIC 基线（Mellanox/NVIDIA 传统实现） | 累计 ACK + NAK 指出缺口序号，发送端从缺口起整体重发；超时兜底 | 本实验原生模式与 go_back_n 扩展都是此语义；"57% 与 86% 代价相同、3× 重传放大"是它的直接后果 |
| 传输层重传：选择性重传 | IRN（SIGCOMM'18，SACK 式只补丢包）；新型 RNIC 的乱序放置 + 选择性重发 | 接收端记录到达位图，只重传真正丢失的包，不要求底层无损 | 正是为消除图 2 展示的放大：86% 丢包下选择性重传只需补 6 包而非整体回退两轮 |
| 传输层：多路径与乱序容忍 | MP-RDMA（NSDI'18）；AWS SRD/EFA（NSDI'20，可靠数据报 + 多路径喷洒 + 乱序交付） | 单包级多路径分散，乱序到达直接放置，丢失只重传单包 | MoE all-to-all 高扇出、短消息，最能从不保序中受益的形态；本平台当前为单路径保序 QP |
| 超时估计 | 固定 RTO；Karn/Partridge 采样 + RFC6298 平滑；Swift（SIGCOMM'20）精确时延测量 | RTO 决定"等多久才认定丢失"；过短放大重复流量，过长拖延恢复 | 对应 recovery 扩展的 rtt_estimator=karn；本实验固定初值 40µs，恢复代价≈1 个 RTO，正比关系直接可见 |
| 拥塞控制与丢包信号 | DCQCN（SIGCOMM'15）；Timely、HPCC、PowerTCP 等 | ECN/时延/带内遥测降速，尽量避免丢包发生；丢包仍被视为严重信号 | 本实验固定原生 DCQCN 不变，隔离丢包恢复单一变量 |
| 集合通信库 | NCCL（通道故障切换、重试）；DeepEP（EP dispatch/combine，RDMA RC QP，低时延/高吞吐双模式） | 库层一般不自带恢复算法：依赖传输层可靠性，失败沿 QP 错误上抛，由框架决定重连或放弃 | 本仓库 hybrid/GIN 系列筛选已核过 DeepEP 完成机制；本实验对应"库下层协议"的行为 |
| 服务系统层 | PD 分离 KV 传输（Mooncake、NVIDIA Dynamo/NIXL、vLLM 连接器）；请求级重试/重路由；副本冗余；引擎重启 | 单请求失败由调度层换实例重算，不要求单条连接必然恢复；用隔离域限制爆炸半径 | 本实验中独立 EP 组（组 1）在组 0 停滞时两轮照常完成，正是隔离域价值的微观对照 |

本仿真器原生模式 = 无损假设 + NACK 触发 go-back-N（无有界超时）；可选恢复扩展 = go-back-N + Karn 自适应 RTO + 有界重试显式失败。三个观察分别对应三个工程取舍：整体回退放大是选择性重传（IRN 等）存在的理由；静默停滞说明有界超时是必要件；ACK 掩盖说明累计确认自带确认路径容错。库层与服务层（请求级重试、隔离域）是传输层失败之后的两道防线。

## 本周期工作与丢包处理现状

- 环境能力（本周期范围）：Scale-Out 推理全链路 `rdma-run`（LLMServingSim 组批 → ASTRA → 原生 RDMA 逐包执行，含 DCQCN/PFC/ECN）；`rdma-build` 锁定原生 `e929264` 现场构建（本周期修复其构建登记的 str/Path 哈希 bug）；`rdma-diagnose` 诊断与全节点逐包捕获。未触及 UB 侧。
- 丢包注入：`FaultModel` 精确规则（≤32 条、每条 ≤10,000 次）+ `drop_once` + 永久断链；已知缺口：不支持全网随机丢包率，需比率型规则与原生重编译。
- 丢包恢复（实测）：原生 = NACK go-back-N 无超时兜底（两轮丢包后静默停滞至 5ms）；可选 `go_back_n` = Karn RTO + 有界重试显式失败（+39.5µs 恢复或 444.2µs 干净失败）；恢复耗尽即整体停止、不伪造成功，独立 EP 组不受影响，单 QP 隔离未实现。

## 新增能力方向（由本实验证据驱动）

| 新增方向 | 解决什么 | 依赖与工作量 | 证据锚点 |
|---|---|---|---|
| 全网比率型随机丢包 | 回答"DCQCN+PFC 在真实丢包率（0.1%→50%）下的表现"，支持丢包率扫描找拐点 | FaultModel 增加 rate 规则 + 一次原生重编译；规则预算从 32 条精确匹配改为比率模型 | 本实验 README/protocol 已声明该缺口；当前 57% 是单消息确定性规则 |
| 选择性重传参考实现（IRN 式 SACK） | 直接量化图 2 的 3× 整体回退放大能省多少：86% 丢包下只需补 6 包而非两轮全量 | 作为第二种可选 recovery.mode；接收端到达位图 + 只补缺口序号 | 本实验 57% 与 86% 同代价（91,297ns / 18,432B）即其存在理由 |
| 单 QP 错误隔离 | 恢复耗尽只终止该 QP 并让服务层重路由，而非整体停止共享仿真 | 文档中已列为未实现后续项；需定义错误传播边界与依赖清理 | 本实验组 1 在组 0 停滞时两轮照常完成，证明隔离域价值；缺的正是 QP 粒度 |
| Karn 自适应 RTO 的重度丢包对照 | 固定 40µs 初值 vs 自适应采样在 50%+ 丢包下的恢复代价与重复流量差异 | estimator 已实现（rtt_estimator=karn），只需在本实验条件族上启用对照 | communication_fragility.md 命题 3 已证明采样无歧义；缺重度丢包场景实测 |
| 多路径/乱序交付（MP-RDMA/SRD 语义） | MoE all-to-all 短消息高扇出，最能从单包级多路径与不保序放置受益 | 拓扑生成已支持 multi-rail/多平面；需 QP 乱序放置与逐包路径选择 | 谱系表第 4 行；本平台当前为单路径保序 QP |
| PD 分离 KV handoff 大流量 + 丢包 | KV 传输是长消息，Go-Back-N 放大比 6KB Dispatch 严重得多，是更真实的受害面 | M4 已有 kv_handoff 提交类型与容量账本；复用本实验的故障注入即可 | 本实验 3×/5× 放大在小消息上已显著，长消息预期更陡 |

边界：单消息确定性逐序号丢包，非全网随机丢包率；声明计算、合成路由；失败仅指 5ms 窗口内未完成。详见 [protocol.md](../../protocol.md) 与 [README.md](../../README.md)。
