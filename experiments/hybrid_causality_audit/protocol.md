# Hybrid 转发的静态因果表示是否足够

2026-10-27；平台固定 `19670ba`。前一轮机内转发是平台准备，不能作为创新。本阶段是独立的逻辑研究，不重开旧网络/规模/性能实验，不修改平台或依赖。

## 要判别的前提

固定 DeepEP `f6aa38fe06cd4a0489e7730365d4e0114970a2f3` 的 Hybrid Dispatch：转发器按轮询顺序选源，选中后等该源，缓存 tail/finish 只在等待时刷新，每次消费最多6项；发送端每6项发布tail，最后单独finish。网络到达可以改变等待，但是否必然改变数据消费顺序尚未得到证据。

竞争解释：

1. 输入已知各源通道长度和有序token后，含tail/finish门槛的普通静态DAG已经足够表达单转发器的逻辑准入；动态轮询只增加零工作的内部步骤。若成立，不把该规则或其DAG实现当独有创新。
2. 缓存刷新/结束标志使某些合法到达次序改变有效消费顺序或准入门槛，静态串接会过约束或错误放行。找到反例即保留，不修输入或弱化比较。
3. 只有满足进度粒度与消费粒度的条件才能约简；条件失效时需要回退。即使成立，也不是新的完整网络/调度理论，仍需与普通静态/惰性DAG及已有方法比较成本。

候选静态参考事前固定：每源通道切成完整6项数据块；余数块由finish放行；恰好整除或空通道另有零数据finish门槛。按源循环顺序合并这些块/finish门槛，块之间串行。块由其首次满足前缀的发布放行。允许擦去已可用的零工作finish/轮询步骤，不能删除未到达finish的等待。

## 覆盖、输入与观测

- 只研究一个forwarder的有序数据块与阻塞门槛，无轮询/计算耗时、warp并发成本、GPU最终slot、Combine、网络时延或报文执行。外部允许任意合法发布顺序，以及任意消费尝试时刻；数据可见须先于释放其前缀的发布。
- 源级有限状态核查不导入平台执行器。独立转录缓存轮询状态机，与不含缓存的固定块序列/门槛DAG同步接受“一个源的下一发布”或“一次消费尝试”。枚举所有可达不同联合状态；重复无变化的等待不展开。比较下一有效数据块、消费前缀、结束和阻塞源，保存最短反例。
