# 真实专家选择下的局部短时故障与共享网络

2026-10-30事前登记。用户选择局部短时故障，观察对其他任务的拖累。平台前置来源补丁`d22491608f`；网络复用固定原生程序/依赖，不改算法，不重开旧逐消息GBN或RTO调参研究。研究执行前保存本文件、程序和生成输入的hash。

## 问题与竞争解释

1. 损失局限于目的端：热点接收端丢包，但另一个EP组不变或更快。没有正外溢也如实收尾。
2. 恢复干扰共享网络：未直接丢包的另一个EP组出现额外等待，同时有真实共用的有向端口、积压/服务及反馈变化。共享路径和时延相关不能单独证明全部额外等待可消除。
3. 发送机会与重试预算不匹配：超时请求增加但未实际发包，应核对源TX、ACK进展、参考控制器和节奏门限；恢复请求数不当作实际重传包数。
4. 基线差异：SR的缓存、反馈16B扩展和选择重传均是机制成本。GBN/SR的差不是新算法收益；不得混用不同拥塞控制或把发送窗口限制当作恢复收益。

- 从用户已确认R1-AWQ/mmlu目录、既有intake合格清单中，按数字文件名升序取前8份，不复制、不按网络结果筛选。原始完整文件SHA、目录、结构检查保留；下载revision未知，显式标记`user_provided_model_routes`，不冒充已核远端版本或独立留出。
- 模型路由保持E256/Top8/H7168，原层3、4、Decode入口1、2，初始KV就绪；激活2B是实验假设，不由AWQ权重精度推出。全部请求到达0、每rank一个、两步两层。计算沿用公开小例的声明成本，不是生产到达/完整61层/实测GPU。
- 8个H100标签、4服务器/2Pod，每服务器2GPU；两个逻辑EP4组`[0,1,4,5]`和`[2,3,6,7]`均跨Pod，各rank每层64专家。只模拟有限通信段，不声称完整671B权重及KV在EP4上可部署。
- 单rail/plane，单ToR/Pod、单Agg/Pod、单Core，100G接入/25G上层，每链路1000ns、缓存8MiB，固定seed11。ECN100G=32/128KiB、25G=16/64KiB、pmax1；不是硬件校准。无机内旁路，声明NIC均1。
- 全部24个组内有向持久连接，端口21000+stream id、queue_depth32；payload/chunk9000B，逐包ACK。相同独立DCQCN参考：NP50us/alpha55us/recovery55us、10MB、min100Mb/s、AI5Mb/s、HAI50Mb/s、F5、g1/256、CNP48B。
- GBN/SR共用初始RTO80us、最大640us、3次无进展重试。SR窗口1MiB、每连接接收容量1MiB+8999B；准备必须证明每连接**全部计划工作**总字节小于窗口，不能只凭末态判断窗口没限制。SR每24连接总配置接收上限约24MiB，实际峰值另报。GBN无乱序缓存；不得把这称等内存比较。
- 热点由组0第一步第一层的原始远端Dispatch入量最大rank选择，并列取最小rank，在运行前冻结。局部故障仅该GPU的目的数据，在`[0,100us)`全部丢弃，重传也受影响，控制包不丢。它是端点接收故障注入，不是物理共享上行关闭或自然拥塞丢包。

## 四个条件及评价

`gbn-normal / gbn-local / sr-normal / sr-local`，各最多一次，同一原生ns-3实例同时调度两个组，网络/队列持续存在。相同工作量、源位置、路径绑定、成本及控制器；仅恢复机制或局部故障改变。全部计划图先独立生成并逐token核算，实际图须完全一致。所有失败保留，首个失败停止后续网络，不扩限救活。

主指标：声明服务整段完成，以及未直接故障的组1完成时间相对同恢复normal的变化。另报组0、逐图起止、消息就绪到接收/确认、实际源数据包/重复字节、超时、目的端丢弃、交换机自然丢弃、CNP/PFC及共享有向出口的服务。组1上一步结束变晚会推迟下一步提交，须区分进入网络前等待与本次通信时延。

分别恢复组0/组1第一步第一层Dispatch累计源TX、去重到达、连续有效接受、源确认曲线；输出逐消息数据及完整抓包原件位置。公开`rdma-check`核验实际调度、依赖、资源和字节；公开`data-loss-check`核验注入命中；分析用稳定读取器，独立核验再从原JSON重算贡献矩阵和源发送区间。至少拒绝工作量、故障位置、完成时间、源发送计数、输入hash五类篡改。图退休、计算消费、源ACK、网络排空分列，不换算真实推理收益。
