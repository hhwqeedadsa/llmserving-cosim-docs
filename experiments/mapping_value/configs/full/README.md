# 完整首轮参考输入

本目录规定最后的代表性完整场景。来源必须是 `reference.json` 固定摘要的完整原生首轮数据包；大文件未随 Git 分发。已有机器上的对应包为 `runs/v04-platform/m16-target-slice/`，迁移机器需取得完整包并保持内容不变；参数依据与来源限制见 [CM384/R1 场景](../../../../docs/scenarios/cm384_r1.md)。小场景不依赖该包或真实数据账户。

| 项目 | 选择 |
|---|---|
| 模型、请求 | 128 rank、1024 个独立真实路由来源、61 块、隐藏维度 7168；256 路由专家、Top-8、每 rank 两个；只执行第一个 Decode 入口 |
| 初态 | 复用核验后的已就绪 KV 和首轮依赖图；重放不重新执行请求接纳、调度或构图 |
| 网络与资源 | 保留完整 48 服务器、七平面物理网络；原生 STORE/LOAD、逐包喷洒、CBFC、worker=1、4096 B 载荷、8192 B 分块、seed/run=1 |
| 物理对照 | 正常、出口 768:16 的 112 Gb/s 与 56 Gb/s；干预时段由新正常参考第 31 层确定，在异常运行前冻结 |
| 观测 | 固定 42 个 L1/L2 出口；10 µs 基础窗口、[0,100 ms)；队列和阶段开启，保留五类应用来源，不保留逐包详细区间 |
| 增强队列 | 固定六个出口：768:16、769:16、770:16、817:16、1104:0、1104:7 |
| 时间规则 | 操作变化容差 10 µs；整轮实质影响为 max(100 ns, 正常整轮时间×0.001)；各组时钟准确且相同 |
| 运行上限 | 每次完整后端 RSS 48 GiB、地址空间 56 GiB、7200 宿主秒；导出 RSS 8 GiB、地址空间 12 GiB、1800 秒；至少保留 20 GiB 磁盘空闲 |

以下命令核验包内全部文件摘要，检查模型及原生范围，生成独立网络、观测与重放配置，并计算展开与记录预留；**不展开图、不运行完整仿真**：

```bash
python -m experiments.mapping_value prepare-full \
  --slice runs/v04-platform/m16-target-slice \
  --backend build/default/output/cosim/ns3.44-cosim-service \
  --output runs/mapping_value/full-input
```

`preflight.json` 中 `ready_to_run` 才表示当前估算满足资源条件；命令本身成功只表示输入准备与预检完成。预算不足时保留差额和配置，不自动改预算、删除旧数据或启动后端。累计预算当前为 48 GiB，包含已登记的新旧根。图展开使用一个共享 `graph-cache/`，后续对照复用；记录、导出与分析预留分别为 2 GiB，这些是预留而非未来实际用量。

通过资源检查后，可使用生成的 `replay.json` 交给公共 `moe-ub replay --slice … --config … --output …`，输出必须为新目录。完整场景的执行与验收状态只见[当前任务](../../../../docs/tasks/current.md)，研究结论只见[结果记录](../../results.md)。旧包的 100 µs 聚合窗口不能细分成 10 µs，本配置要求新一次后端执行。

完整场景只延伸少量代表性网络对照。端侧成本、应用同步机制和重叠负对照先在小场景中检验；不重复完整前端、不展开全部组合，也不将结果称为目标硬件校准。
