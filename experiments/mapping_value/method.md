# 当前分析与评价规则

研究问题和允许输入以[实验说明](README.md)为准。本页描述 `candidate-evidence-v1` 实际使用的规则，解释输出可以支持什么判断；不承担任务进度或运行日志。

## 公共参考与调用选择

所有条件得到相同的拓扑、名义速率、端点位置、固定 EP 组、端侧区间与阶段，以及同口径正常参考。第一批使用准确的共同纳秒时钟。各 rank 的正常与当前记录按公开的本地编号及调用类型比较；只支持固定单轮、相同调用序列，编号集合或类型不一致时拒绝比较，不使用内部身份帮助分析配对。

锚点为 EP 组最小 rank。分析选择该 rank 最早出现持续时间增加或完成后移超过 100 ns 的调用。没有这样的调用时不暗中通过真值选择其他调用。准备程序为每个全局逻辑调用找到唯一锚点记录，投影该调用在全部已声明端口与窗口中的正业务字节关系；不按锚点的局部起止裁剪其他 rank 的贡献。状态扩展条件另并入三类真实应用状态，始终去掉字节权重和内部编号。

## 候选与判断

端侧证据来自同一局部调用的 `prepare_end - prepare_start` 对正常参考的增加。超过容差的 rank 列为优先检查的端侧候选；操作整体变慢但准备持续时间未增加，不能直接判为端侧准备成本增加。

E2 及以上统计每个出口在整轮捕获范围内相对正常参考的逐窗整包字节绝对差之和。零值只在已声明范围内补齐。发生变化的出口列为待检查的流量变化位置；这本身不能证明出口服务变慢，因为端侧准备后移同样会改变包的时间分布。无映射条件可以使用全部公开时间与拓扑，本规则没有禁止这些信息。

E3/E5 使用正常与当前的理想二元关系并集，只在上述流量变化候选中标出与所选逻辑调用有关的出口。`port_candidates` 保存这一调用范围，`all_changed_ports` 保存原始变化集合，`excluded_from_selected_call` 保留每次缩小的依据。没有业务关系只表示不属于该调用的已观测业务路径，不能排除上游依赖或应用状态造成的影响。因此该集合不宣称包含所有整轮根因。

E4/E5 在固定六个出口上汇总各窗口 VOQ 与 FIFO 等待均值的正增量，作为排序证据。未开放队列的出口保留为未知，不能因缺少队列证据而排除。接口同时提供峰值，但当前排序不使用峰值。变化位置和队列增加均可能是依赖传播的结果；除明确的准备阶段持续时间证据外，程序保留 `unresolved_wait` 或 `unresolved_wait_with_network_changes`，不把关联写成已经证明的因果位置。

## 局部时间与整轮时间

分别保存每个局部调用的持续时间差、开始后移和完成后移。后继同时后移不累计成多份损失。分析可见的末个端侧操作完成时刻只作为整轮影响的代理指标，不等同于模型全部计算完成。

评价程序独立使用实际 `service_finished_ns` 计算整轮差值，阈值为 max(100 ns, 正常整轮时间×0.001)，同时保留未经阈值化的纳秒差。评价用内部操作身份配对局部记录，不将这些配对交给分析。运行、参考、设计、干预和受限输入摘要必须相互匹配。

物理服务区间与观测窗口预先对齐。评价按实际分类来源记录判断区间内是否经过应用业务或状态、是否命中所选调用；存在限速配置不自动标为性能受损。只有控制包经过的情况不能由应用来源推断为“没有任何包”。报告候选数量时一起报告真正受干预出口是否被错误排除、未确定判断及局部变化但没有实质整轮影响的情况。

同一首轮的 32 个请求共享一次执行，不能作为 32 份独立运行统计。五种信息条件也不是五次物理仿真。后续方法若改变，应另记版本并对同批数据重新分析，不能将规则变化的收益当作映射收益。
