# 映射价值实验结果

本页只记录已获得的结果与限制；研究方法见[实验说明](README.md)和[分析规则](method.md)，命令见[使用方法](usage.md)，批次状态见[当前任务](../../docs/tasks/current.md)。

## 首组成对检查（规则 v1）

使用独立 8 rank、32 请求、4 块配置、原生 STORE/LOAD、最短路喷洒和 CBFC。正常参考为 41,376 ns。冻结的第一项干预在 rank 3、第 2 个 MoE 层增加 353 ns/本地 Token 的 Dispatch 准备成本，4 个本地 Token 合计增加 1412 ns 的工作。

| 运行 | 实际整轮时间 | 对正常的差值 | E1–E3 判断 |
|---|---:|---:|---|
| 正常 | 41,376 ns | 0 | 没有超过容差的端侧变化 |
| 端侧准备增量 | 42,061 ns | +685 ns | 三组均将 rank 3 列为准备成本增加候选 |

在这一个样本中，E2 与 E3 都保留 32 个变化出口，映射未缩小所选调用的业务候选范围。端侧增加的工作量与整轮损失也不同，不能直接把额外计算成本写成整轮时延增量。这仅是首组成对机制检查，不是完整 A/B/C 或目标规模的结论。

证据位于 `runs/mapping_value/batch1-v2/`：`r000/`、`r001/run/` 保存平台运行，`frozen/` 保存干预，`r000-prepared-v1/`、`r001-prepared-v1/` 保存受限输入，`analysis/` 与 `evaluation/` 保存 E1–E3 结果，`experiment-commands/` 保存实际命令、退出状态与日志。大文件不随 Git 分发，按使用方法可从版本化小输入重建。

初次输入预检在 `runs/mapping_value/batch1/` 因缩小模型的 KV 池超过声明块数而停止，未运行网络；修正设备容量为权重、预留及 1024 块之和后，在新目录完成以上执行，没有提高宿主预算。计算成本为声明参考值，尚未校准目标硬件。

## A：端侧准备与出口服务（统一规则 v3）

规则 v1 只按出口集合筛选，随后补充窗口关系、无映射组的公开时间与次序推断，并修正仅看锚点自身会遗漏其他 rank 延迟的问题。以下六项均使用相同 v3 规则重新分析原执行，没有因方法变化重跑网络；中间 v2 输出保留在运行目录，但不与 v3 混合计算增益。

| 对照 | 整轮差值 | E2 候选出口 | E3 候选出口 | 受限出口是否保留 |
|---|---:|---:|---:|---|
| 正常 | 0 ns | 0 | 0 | 不适用 |
| rank 3 准备增加 353 ns/Token | +685 ns | 32 | 25 | 不适用；端侧候选为 rank 3 |
| rank 3 准备增加 1762 ns/Token | +6710 ns | 32 | 25 | 不适用；端侧候选为 rank 3 |
| 出口 8:4 限为 112 Gb/s | −5 ns | 32 | 32 | E2/E3 均保留 |
| 出口 8:4 限为 56 Gb/s | +381 ns | 32 | 28 | E2/E3 均保留 |
| 空闲时段的出口限速 | 0 ns | 0 | 0 | 无应用命中，也没有误判端侧异常 |

整轮实质影响阈值为 100 ns。112 Gb/s 对照确实命中应用流量，但 −5 ns 的整轮变化低于阈值；相同 seed 不强制时序改变后仍走相同逐包路径。56 Gb/s 对照中，映射缩小了所选调用的出口范围，尚不能把剩余 28 个出口中的一个宣称为已经定位的唯一根因。端侧组的网络范围缩减也不代表出现了网络根因。

E1–E3 均能用准备阶段持续时间识别两个端侧增量。两个网络对照没有被误称为端侧准备成本增加，但算法保留网络等待原因未确定的判断。E1 未得到网络观测，其出口定位指标记为不适用，不能把空候选记作成功排除全部出口。

物理运行在 `runs/mapping_value/batch2/r002/` 至 `r005/`，正常及第一端侧运行沿用首批。统一评价在 `batch2/assessment-v3/`，实际命令在 `batch2/commands/`；13 项人工检查日志在 `batch2/checks/`。这些是同一固定工作负载的机制对照，不构成独立随机样本的统计显著性证明。

## B/C：局部变化、状态尾段与重叠

强端侧对照的最大局部持续时间增量为 6237 ns，最大局部完成后移为 8595 ns，实际整轮增加 6710 ns。另有 5 条局部调用完成后移超过 100 ns、持续时间变化却不超过 100 ns。这些后移不能累加为整轮损失。

正常第 2 个 MoE 层 Combine 中，各消费者的最后一条远端应用状态就绪，晚于其最后一条远端业务数据就绪 92–363 ns。这是实际消息与回调形成的尾段，没有加入轮询；本核算只涉及网络交付，不能据此断言同芯片数据和计算资源也已经全部就绪。

| 新对照 | 冻结的物理干预 | 整轮差值 | 观察 |
|---|---|---:|---|
| 状态窗口 | 出口 8:0，27.4–27.5 µs，56 Gb/s | +6 ns | rank 0 的远端状态尾段由 92 增至 99 ns；局部变化低于声明容差 |
| 同一出口业务窗口 | 正常同调用业务字节最多的 100 ns 窗口，56 Gb/s | −11 ns | 最大局部持续时间增量 1220 ns，但没有实质整轮损失 |
| 重叠负对照 | 保留弱端侧增量，在出口 8:0 的 15.6–15.7 µs 另加限速 | 相对端侧单干预为 0 ns | 区间实际没有应用消息命中，算法没有把它认作新增异常 |

状态窗口对照中，E3 与增加应用状态关系的 E3S 都未给出超过容差的异常；不能声称状态关联在这个样本中改善了定位。业务窗口对照中，状态关系将候选从 31 个扩为 32 个，也不能直接将更大的关系集合视为更准确。真实状态尾段的存在与分析方法是否取得收益是两项不同证据。

上述三次执行在 `runs/mapping_value/batch3/r006/`–`r008/`；`frozen/` 保存正常选窗依据，`effects/` 保存真实业务/状态就绪时刻及局部差值，`assessment-v3/` 保存比较。重叠组以既有 `r001` 为参考，只移除网络干预，未把组合损失简单相加。

## E4/E5：少量队列增强与最终小场景汇总

九次物理执行分别生成 E1–E5 和 E3S/E5S，共用原先采集的记录，没有为信息条件重跑网络。最终一致版本的逐对照摘要保存为 [results-small.json](results-small.json)，完整输入与评价在 `runs/mapping_value/batch4/`。其参考投影跨对照经摘要核验后硬链接复用，正常自对照也不复制第二份。

56 Gb/s 出口对照最清楚地分开了两类信息作用：

| 条件 | 候选出口数 | 受限出口的排序位置 |
|---|---:|---:|
| E2：端侧与端口计数 | 32 | 5 |
| E3：再加业务映射 | 28 | 4 |
| E4：计数加少量队列 | 32 | 1 |
| E5：队列加同一业务映射 | 28 | 1 |

这里映射缩小的是所选调用的出口范围，队列信息改善的是候选排序；不能把队列收益记作映射收益。第 1 位也只是分析排序，并非已经证明唯一根因。所有对照均保留正常、无应用命中、没有实质整轮影响和未确定判断；该固定工作负载下没有将实际命中的所选调用受限出口错误排除，但样本不足以推出一般准确率。

人工研究检查现为 17 项，补充了未声明成本/后端/路由变化拒绝以及硬链接累计空间核算。软件行为检查、合成输入机制结论、完整真实输入来源和硬件校准分别记录。
