normal不注入额外故障；local仅在前20µs丢弃到达GPU28的DATA，控制包保留，两条件均保留同选择性重传/参考DCQCN。control的目标/健康备用期限均4ms，本轮都没有触发；treatment仅将目标改为70µs。

故障目标少等5.048µs（3.72%），但总有效通信由5,570,752增到7,100,544字节（+27.46%），总声明计算由59,600增到75,380ns（+26.48%）。这两个总量包括健康任务；目标自身执行双份工作。实际源端DATA载荷为5,614,144和7,143,936字节，两者均额外重传43,392字节、故障丢6包。网络收尾晚459ns。四条件均实际预留备用KV46,792,704字节并按各call生命周期释放，最终0。

健康任务69.995µs完成，比目标备用70µs启动早5ns，比备用第一包进入交换机72.211µs早2.216µs。虽有71个共同出口，但数据活动未重叠。两条件健康任务的2,136个交换机经过全部配对，驻留增量均0；源注入/消息接收确认/计算节点/阶段门限时刻相同。正常条件两策略完整包记录及原始队列事件完全相同。

这是没有观察到健康任务干扰的负面结果，不能写成证明备用在持续服务中没有干扰。它也不是新算法收益。下一步需支持独立请求持续到达或自然多步执行，事前固定方法后检查实际共享时间窗；不能对本轮门槛、负载或故障寻优来制造干扰。

规模为128模拟端点、四组EP32，每rank每层8专家，正常数据活跃56rank、故障备用81rank。15份不同R1-AWQ/MMLU专家选择原件分为目标4份/健康11份，仅原层3/4、首Decode入口、一个Decode步。原4份有已核验固定版本身份，新增11份仅用户确认目录与本机SHA，远端修订未知；两份缺层文件排除。备用清单不增加独立原始请求数。前端由原件生成有依赖的声明计算和Dispatch/Combine，后端生成ns-3模拟包，不是R1运行时抓包。

固定计算成本、BF16消息布局、预先完整专家与等价ready-KV均为声明，不是GPU校准、完整671B执行或数值验证；没有持续到达、吞吐、SLO和经济收益结论。旧两组EP64结果不是本轮EP32部署的数值对照。
