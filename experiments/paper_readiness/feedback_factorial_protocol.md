# 短时 MoE Dispatch 的拥塞反馈分因素对照（执行前固定）

平台固定为`591c62a`，不修改后端、固定依赖或默认参数。本轮检验反馈抽象是否足以影响源端并发建议，不提出新算法，也不以此前失败的完整 Prefill 为调参目标。

输入为已核 hash 的四份 R1-AWQ/MMLU 路由，按 manifest 顺序各取 entry0、层4的前6个 token。6是四请求共同可用的最大前缀长度，保留原专家选择，不复制 token。这是均等长度的已见数据窗口，不是独立留出或完整 Prefill。连续等容量放置 expert_id//64，EP4、H7168/E256/Top8；每 token 按远端目的 rank 去重，每份14,464B。BF16/direct 打包是源码建模假设，不是原采集 dtype 证据。仅 Dispatch 数据，所有根工作声明0ns就绪；无计算、Combine、现代控制或真实到达过程。

8端点小Clos，逻辑rank→GPU0/2/4/6，接入100G、上层25G、链路1us，seed11、12条持久QP和固定wire port。ECN沿用32,768/131,072B、pmax1；不降低阈值制造拥塞。全部条件使用同一`figure7_reference/1`机制，每条件一套Simulator；不混用旧ACK反馈模式。

固定完整2×2×2×2共16条件，按下列顺序的笛卡尔积执行，不根据先验收益筛条件：

| 因素 | 水平 | 所改变的内容 |
|---|---|---|
| 源端队列深度 | 1、8 | ACK释放的功能额度，不代表硬件默认CQ |
| NP通知间隔 | 5、50 us | 通知时序及实际反向CNP数量，二者耦合，不能称纯时间干预 |
| RP恢复周期 | 5、55 us | 仅时间恢复周期，不连带替换g/alpha/字节阈值 |
| CNP模型帧 | 48、512 B | 实际反向序列化/排队成本，不代表RoCE完整线速帧或NIC处理 |

其余控制器固定：alpha55us、恢复字节10,000,000B、g=1/256、F5、最小100Mb/s、AI5Mb/s、固定HAI50Mb/s；通知/速率日志各最多10,000项。参数是参考假设，无GPU/NIC硬件校准含义。512B是成本敏感性边界，不能当生产CNP常态。字节阈值远大于此短输入，预期字节恢复不会触发；因此本轮不能评价双触发恢复在长流中的收益。

竞争解释与否证条件：

1. 只有静态出口服务量决定完成：所有条件数据/ACK服务量相同。若完成差异出现，则该下界不足以预测绝对时间；不能因此否定它作为强基线的价值。
2. 深度8的排序对反馈假设稳定：逐个固定NP/RP/帧大小比较depth1/8。若有反向，说明建议有模型敏感性；没有反向就如实收缩主张，不另调参数造反转。
3. 短通知间隔总是更好：报告全部8个配对，包括无差异与恶化。CNP数、CE、实际降速和发包共同解释，不能将差异只归给通知频率。
4. 反向字节成本主导变化：固定其他因素比较帧大小，核对实际反馈字节、到达时刻及业务ACK。若影响小，拒绝在这个窗口宣称其主导；没有反向背景，不外推忙反向网络。
5. 恢复参数主导变化：单独报告8个恢复周期配对和真实timer事件。短任务未触发恢复时，该因素无作用是有效负面结果，不扩长任务追求差异。

主要指标：最后业务ACK、物理排空（分开）、接收完成、队列峰值/面积、唯一目的CE、CNP数及逐跳字节、实际TX采样速率、timer/byte恢复、发布等待。独立按拓扑/端口哈希重算所有物理端口数据+最小ACK必要服务量；CNP用实际事件和完整端点捕获核验，逐跳总量再与物理端口对照。分析只读observed与公开输出，truth/原始专家仅由独立checker读取。配对是确定性敏感性结果，不作统计显著性或总体效应推断。
