# RC完成语义：本轮筛选结果

**结论：这一轮收紧了旧异常的成立条件，也排除了把它直接当作MoE跨机主创新的做法。没有确认完整RXE、当前Linux或真实网卡漏洞，没有新的性能收益。**

我们需要回答的是：网络确认是否足以证明下一步计算可以安全执行。普通字节流不携带完整的操作含义；但一个通用原子返回问题，只有确实影响目标MoE控制行为时，才值得作为本课题主线。

固定Linux v6.12提交 `adc218676eef25575469234709c2d87185ca223a` 的9份文件/5层tree重新核验。一次小型CPU编译执行10个未修改门槛/状态函数及2个原枚举，覆盖事前五个顺序前缀。发送驱动、队列、信用和时钟均有显式替代，未运行完整rxe_requester/rxe_responder/rxe_completer、包校验、内核、NIC或网络。

| 条件 | 所选源码函数实际结果 | 能说明什么 |
|---|---|---|
| 初次发送WRITE和原子，两反馈均未交付 | 两WQE均pending；原子持有唯一额度 | 所选原函数允许构造初次前缀；不等于真实收包路径 |
| 重试WRITE后，累计ACK先于原子重发到达 | 原子仍posted，get_wqe返回DONE | 旧异常不能不分时序地套用 |
| WRITE和原子均重发后，累计ACK才到达 | 原子pending，get_wqe继续CHECK_PSN | 一个门槛未排除；未执行完整内核或证明漏洞 |
| 原子带FENCE后重试 | 所选函数因本请求仍占用原子额度而阻塞 | 替代环境中的边界；不声称实机死锁或MoE损失 |
| WRITE确认先到，随后重试 | 从原子重试，不再发送旧WRITE | 本有限输入不再生成该重复WRITE来源的累计ACK |

先前旧值未写回的结果来自另一阶段的完成器片段；本轮不重复旧五项测试，没有再次模拟或声称该错误已在完整流程发生。新证据只把请求端从任意假定的pending状态，追踪到部分合法门槛；PSN、请求额度和WQE状态比“丢了几个包”更能决定后续分支。四类来源/状态篡改被独立核对器拒绝。

## 为什么暂不作为MoE主线

已缓存固定版本的DeepEP Hybrid中，跨机tail通知调用 `gin.red_add_rel`，接口返回void；目标端读取通知内存推进。分配slot时消费原子返回值的 `atomicAdd` 操作访问本地scale-up sender counter。现有modern控制器的所核回调推进段只读取operation/event/time_ns，并不消费远端原子旧值。不能将本地GPU原子和远端RDMA fetch-add混为同一条通信。

这些证据仅适用于核对的Hybrid tail/slot及本项目控制器，不能推广成所有MoE、NCCL/provider都不消费返回值。void接口仍需正确目标副作用、顺序及传输完成；不能因此删除Atomic ACK、取消重传或减少协议字节。当前没有证据把RXE旧值分支换算成MoE任务失败率或推理损失。

## 与竞品比较应怎样表达

| 对象 | 已有优势/事实 | 本轮研究定位 |
|---|---|---|
| CLEM固定公开路径 | 实际CCL、持久QP、ACK/CQ与控制写回已有实现；所核路径未实现一般fetch-add | 是双向联动的强基线；不能把我们增加原子接口直接当创新 |
| Linux RXE | 真实软件RC请求/重试/完成代码，比手写字节模型更强 | 本轮只执行其部分原函数，不冒充整栈；当前版本未验证 |
| 本项目 | 可区分目标应用、反馈、源释放与声明的控制依赖 | 此阶段补的是研究筛选证据，没有超越强基线的精度/成本收益 |

两项原候选仍未成立：第一项需要证明普通阶段/链路/DAG以外的信息能改变有代价的网络决策，第二项需要相对优化后的完整流程实际节省宿主成本。健康四卡排序、旧值异常、修复工程和源码函数数量都不能替代这些证据。本轮不新增接口，不把漏洞发现能力另起名字当第三个已成立贡献。
