# 有限缓冲恢复前的生命周期判别

平台固定`726ab7d`。本轮不运行新网络，只重读上一轮16份实际结果并核对当前固定源码，回答有限缓冲恢复评价是否已具备足够的模型依据。它不是新恢复算法或硬件内存测量。

预登记竞争解释：

1. 未完成源lease可能只是声明的保护边界，不能从其数量推断重传仍会访问应用源地址。核对发布时捕获、实际重传取数、lease释放的具体实现，并逐操作检查捕获次数及重复包内容。
2. ACK丢失与目标数据缺失不能使用同一种目标隔离结论。在本功能协议保留连接身份、单调字节接收与事务去重的范围内，一项已经实际applied的旧put不会再次改写；目标数据消费后的复用不等于源缓冲可改写。未应用操作仍需要退出证明或隔离。
3. 软件源缓冲复用不等于仿真器内部副本释放。核对操作body、stream payload和目标请求去重缓存；只核算由源码和实际操作导出的字节内容量，不将vector容量、RSS、HBM、日志或链路字节混入。
4. 若有限缓冲候选只能通过释放声明lease、忽略重传副本或假设免费撤权获得收益，暂不进入性能矩阵。操作级重放、独立目标窗口和有明确保证的旧访问退出继续作为强基线；这些经典机制本身不称论文创新。

方法：把16份原result压缩保存并绑定原SHA256；只读取得四份固定本仓源码（不拉取外部资料），保留完整身份。独立核验程序重读压缩原件，用操作/目标事件核对分析结果，并拒绝更改lease量与副本量两类篡改。输入准备、核算、核验分别提供命令；不导入tests、fixtures或历史研究辅助函数。

验收仅覆盖这16份已有小型Combine输出片段，不涉及独立请求、训练、千卡、GPU内存序或现代provider执行。报告明确当前功能语义和硬件结论的边界；不修改平台释放策略，不重跑旧失败网络。
