# 压缩表示后的真实两调用检查

原明文两计划因保存体积失败，原件和错误保留。平台1422ba2073独立验收压缩保存后，本补充保持同一现代配置、原始选择、逻辑上限和16MiB实际产物上限，只用新增`--format compressed-json`，输出至新目录。不是重跑网络，也不扩大原flat上限。

两组各公开plan/check一次；另用独立标准zlib读取器、原始选择和32×32源/目标枚举，核对四种屏障、完整rank/expert计数（含零值和self-peer）、Dispatch/Combine数据及规范hash。不得预先给slot排序或触发回调。研究通过仅证明完整表示和无时间闭包，不证明现代native运行期或多组共享网络。

原研究的900秒/512MiB累计预算保持，源归一化、路由统计及旧库寿命拒绝不重跑。下一项实际网络前仍需审计现代入口的256次交互、16,384逻辑步、原生节点与缓冲等门限，不能把压缩后的可保存当成可执行。
