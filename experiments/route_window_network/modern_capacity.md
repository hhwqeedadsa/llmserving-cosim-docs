# 现代direct表示的补充容量核查

旧库两调用在Python寿命预算前被拒绝后，进一步核对现有现代direct公开入口能否表示相同来源的两次调用。此补充先于执行保存，不改原层、请求、两步选择或旧失败记录。

分别为原来的两个EP32/E256/H7168组构造现代direct两调用输入，BF16/expanded/local reduction沿已有声明。使用两个逻辑SM角色、两个Dispatch/Combine warp、五个context、一条连接及每rank本地device0；这些是功能角色，不是GPU性能/资源校准。保留完整屏障、rank计数、expert计数块及self-peer，不删除零值。

使用现有最大有界表示：65,536事件、16,384操作、16MiB输出，若失败如实记录，不提高上限、降低EP/E或删除操作。每组只尝试一次计划生成；成功后公开check一次。均不驱动网络、动态slot分配或执行服务调度，不能把计划通过等同原生执行通过。结果仅决定下一项应优先验证现代路径还是改进旧库寿命管理。

沿用本轮900秒/512MiB累计、阶段120秒/RSS1GiB/地址2GiB预算，无新网络、安装、下载或构建。重复身份与完整数据/控制操作另由独立读取器核对。
