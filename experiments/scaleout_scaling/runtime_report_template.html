这些时间分别指什么？

Worker 墙钟时间
本机实际等待，包含初始化、构图、后端执行和写出；不是纯 ns-3 CPU 时间。
完整命令时间
公共运行命令的起止，还包含准备与自动校验。不能把它与 Worker 的差全部算作校验。
独立校验时间
额外调用检查命令的耗时；只有采集了起止时间的用例才填数值。
模拟完成时间
模型内业务事件的完成时刻，与宿主墙钟分开；超时运行没有最终值。
采样峰值内存
所属进程树的采样峰值 RSS；超时仅报告中止前观测，不能视为完整运行峰值。

    专家热点数据怎样接入网络？

    MoE_expert_selection_trace记录每个请求、每个token、每层选中的专家。它提供专家选择，不提供原集群的源GPU、专家位置、请求到达时间或网络包。

    1. 校验来源文件和SHA-256，保留模型、原层号和专家编号；Prefill与Decode分开统计。
    2. 在输入的route_replay中，明确每张卡每个请求槽对应哪个文件、从哪个Decode入口开始；不同并发请求使用不同原文件。
    3. 声明专家到GPU的放置。按实际选择和hidden×激活字节生成Dispatch/Combine；同卡留本地，同机走机内织构，跨机走原生ns-3 RDMA。
    4. 下一轮等待本轮真实完成事件；观察片段结束记为OBSERVATION_ENDED，不能当作模型EOS。

    新接入口允许逐层静态重排，但保持每卡专家数相同，不增加免费副本。有限片段service/1可执行1—4个连续MoE层；完整结构service/2要求覆盖来源的所有层，当前仅支持全MoE的GQA结构，不能冒称已完整支持R1的Dense层与MLA。

    验证范围：公开的4卡人工样例已完成两轮联合执行和独立核验；它验证接口，不代表真实热点收益。本报告最初生成时尚未取得原始路由；后续4请求真实路由接入结果另见仓库的四请求核验报告。本页历史测量继续使用原有合成路由，所有耗时与超时结果保持原样。重点对照是固定专家选择，改变专家放置、跨Pod位置与分层带宽，观察网络排队及Decode等待。
