# Scale-Up 正常业务问题筛选

本实验从正常 MoE 执行中观察参与端拖后、通信持续偏慢与网络竞争，核验具体原因，再判断已有端网观测是否足够。长尾与拥塞只是候选入口，不要求它们同时出现，也不预设需要新增测量机制。

整体研究范围见[实验方案 v0.1](plan_v0.1.md)，原平台修正见[平台 v0.5 规范](../../docs/archive/moe_ub_cosim_dev_v0.5.md)。当前范围、实际基线、状态和执行顺序只维护在[当前任务](../../docs/tasks/current.md)。查看已有发现先读[研究结论](conclusions.md)，具体证据见 [E1 正常业务](results/e1/README.md)、[E2 成因与信息比较](results/e2/README.md)和[资源汇总](results/resources.md)，运行恢复与分析入口见[操作说明](usage.md)。

C1 发送队列分支已经冻结，N1/N2 的网络等待、业务作用和局部服务对照已经收尾。本轮按[信息能力与通信结束边界核验](candidates.md)，连续完成源端结束语义检查、已有字段的加强基线、完整理想关系与简化边界对照；仅在仍有有意义的歧义时尝试简单离线恢复，随后用已有记录复核并给出去留决定。不新增后端仿真，不直接进入正式 E3/E4 或完整测量算法。

原 105→116 的唯一归属结果保留旧基线口径。它没有证明全部增量必须依靠新测量，也不预定会被源端结束时间全部消除。上轮网络筛选要求见[固定历史版本](https://github.com/baoy21/moe-ub-cosim/blob/195fa8bb1e9fe053fc0632cd39c8ffbc5fe2390b/experiments/scaleup_issue_screening/candidates.md)，不再作为本轮运行清单。

## 接手入口

先读 [AGENTS.md](../../AGENTS.md)、当前任务、候选文档及[开发维护](../../docs/development.md#性能现象核查)。从现有受限输入、分析记录和绑定归档开始，不先建设平台。资料不足时说明具体覆盖，不能以摘要代替完整语义核验，也不能为补一个评价标签自动运行新场景。

原正常输入与判定方法见 [method.md](method.md)，原交付补证见 [delivery_method.md](delivery_method.md)，本轮要求以候选文档为准。字段含义见[记录格式](../../docs/record_storage.md)，模型语义与近似见[模型依据](../../docs/model_validation.md)。本目录与 `mapping_value`、`scaleup_observability` 独立，旧结果不自动成为当前方法的参数、标签或采样规则。

## 实现与资料职责

平台负责通用执行和读取能力，实验负责输入准备、离线判断和独立评价。本轮优先复用 `network_information.py` 与现有读取工具，按需要增加分析检查；不让平台导入实验，不让正式分析依赖测试 helper。通用读取缺陷应独立修复和验证，不能修改执行语义来使时间上界成立。

研究者可使用内部传输和依赖核验完成条件，实际基线与恢复程序只读取明确开放的资料。理想关系与理想结束边界单列为增强信息，不混入已有观测；使用后续窗口的方法保持离线身份。真实混合、无记录与未知项不被强制变成唯一标签。

原数据和结果保留，新分析单独绑定代码、输入、语义条件和输出。新增脚本、配置与证据在实际需要时放入本目录，结果按既有 `results/e2/` 组织，不预建空页或新实验目录。仅经验证的操作进入 `usage.md`，综合判断进入 `conclusions.md`，进度只更新当前任务页。

大型产物仍位于 `runs/scaleup_issue_screening/`，采用显式来源和独立输出路径，遵守已有 64 GiB 累计预算及清理规则。每批检查和本地提交沿用仓库规范，未经新的明确授权不推送后续实现。
