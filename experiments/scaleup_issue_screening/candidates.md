# 信息能力与通信结束边界核验

本轮继续正常业务问题筛选中的离线信息分析，核查现有操作时序是否已经足够，以及更准确的出口发送结束边界是否确有增量。N1、N2 的网络等待和服务影响实验已经收尾，C1 发送队列分支继续冻结。不开新任务、平台版本或实验目录，不追加后端仿真。

整体问题沿用[原实验方案](plan_v0.1.md)，进度与授权只维护在[当前任务](../../docs/tasks/current.md)。上轮筛选与服务对照的要求保留在[固定历史版本](https://github.com/baoy21/moe-ub-cosim/blob/195fa8bb1e9fe053fc0632cd39c8ffbc5fe2390b/experiments/scaleup_issue_screening/candidates.md)，原结果不追溯改写。执行时遵循[性能现象核查](../../docs/development.md#性能现象核查)，按本页分支连续做到去留判断，不在每项辅助工作后停止等待确认。

## 1. 要回答的问题与结束条件

原信息比较中，两个峰值窗口已能用工作量、操作时序和静态出口关系定位到第 7 层 Dispatch。其余 132 个有已知应用等待的相关窗口，唯一归属由 105 增至 116，来自一项理想操作—端口—发送窗口关系。原始数据见[信息比较摘要](results/e2/network-discovery-information.json)。这是相对原规则的结果，不足以证明必须增加新的观测。

代码复核提供两个待检验点。原规则使用源操作开始与目的操作结束，没有使用已经输入的源操作结束；判断器虽然接收完整窗口关系，实际只使用每操作、每出口的最后发送窗口结束时刻。本轮先检验这两点，再决定是否尝试从已有统计恢复边界。

最终需要回答三个具体问题。充分使用已有字段后，哪些旧阶段仍会被错误地保留为可能等待者；若出口发送边界有帮助，完整映射是否提供了比这个边界更多的实际判断信息；不用理想关系时，已有端网记录能否得到足够保守且有用的结束区间。

本轮不预定新增信息必须有价值，也不要求提出算法。加强基线后增量消失、边界能由既有统计恢复、仅有有限但无明显诊断作用的增量，均可正常收尾。无法恢复不自动证明信息论意义上的不可识别；可以恢复少量案例也不代表所有 Scale-Up 测量问题已解决。

## 3. 先核实源端操作结束能否约束交付

原准备程序检查源操作开始不晚于发送提交、目的操作结束不早于相应数据就绪。本轮补查源操作结束的含义。固定模板的 Dispatch 与 Combine 完成节点包含本端发送条件，因此源结束可能为自身发出的应用数据及状态提供另一个上界；这是待验证的语义，不直接当作已证实结论。

从构图到后端回调核对相关发送条件，在明确对象范围内检查是否有 `data_ready_ns <= source_operation_end_ns`。验证应覆盖所用运行中全部相关应用网络传输，而不仅是 N1/N2 的选定包；同时检查目的边界、操作身份、源目的关系与数据/状态分类。保留各类数量、未覆盖项和全部反例，不能从真值逐条挑选符合关系的传输，再把这种选择开放给判断器。

能否采用该上界由模板及可公开说明的完成语义统一决定，实际记录只用于核验，不提供逐样本答案。若出现反例，先检查身份绑定、回调定义和真正的依赖范围；区分分析错误、确实不适用和资料不足。不改变仿真模型、不补造时间戳、不删除反例来获得上界。确有不适用的调用类别时，公开其语义范围并在相应类别回退到较宽边界。

该核查只说明现有模板的记录语义。不能将 CPU 异步提交返回、缓冲可复用、远端应用数据到达和协议回收都解释成同一个完成时刻。对于只保证本地请求形成的其他完成方式，合成测试应确认不会错误套用远端到齐上界；不为此另跑一组实际完成方式对照。

端侧时钟精度、时间取整和窗口端点按照原公开字段处理。当前各条件共享准确时间关系，不引入时钟误差矩阵；也不从私有记录读取更细时间来悄悄提高基线精度。若需要保守舍入，所有条件采用相同规则。

## 4. 加强基线，分清已有字段与新增信息的作用

先复算并保存旧输入、旧规则和旧评价，核对原 105/116 及完整逐窗集合。新结果另存，不覆盖原预测和摘要。基线复现不需要重放仿真。

原规则对一个正工作量的源目的对，只要求源操作开始早于窗口结束、目的操作结束晚于窗口开始。源端上界经第 3 节确认适用时，可以进一步要求源操作结束晚于窗口开始。用半开窗口 `[a,b)` 表示，则该对仍可能有正时长等待的必要条件为 `src_start < b` 且 `min(src_end,dst_end) > a`。这是时间范围筛选，不证明它实际经过某端口或正在等待。

同一操作存在多个来源时逐源核对，再合并仍可能的来源；任一有合法工作量的来源尚可能发送，不能仅因另一个源已经完成就排除整个操作。不使用最早源结束、固定热点 rank 或最晚消费者的私有身份替代逐源关系。数据可以早于目的操作进入而到达，因此目的开始时间不能未经依据当作包到达下界。

对静态拓扑和已有字段的其他简明约束也进行一次有界检查。约束只能使用原受限输入与已声明的语义，不能读取精确路径、真实包身份、内部阶段、完整依赖或干预结果。若公开源目的工作量来自平台准备的参考能力，应保持原假设，不写成真实设备必有接口。

| 条件 | 要隔离的变化 |
|---|---|
| 原基线 | 保留旧规则，建立可复核起点 |
| 加强基线 | 只充分使用原有字段与经核验的完成语义 |
| 加强基线加原理想关系 | 检查在较强基线之外还剩多少信息增量 |
| 同一基线加简化边界 | 按第 5 节判断是否需要完整关系 |

保存每个窗口的候选集合、排除依据和未确定项，特别核对原来 27 个多候选窗口、11 个新增唯一窗口及真实混合窗口。多个可能操作不一定错误；同时存在多个真实等待操作时，强行唯一归属属于错误。

FIFO 评价与只有部分上游到达证据的评价分列。后者的已知等待集合可能不是完整真值，唯一候选只可称符合已知事实，不能自动确认不存在其他等待者。正面积但没有已知应用等待的窗口保留未知，不一律认定为协议流量。报告遗漏已知操作、未证实候选、唯一且符合已知事实、多候选及未知的数量和分母，不把相关窗口算成独立准确率样本。

若旧 11 个窗口的增量全部被加强基线消除，仍完成简化信息的等价检查及可用记录复核，再结束当前恢复分支；不能换一套更弱字段定义重新争取收益。

## 5. 检查完整关系是否只提供最后发送窗口

当前 `judge_input()` 将理想关系压缩成每操作、每出口的 `last_tx_window`。准备独立的简化输入，按同样的操作与端口保留最后一个有应用发送的窗口结束值，以及必要的覆盖和完整性声明。它不携带该窗口内的精确最后包时间、不增加字节分类、依赖或影响标签。

分别对原基线和加强基线，核对完整理想关系与简化输入的全部逐窗输出是否一致。固定时间分辨率、样本、后续覆盖和排除规则，不同时改进边界算法后把增量归因于压缩。出现不一致时追查哪个额外字段或覆盖条件起作用，不能只验证摘要总数相同。

必须区分有最后发送记录、在完整范围内确实无相关发送、未来范围未覆盖和记录缺失。包在当前窗口等待，可能到后续窗口才发出；当前窗口没有发送不能用于排除。原程序在目的完成落在采集范围之外时保留未知，这个保护不能在简化中删除。若利用新的源端上界进一步证明覆盖充分，应作为对两种输入共同生效的新规则单独核对。

这个边界描述应用数据或状态在一个出口的发送窗口，不等于整个操作完成、所有平面无流量、接收端消费结束或协议资源释放。以发送开始记录构成的边界也不升级为准确的离开链路或到达时刻。对零流量、边界恰在窗口端点、记录裁剪和窗口内发送未结束等情况保持原定义。

等价成立时，只能说明本次判断器不需要完整映射中的其他内容，不能宣称已经证明理论上的最小充分信息。记录简化前后逻辑项数、必要字段和处理规模；JSON 大小不作为交换机 SRAM 或线上上报开销。理想边界来自评价准备，仍不是已经实现的测量。

本轮保持离线分析身份，明确使用了多长后续记录。禁止将依靠未来窗口排除候选的方法描述为当时即可在线判断。

## 6. 有剩余价值时，尝试仅用已有信号恢复边界

只有加强基线仍存在值得处理的歧义，而且理想边界能改善明确判断，才进入本节。先说明缺口具体是什么，例如旧阶段已不经过某出口但仍被操作总时长保留。增量只改变少量无实际用途的标签时，可说明原因直接收尾；不因理想边界存在就自动构造恢复算法。

允许使用既有操作起止、源目的工作量、静态出口关系、端口包/字节计数和队列窗口，尝试少量有明确依据的简单约束或保守区间规则。先保存规则及不同解释的预期，再独立评价；不对已知 11 个窗口调阈值，不以机器学习、完整流量矩阵恢复或新增协议作为默认实现。

重点防止以下错误。短暂无发送或队列为空只说明该时刻没有对应观测，不能证明后续不会再注入。逻辑应用字节不能直接与含协议控制、元数据和逐跳重复的端口字节相减。多平面逐包喷洒不能假定均匀分摊，不用总工作量除以平面数当作单端口精确预算。字段不能支持精确关系时保留范围或未知，不读取真值补齐。

输出可以是结束时间所在区间、排除某旧操作的充分条件，或者当前无法确定，不要求每个窗口都唯一归属。将保守且正确的范围与启发式猜测分开报告。评价首先检查是否过早宣布结束、漏掉仍在等待的操作，再检查区间宽度、候选减少与离线观察范围，不能只优化平均误差或唯一标签数。

准备程序可以使用私有事实产生真值或理想输入；实际恢复程序只能读取显式受限文件，不能读取理想关系、原始归档位置、带答案的文件名、逐包身份或依赖。基线、恢复与理想边界三组分开，保持相同观测覆盖与精度。若需要控制报文的未知量，只能采用公开可依据的界限，不能借用评价里的准确类别计数。

无法取得可靠边界时，保存一个具体歧义及规则失败原因，说明缺少的是怎样的观测或语义。不把一个尝试失败写成所有可能方法都失败；只有构造出同一可见信息确实允许不同答案并说明约束时，才讨论相应的不可区分结论。

## 7. 在已有记录中复核，并验证分析实现

主要 1024 请求资料用于复现与规则开发。先固定规则，再用原 256 请求被动记录及其实际覆盖重新准备同类输入。额外使用其他操作或片段时，以现有真值与窗口范围为限，不为了填表重新采样或仿真。服务干预记录如用于补充，单独标明，不能作为正常独立输入。

复核前说明哪些规则利用过哪些案例。256 请求也曾在本项目中分析过，只能作为本轮固定规则后的跨记录复核，不能称全新独立测试集。嵌套请求、相邻窗口与同一执行回放均不独立。不在看到复核答案后反复修正规则，再把该资料继续称留出验证。

复核保留全部合法窗口，不只检查原来新增唯一的窗口。对真实混合、无流量、未知协议归属、覆盖之外仍可能发送的操作都正常输出。原资料只有部分上游捕获时，不补零、不把未捕获当已排除。资料不足以评价某项边界时，给出覆盖限制和案例级结论。

小型分析检查至少覆盖多源中一源已完成但其他源未完成、源先结束而目的仍等待其他数据、异步完成不能充当远端上界、真实混合操作、瞬时边界与半开窗口、跨窗口滞留、覆盖外后续发送、无记录与无发送的区别，以及完整关系和简化边界逐窗等价。检查还应验证判断与恢复程序仅打开允许的输入，标签或原始路径不经辅助函数泄漏。

复用现有 `check_network.py` 等实验工具检查方式，按实际职责增补测试，不把研究收益设为必须通过的断言。旧结果发生变化时区分输入语义修正与程序 bug，原运行证据不改写。分析错误只重做分析，不启动后端。

## 8. 自主范围、资源与实现方式

本轮授权从覆盖核对连续做到综合结论。源码语义核查、流式读取、受限输入准备、分析修正、小型合成测试、加强基线、简化关系、条件性恢复与跨记录复核均可自主完成。不要在核实一个字段或得到负结果后仅提交下一步建议；按照本页分支继续处理其他可执行内容。

新增后端运行为零，不建立新场景、不生成或修改业务执行图、不改通信模板、资源、调度和同步，不扫描带宽或故障。上轮六次配额中的剩余次数不延续成本轮权限。确有执行缺陷影响语义判断时，保存最小问题说明并限制结论，不通过改模型和重跑来维持当前候选。

实验分析代码留在现有实验目录，使用公共命令或稳定读取接口，不导入测试 helper。确需修复通用读取或导出时，平台与实验分别提交并做相应小型检查；没有必要不改平台，不重建 ns-3。数据重分析使用显式来源路径、绑定清单和版本，不能依赖某台机器上默认的 `runs/` 状态。

分析受监控上限为 RSS 8 GiB、单进程地址空间 12 GiB、1800 秒；累计产物采用已授权的 64 GiB、原 16 个计量根目录和至少 20 GiB 空闲。先核对实际占用，再流式或按需读取归档；只清理本轮登记的可再生副本，不删旧归档或改计量范围。正常按对象分批分析可以采用流式实现，但不能通过拆命令掩盖超限或不记录总工作量。资料或预算不足时，先完成其余可做分析并给出最小缺项，不自动提高额度或下载新大型数据。

每批通过检查后建立本地提交。原预测、理想关系、评价和运行资料保留；新语义核验、新规则与新结果分别绑定摘要。具体脚本与结果文件按实现需要增加，不预建空文档。只在验证命令后更新 `usage.md`；状态仅维护当前任务页，方法和结论不写过程日记。

## 9. 下一次同步的完整产出与去留判断

产出应让读者直接判断是否值得继续投入，而不是再次从大量日志中找问题。至少说明已核验的完成语义与覆盖，原基线和加强基线的逐窗及汇总差异，完整关系与简化边界的等价结果，条件性恢复及跨记录复核，以及仍然无法判断的具体对象。相关证据按现有 `results/e2/` 组织，综合判断更新 `conclusions.md`，旧摘要不覆盖。

| 结果 | 本轮决定 |
|---|---|
| 加强基线消除了旧增量，复核支持 | 将已验证规则保留为既有观测基线，不为这些案例新增测量机制 |
| 尚需较紧边界，但既有端网统计能可靠恢复 | 保留简单端网关联方法，说明作用、适用范围和代价；不自动扩大为完整系统 |
| 边界确有稳定增量，已有规则仍不能消除有意义的歧义 | 推荐一个具体观测需求及获取位置，区分已证实信息增量与尚待研究的恢复方法 |
| 增量仅为少量相关窗口的标签变化，缺少有用判断 | 有限记录并结束候选，不通过新增负载或模型维持必要性 |
| 语义不适用、真值不完整或资料受阻 | 限定能够支持的结论与最小缺项，正常交付已完成部分 |

有用判断可以是阶段已离开某出口、旧操作不应继续承担该处等待，或可作为端网对照的时间范围；不要求每个案例都证明较大性能收益，也不把唯一标签数提高直接当作根因定位价值。需要进一步研究时，说明它改变哪项具体诊断或对齐判断。

未进入恢复等条件性分支时记录原因即可，不要求凑齐算法。负面结论可以完成本轮，必要目标因权限或资料受阻则如实标记部分完成。结束后不自动进行新的候选扫描、正式 E3/E4、P4、包头标记、时钟误差矩阵或硬件机制开发；后续实现未经新的明确授权不推送。
