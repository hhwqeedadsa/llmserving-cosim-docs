# 候选 C1 与成因核验

C1 检查 Combine 等待及其对后层执行的影响。本页保存最晚消费者完成依赖补查、固定总额度队列组织对照的约定口径及候选判断。不开新任务、平台版本或实验目录。整体目标见[原实验方案](plan_v0.1.md)，进度只维护在[当前任务](../../docs/tasks/current.md)。

原候选与三项成本/完成条件对照的预定安排见[原始版本](https://github.com/baoy21/moe-ub-cosim/blob/6ebe4984280465316f90886ccdbf4f66f4fe9d49/experiments/scaleup_issue_screening/candidates.md)；上轮请求阻塞核验的完整要求和判断见[本次交接前版本](https://github.com/baoy21/moe-ub-cosim/blob/2362ef9d502fb0d12f51f0649b9b81ac619a6cd1/experiments/scaleup_issue_screening/candidates.md)。这些旧安排不再作为本轮必跑清单，原数据与运行证据保留。

## 1. 当前要回答的问题

上轮已证明当前请求额度影响发送推进及业务结束，但容量与统一队列的作用尚未分开。本轮要判断：总在途资源与请求划分不变时，按通信核组织待发请求是否会显著改变已观察的等待及业务影响。该对照用于检验 C1 对模型组织假设的依赖，不是设计新的硬件优化或测量算法。

固定已有真实专家路由、物理网络、请求、专家放置、线性计算成本和所选 A3 STORE/STORE 调用。输入复用只核对身份和摘要，不重复开展负载代表性、成本拟合、算子校准或专家复制研究；发现直接影响本次判断的新错误才处理对应项。

本次同时修正上轮新最晚消费者的分析方法。最后到达的数据未必是最后满足的执行条件，需要检查状态、本核发送、归约和资源调度。不能因为找到了一个晚到的数据源，就默认已经定位完整阻塞原因。

[固定源码核查](results/e2/c1-source-review.json)支持数据/状态顺序及缓冲复用，但尚不能确认所有 AIV 共用一条请求队列，或下一份准备必须等待前一状态的全部原生请求形成。`ThreadNum=1` 是项目显式值；默认 48 会把每份任务按字节分给多个 worker，已有小测确认 32 B 状态会变成 32 个请求。不得再把 1→48 当作只增加并行度。

当前图中下一份准备依赖上一状态的 `local_read_complete`，因此双缓冲并未在所选序列上提供相应的准备重叠。本轮记录这项剩余假设，不修改该依赖，也不通过同时放松栅栏来增强队列对照收益。

## 3. 最晚消费者完成依赖补查

先重分析已保存的额度 32、64 运行。对每层全部并列最晚消费者，从 Combine 完成节点向前核查真正最后满足的条件，再核对后续计算开始。基线 rank 27、58 和额度 64 的 rank 33、56 是起点，不是固定根因标签。

现有 [native_review.py](native_review.py) 的 `latest_incoming_data_for_actual_last_consumers` 只从 `message_role=data` 中选择最后到达者。保留该字段原有的数据含义，需要时增加独立的完整依赖结果，不能静默把原字段改名解释为根因。

完整核查须区分业务数据、状态到达、本核发送结束、各 Token 归约及算子完成。依赖已满足但实际开始更晚时，继续核对资源持有者；不能把这一调度间隔塞进网络时延。并列最晚端、并列前驱和已知边界均保留，不能任意挑一项后写成唯一原因。若上游资源事实缺失，明确可确定到哪一步，不从最后到达数据或时间邻近猜测。

优先流式读取已有归档中的图、执行记录和传输信息，按需导出有限对象，不为这项分析修正重跑仿真。补小型分析检查，至少覆盖状态比数据晚、本核发送或资源调度比入站数据晚，以及并列依赖。重分析结果单独绑定原清单与新分析程序，旧运行数据和旧摘要保留；更正影响解释时在 E2 结果就地注明。

新队列对照采用同一修正后的分析方法，按当次实际最晚端追踪，必要时扩展到新的供数端。不要只对 rank 70、65 的旧传输重复统计。

## 4. 固定总额度的队列组织对照

### 要区分的解释

| 解释 | 支持它的对照现象 | 削弱它的对照现象 |
|---|---|---|
| 统一任务 FIFO 放大跨核等待 | 总额度不变时，其他核任务造成的等待明显改变，并能追踪到目标完成或后继计算的变化 | 局部等待与业务结果基本不变，或主要差异发生在别处 |
| 局部消息提前不改变业务必要完成条件 | 状态较早形成，但另一份数据、状态或本核工作仍决定完成 | 目标完成和后继计算确实随该等待同步提前 |
| 当前现象对这项组织假设不敏感 | 两种组织下，主要等待来源和业务影响形态均保留 | 主要等待、最晚对象或传播关系发生实质改变 |

最后一种结果只证明对本次组织变化的稳健性，不能排除未核实的核内同步，更不能自动证明真实 A3 的行为。运行前固定判断口径，报告具体变化量与原因，不用是否获得正收益作为验收条件。

### 基线与替代方式

基线保留一个 worker 中的统一 STORE 任务 FIFO。替代方式在同一端点请求发起器内，按通信核保存待发序列，共享同一组在途额度。每次允许发起请求时，在非空且依赖已满足的序列之间轮转，从选中序列的队首任务形成一个原有字节范围的请求，然后转到下一序列。任务仍有未形成请求时保留在该核队首；全部请求形成后才允许该序列的后续任务取得机会，不额外等待整任务确认。

这是一项显式参考策略，逻辑序列不代表一组已核实的物理硬件队列。可继续使用单个 worker 持有所有在途资源，不能为实现逻辑分队而创建每核独立的请求额度或链路服务能力。一个请求成功形成后才推进轮转位置；空序列可跳过，没有额度时按既有响应事件唤醒，不增加轮询延迟、忙等事件或随机数。初始顺序和后续游标采用预先固定的确定规则，不按热点、目标消费者、消息大小或预期收益调整。

核身份来自产生 SEND 的真实静态工作分配，经平台描述和实际任务传递。不能读取实验真值文件来驱动调度，不能从目的地址或已知阻塞样本猜测生产者。核身份不唯一时先检查构图来源；启用该策略却缺少必要身份的输入应明确拒绝，不静默分配到某个默认核。身份只作为模拟器内部调度资料，不进入线上包、不改变选路哈希，也不成为真实设备已有观测字段。

对照对同一场景所有 A3 参与端采用相同规则，覆盖该路径的数据与状态 STORE，不只改 rank 70、65，不单独照顾 32 B 状态。保留每核原有任务顺序及数据/状态依赖；不同核之间允许改变请求发起顺序，这正是被检验的因素。

### 必须保持的不变量

| 内容 | 两种组织共同要求 |
|---|---|
| 总在途资源 | 每端 STORE 总额度 32；共享请求编号池 256；占用和响应释放条件不变 |
| worker 与字节划分 | `ThreadNum=1`，请求粒度 4096 B；每份任务的实际请求数量、偏移和长度相同 |
| 软件执行 | 同一业务图和全部依赖、数据/状态顺序、缓冲复用及核内同步；计算工作量和各成本不变 |
| 业务与网络 | 同一请求、路由轨迹、放置、拓扑、链路服务、流控、喷洒策略和随机配置 |
| 策略权限 | 不给状态或关键业务优先级，不增加每核配额、专用 VC、链路或服务速率 |

协议请求标识、包 UID、请求顺序和实际路径可随执行变化，不能用这些易变编号作为跨运行的业务匹配依据。请求不变量按业务身份、方向、字节偏移和长度核对。不得为保持请求序列而固定旧发包时刻，实际网络竞争和完成反馈必须保留。

## 5. 平台实施与小型验证

优先在现有原生请求发起路径增加可选策略，旧 FIFO 保持默认。策略字段、核身份表达、有效配置回读、记录和保存/重放一起实现；不在实验脚本中重新发包或用外部调度绕过后端。平台通用代码不得导入实验或测试 helper。

检查现有冻结图是否足以提供唯一核身份。只有身份完备且业务依赖不变时才扩展明确的重放白名单；不得直接删除版本、图或配置检查。若必须增加静态身份元数据，应可复核地生成并绑定新输入，核对去除该元数据后的图、依赖和工作量等价，不伪造旧摘要或静默改写旧切片。具体接口由实现确定，通过后再更新使用指南。

先做以下最小检查。

| 检查 | 验收内容 |
|---|---|
| 单生产者与旧模式 | 单核轮转退化为原 FIFO 请求顺序；默认策略保持原行为；新增记录启停不扰动执行 |
| 多生产者与混合长度 | 多核大数据和小状态按请求轮转，任务内部字节范围及核内顺序不变；状态没有特殊优先权 |
| 有限资源与实际唤醒 | 所有逻辑序列合计最多占 32 个在途额度，响应只释放一次；共享池阻塞与 worker 阻塞分别正确，无饥饿或死循环 |
| 完成与兼容 | 本地请求形成、目标到齐和协议回收保持原语义；缺失身份和非法配置拒绝，STORE/LOAD 与受影响 A3 回归通过 |

测试用于证明替代策略实现了声明行为，不以通信必须更快为断言。必要时补一个不依赖真实路由和旧产物的公开小例，复用现有示例组织，不建立新平台里程碑。新增调度不能扩大记录量到全网逐包；只保存足以核验轮转、在途占用和请求范围的有界事实。

## 6. 实验范围与判断方法

小型验证通过后，使用现有 128 rank、256 请求、原始第 6～8 层场景。新二进制先完成必要的同场景 FIFO 等价核对，再做一次总额度 32 的轮转对照。正式研究不追加 64/128/256 扫描、其他轮转权重或状态优先级，不默认重跑 E1 全批、完整 61 块或 64 步。

FIFO 核对要检查原业务执行、传输、完成时间和已有端口指纹。不能仅以旧模式仍能结束证明基线未受改动影响；差异先查原因，不更新旧预期来迁就新代码。每次运行绑定实际主仓、依赖和二进制，改动与基线分别登记，不把模型对照算成独立统计重复。

主比较是 FIFO/32 与轮转/32。已有 FIFO/64 仅作背景证据，不新增第二个变量。至少检查原两条相同业务贡献的等待、状态任务前的其他核任务及在途资源、原消费者和当次全部最晚消费者的完整完成条件、后续计算开始及第 8 层最后模型计算结束。网络排空单独保存，不能用模拟结束代替业务结束，也不能将两条局部链差值相加为总收益。

请求范围核查优先覆盖全部原生 STORE，采用流式计数或摘要控制开销；需要逐项证据时对选中端点展开。若覆盖不足应说明未证明的范围，不能把局部核验写成全图一致。保留全图任务与计算摘要、业务/状态字节和实际端口分布；物理控制包数量或路径可能变化，报告它们，不以同种子声称路径相同。

数据与状态完成先后、最晚消费者和供数者都可能改变。修正后的分析从当次实际完成事件追踪，记录替代路径和并列前驱；旧关键传输只用于同贡献比较，不继续假定它决定新执行。逐包网络反馈未独立分离时，只报告队列组织改变后的总效应，不称为纯队首等待损失。

## 7. 本次核验后的候选判断

对照前确定的判断原则如下，现有 32→64 结果与源码缺项见 [E2](results/e2/README.md)。这些原则不以参考方式更快为验收条件。

如果总资源不变、只换请求组织就明显改变主要等待或业务影响，应降低 C1 作为真实测量问题的优先级，明确它依赖何种队列假设。替代模式保留为参考，不因更快就直接替换真实硬件基线。

如果局部状态更早形成但业务没有相应改善，追踪其他完成条件，说明它为何遮蔽局部变化；不能继续调度来保住收益。如果主要形态仍保留，记录对这一次组织变化的稳健性，同时保留核内同步和硬件组织的未决项，不自动升级真实性判断。

本轮最后给出继续保留、降低优先级、暂停或结束 C1 的理由。需要继续时必须指出尚缺的最小机制依据或已有观测的具体歧义；没有候选价值也是有效交付。不新增测量算法，不进入 E3/E4，不把状态消息或轮转调度另立为优化课题。

实际证据支持：**保留 C1 为模型内供数链现象，降低直接以其请求排队分量提出真实测量问题的优先级，暂停新增测量研究。** 全图请求范围和总资源不变时，原两条链的前序状态请求形成等待下降约 81.2%、69.8%，前序数据请求形成却明显变慢，业务只提前 945 ns（0.85%）。因此局部组成依赖统一队列假设，状态提前并不是可直接兑现的整段收益；热点供数端仍是 70、65，而最晚消费者改为 10、34，完整状态到达和归约链已有记录支持。

该参考对照没有消除硬件依据缺项，也不能把形成前的等待解释为与网络响应无关。继续 C1 所缺的最小资料仍为选定 A3 的 AIV/MTE 请求队列组织与共享范围、状态到下一份准备的实际同步对应。数据、请求形成分段、实际队列状态及网络分布见[E2 组织核验](results/e2/README.md#固定总额度的队列组织)，不以额外轮转权重或额度扫描代替机制依据。

## 8. 资源、文档与自主推进

沿用当前任务中的时间、内存、累计磁盘及最低空闲空间上限。上轮归档占用约 46.32 GiB，仅为历史记录；开始前重新核对实际空间。先读取索引和压缩资料，按需恢复，串行执行并核验归档后释放本轮可再生副本，不删除旧归档、不自动增加上限。资源不足时停止受影响部分并记录最小缺项。

已授权的消费者重分析、静态身份核查、最小实现、小型验证、FIFO 等价检查和一次组织对照由 Codex 连续自主完成。核内同步和硬件资料仍未确认，不妨碍把本次明确的参考对照做完；但不得据此猜测硬件或顺手扩展为同步改造。遇到不变量不能保持，先检查最小反例和混杂因素，不能只写未知或无说明地放宽要求。

结果写回既有 E2 组织，必要证据文件在实际形成后加入，旧结果按旧版本保存。若完整依赖补查纠正旧解释，应就地注明原因和来源，保留旧运行。通用规则沿用[开发维护](../../docs/development.md#性能现象核查)，进度只维护当前任务，不在多个文档追加日志。

平台和实验分别验收、分别建立本地提交；依赖修改按由内向外的顺序保存 gitlink 与锁文件。后续实现的远端发布仍需明确授权。
