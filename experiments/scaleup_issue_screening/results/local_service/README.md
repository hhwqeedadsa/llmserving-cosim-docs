# 本地竞争与服务不足

[四档正常记录摘要](normal.json)保存统一 `[0,1 ms)` 范围、每档 2688 个声明出口的首次机制筛查：其中 896 个通向端设备，1792 个为交换机间出口。完整非零窗口及分组在摘要绑定的运行目录；未声明的端设备源队列不是零值。该文件是三个问题类别共同使用的正常来源，只保存一份。

按预存规则，1024 请求短段的首个持续较高发送量检查为 `768:6` 的 2～12 μs：发送开始字节为 491656 B，VOQ 面积约 1.374×10⁹ B·ns。交换机间同档没有满足两窗的较高发送量对象，保留 `768:18` 的中间服务分层（1～4 μs）作为另一检查。没有用最大峰值或业务改善排序。

这只能说明等待与一定发送量同时存在。实际忙碌时间、多个来流的竞争、信用约束和等待是否影响必要完成条件尚需核验，不能先把对象命名为根因。定义见[方法](../../method.md)，六个检查对象见[预声明选择](../../configs/scenarios/mechanism-cases.json)。
