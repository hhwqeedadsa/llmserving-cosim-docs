## 研究者核验与测量方法分别读取资料

执行概览和成因验证属于研究者核验，可以读取已保存的任务图、阶段、传输与队列记录。这些内部资料用来解释执行，不作为测量方法默认可得的输入。

观测比较另行准备端口计数、端口计数与队列两档输入，后续按已发现缺口逐项补充。测量方法接收整段声明的观测区间；内部身份、详细依赖、精确异常范围及配对正常反事实不自动开放。基线、端侧 profiler 和时间误差分别按原方案声明。这里只划分读取职责，不增加原方案之外的信息条件或评价指标。

概览中的各项数量必须能够追溯到记录字段或说明清楚的计算方式。未保存的就绪或资源状态标为资料缺失，不以首次发包、队列为空或另一事件时间替代。首批先使用现有记录生成概览；解释所需的资料确实缺失时，再记录具体缺项与影响。

## 何时单独补平台

原方案第六节所说的统一执行概览在本实验中实现。读取已有记录、跨运行统计和画图不改变平台执行行为。

只有实际现象需要进一步确认等待对象，而现有记录不足时，才在相应平台位置补充有界事实记录；先核对新增记录开关前后执行一致，再继续实验。端点服务模型按原方案的条件决定，分别实现排队、处理、释放及其上游影响，不以单纯延迟应用回调替代接收资源模型。

这类修改在 `current.md` 中明确其目标与验收，平台代码、最小功能检查及提交与实验分开。新增接口只在实现并验证后更新现行技术文档，不先创建空泛的平台版本计划。

## 执行与交付

先完成九组正常小场景和同口径执行概览，再依据结果选择扩展、定向对照及信息比较，最后选择少量完整场景。原方案中的运行数量、速率档位和采样粒度保持建议起点的性质；实际选用值及理由在运行前固定，不按期望结果调整。

任务切换、阶段状态、检查点和资源预算统一见 `current.md`。首批完成后先保留现象记录和下一步选择依据；未形成清楚解释的情况保持未解释，不为满足两个候选方向而制造正例。后续有明确发现时再形成深入解释与观测取舍，按原方案第七节交付。
