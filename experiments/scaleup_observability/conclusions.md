# 本阶段发现与研究取舍

本阶段最明确的测量需求是：**区分端点没有待发工作与已有工作但发送资源占满，并在有限记录量下保留短等待。** 出口计数与队列适合描述网络活动，但不能直接替代端侧等待状态或整轮执行影响。

本阶段按原方案完成正常探索、定向对照、成因核验、观测信息比较及两组完整首轮代表性验证。以下分别归纳性能现象、已解释的机制与下一步取舍；详细数值及操作保留在各结果页。

## 已发现的性能现象

| 现象 | 证据与适用范围 | 不支持的推论 |
|---|---|---|
| 增加发送槽使整轮更快，同时增加网络积压 | 多组输入的单槽/双槽配对；显式依赖、实际提交和释放核验；[发送槽结果](results-slots.md) | 网络队列增加就必然使整轮更慢；所有等待都由下游信用不足造成 |
| 发送槽收益受计算节奏影响 | 固定 seed=4，专家计算 0.5/1/2 倍时，双槽缩短整轮约 25.68%/19.97%/15.02%；[节奏结果](results-tempo.md) | 该范围外仍有同样收益，或参考计算已经硬件校准 |
| 减少响应数量和网络工作，不一定更早完成 | 同一 2048 B 读取拆成 16/4/1 份响应；单响应相对四响应使整轮慢约 10.6%～10.9%；[拆分结果](results-load-grain.md) | 收益完全来自某一种多路径或流水机制；数据到齐前变慢就证明了协议完成拖尾 |
| 物理出口局部变慢，整轮影响较小且非单调 | 六个干预全部命中业务，目标队列明显增加，整轮变化 −4～+780 ns；[出口结果](results-service.md) | 降速比例可直接换算成整轮损失；所有发生队列变化的出口都参与信用反压传播 |

计算与分段的扩展使用已见 seed=4，属于条件敏感性检查，不是新增独立输入复核。小场景全部为合成专家选择与参考计算。

## 已解释的等待，以及保留的解释边界

发送槽分支已形成完整证据链：任务的显式前驱已完成，发送任务（SEND）仍未提交；同一端点的实际发送槽被其他传输占用；相应完成回调释放资源后，待发任务才获得槽。增加槽数保持图、业务与计算不变，减少等待并缩短整轮，同时改变网络中的并发与排队。等待按计算端点（rank）的区间并集计量，不能把不同 rank 的重叠等待直接相加成可节省的整轮时间。

该解释定位到端侧发送资源，尚不说明占槽的传输为什么没有完成。信用、原生在途请求资源、接收处理或物理发送都可能影响传输生命周期；没有对应事实记录时不进一步贴标签。

响应拆分形成第二条路径与时序证据。业务字节不变、分段数实际执行正确；对六组全部 188 个同大小跨服务器任务的逐包核验，确认较细响应使用更多物理出口、每跳序列化更短。末跳真实发送结束加传播时间重建的全部数据到达时刻，与实际数据就绪事件一致，见[响应路径证据](results-response-paths.md)。多路径和流水推进的贡献尚未独立分离，逐请求资源等待也没有完整历史。所有同组 LOAD 的数据就绪到协议完成尾段为 0，较粗响应的变慢发生在最后数据到齐之前。

本阶段的小场景与六个出口干预中，没有获得持续信用停发及其传播的充分证据。没有为填满两个预设方向而新增接收消费或高带宽内存（HBM）模型，也未继续加强干预。

## 被动测量已经验证了什么

观测比较严格分开公开输入、测量程序和内部评价标签。计数、计数加队列、再加实际端侧状态来自相同执行；内部身份与完整依赖不自动提供给测量方法。规则固定后使用新输入复核，详见[基础比较](results-observations.md)和[端侧状态比较](results-send-state.md)。

在当时的新输入 seed=4、100 ns 采样下，加入端侧状态将检查范围从约 43.05% 降到 10.23%，但等待覆盖率从约 99.98% 降到 90.28%。按槽数拆开，双槽覆盖率只有 76.62%；1 µs 采样的整体覆盖率降到约 58.72%～67.52%。采样点判断正确不表示连续时间覆盖充分，“没有选中”也不能用来排除短等待。

这些结果支持新增端侧事实的价值，不证明某个复杂根因分类器有效。简单队列筛选规则本轮没有明显额外收益，也不等于队列信息对所有方法无用。出口干预的已知位置和时间只供研究者核验，本阶段没有把它们交给算法后宣称实现定位。

## 完整场景补充了什么

真实专家选择输入下的 128 rank、1024 请求、61 块完整首轮，两组均正常结束并通过工作量、导出和公开校验。固定 L1 上行出口半速后，其队列积分增加 57.60%，整轮从 48.446098 ms 增至 48.520336 ms，增加 0.1532%；其他两个观测出口的队列积分略降。八类任务的数据和协议完成 p95 均未变化。详见[完整代表性结果](results-representative.md)。

这进一步说明局部排队、全组分位数与整轮影响不能互相替代。完整场景保留原有一个发送槽和 4096 B 载荷，且仅采集三个代表出口的聚合记录；它没有验证小场景双槽收益、响应粒度对照或短等待采样覆盖率在完整规模下保持，也不能用来排除未观测位置的信用等待。

## 下一步应优先做什么

1. 优先比较在相同信息预算下怎样保留短等待：状态变化记录、窗口内等待时间摘要或其他明确规则。先固定可见字段与预算，再比较覆盖、检查范围和遗漏；本阶段没有实现这项后续算法。
2. 若选择深入响应拆分，先比较有依据的固定选路与逐包喷洒对照，明确需要区分的路径并行、流水和请求资源机制，再决定是否增加有界记录。已有逐包证据能核对数据推进，但不能独立分离上述机制。
3. 暂缓把持续信用反压、慢接收端或完整 HBM 服务建模作为必做开发项。当前没有足够现象证据说明它们是这批执行的主要解释，也没有实机校准来支撑硬件结论。
