# 首批正常输入

`reference/` 是本实验独立保存的小模型参考配置，来源为主仓 `9e9085b` 的 `experiments/mapping_value/configs/small/`。不复制旧实验的调用选择、干预或 E1–E5 规则；运行时不读取旧实验目录。`service.json` 的请求列表为空，由本实验 `prepare` 命令填充。其余参数及单位以配置为准。

| 项目 | 固定值 |
|---|---|
| 模型 | 8 rank，4 块（1 dense、3 MoE），隐藏维度 1024，16 个路由专家、Top-2、每 rank 两个专家 |
| 初态 | 所有请求在 0 ns 到达，prompt 64，KV 及首个生成 Token 已就绪，只推进一次完整 Decode |
| 输入组合 | input set 0/1/2 × 每 rank 2/4/8 请求，共九组 |
| 网络 | 两服务器、每服务器两芯片、每芯片两个 die；两平面，每平面两 L2；32 个交换机出口 |
| 通信 | 原生 STORE Dispatch、LOAD Combine，32 B 供数通知；8192 B 任务分块，1 发送槽、2 条逻辑 AIV 序列，逐包最短路喷洒，信用流控 |
| 原生资源 | 1 worker，STORE/LOAD 各 32 在途，请求标识池 256；实际 STORE 请求和 LOAD 响应体为 512 B，LOAD 请求配置 64 B |
| 观测 | 全部 32 出口同等计数及 VOQ/FIFO 队列统计；100 ns 窗口，[0,1 ms)，详细事件、操作阶段和五类应用来源；时钟无偏移漂移 |
| 计算与容量 | 保留逐 Token、逐专家输入的参考成本；设备容量 1,160,051,392 B/rank，通信预留 64 MiB，1024 个 KV 块；每组重新构图并核对容量 |
| 保存预算 | 原始压缩记录和导出各 128 MiB；图资源限制及事件限制见 JSON；累计宿主预算见当前任务 |

路径时延、分配时间和链路速率分别由 `scenario.yaml` 及公开 `resolve` 保存的有效后端配置确定。不要用 RTP 的 `tp_max_data_payload_bytes=4096` 推断 LDST 原生分段大小；实际值和有效完成分段数在概览中另存。

对每个输入组 `s`、rank `r`、本地序号 `q`、MoE 层 `l`，将 16 个专家按下列字符串的 SHA-256 原始字节升序排列，取前两个：

```text
scaleup-observability/v1/set={s}/rank={r}/slot={q}/layer={l}/expert={e}
```

`s=0,1,2`，`r=0…7`，`q=0…7`，`l=1,2,3`，`e=0…15`；摘要相同时按专家编号排序。请求编号为 `s*64+r*8+q`。每 rank 的 2/4 请求分别取前 2/4 个 `q`，因此同一组内请求身份和路由嵌套，不随批次重抽。三组路由独立生成，保留自然不均衡，不通过试跑筛选。

请求数同时更新服务调度和层批次限制，计算仍由平台按实际本地 Token、上下文与专家输入重新计算。`batch.json` 在执行前保存九组完整输入摘要及逐专家贡献数；输入被修改时拒绝启动。九组是三个输入组的嵌套规模比较，不能当作九次独立随机重复。

## 后续观测复核

`prepare-observation-source` 沿用上述生成规则，固定采用 `s=3`、每 rank 8 请求，生成发送槽 1/2 的一对新输入。其余配置相同；该输入用于规则冻结后的复核，不加入首批九组。

`observation-development-sources.json` 绑定前三组已完成的单槽/双槽开发参照，路径相对于本目录。它只用于复用既有研究产物；[观测操作](../observations-usage.md)提供不依赖这些旧目录的两次新运行完整流程。公开测量包不包含此清单中的路径、角色或条件。
