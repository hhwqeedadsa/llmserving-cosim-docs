# SimAI与320GPU真实路由实验方法

固定平台`44b55c1`。目标为实际SimAI调度、320个物理GPU端点共享原生ns-3、用户提供的真实专家选择，以及本次运行的逐包统计和Dispatch/Combine累计有效接受曲线。没有模型权重、CUDA执行、完整R1前向或硬件校准。

来源沿用`local_additions_20261027/intake.json`，只取15个完整JSON，按文件数字排序；899/1479不完整排除。原目录为`cognitivecomputations/DeepSeek-R1-AWQ/mmlu/`，保留原件SHA256。新增原件远端下载revision未知，不将参考目录revision当原件发布身份。有限ready-KV观察窗口为原MoE层3—4、Decode entry1—2，不复制或循环请求。

320GPU/40台8GPU服务器：rank0..255组成EP256，前12个请求的源rank=floor(i×256/12)；rank256..319组成EP64，后3个源rank=256+floor(i×64/3)。每rank每层分别1/4专家，E256/Top8/H7168/F2048/BF16激活。真实源请求数15，与320个物理端点分开记录。两个EP域共用一份网络，不能拼接独立运行。上游SimAI采用H100/DeepSeek671B容量参考，计算为公开小例相同声明参考；GPU标签不提供性能预测或实机校准。

Clos与HPN启发两种参考结构沿用`examples/scaleout_large_models/*-320.json`。Clos为5Pod、20ToR/20Agg/8Core、440边、400G单plane；HPN启发为2Pod、8rail/2plane、64ToR/16Agg/8Core、960边、每plane200G接入/400G上层。它们交换机与上联资源不等，不能把完成时间差称为相同成本下拓扑收益。没有NVLink旁路，同服务器不同GPU仍走声明网络；不是阿里生产HPN复现。

四条件：Clos/HPN启发×正常/指定数据和ACK丢失，各一次。恢复均为同一显式GBN、RTO40/160µs、最多4重试。故障规则只从原输入在执行前选择：g0.w0/原层3/Dispatch中，按字节降序、id升序选跨Pod消息，第一条的data offset9000丢2次，另一条的最终ACK丢1次。不看执行结果挑故障。保持两个结构内正常/故障原件、字节、计算、路径规则和资源相同。

竞争解释：正常/故障差来自恢复等待或额外队列争用；依逐包到达、实际重传和完成回调区分，不能把总差均归于排队。两拓扑差还受带宽、交换机数、路径、源部署跨Pod比例影响，不单因归因。真实路由并不保证把320卡打满；记录实际参与收发GPU及每rank负载，不宣称生产压测或总体代表性。

先生成和核输入及端口/MMU，再执行四条件。每次网络最多60秒、RSS2GiB/地址4GiB、仿真5ms、结果64MiB、产物256MiB；GPU上限320、交换机128、边2048、消息4096，端口计数采用port_dense。完整捕获全部节点、0—5ms、最多100000事件，payload9000/chunk36000，ACK间隔1；达到上限则保留失败，不自动删记录、提高额度或重跑。整个新研究根`runs/simai_scaleout_real_20261028/`累计1200受监控秒/1GiB，卷预留8GiB；无新构建、下载、安装或push。

执行后通过公开`simai-check`从原件独立重建源矩阵、核图/端侧字节/ASTRA依赖/网络反馈。公开`rdma-arrivals`对四条件各导出g0.w0、原层3的Dispatch与Combine；记录全任务逐rank端点、逐消息、逐包和曲线CSV。有效字节定义为接收协议连续接受，重复及GBN乱序丢弃不计入；另画物理到达、去重到达和源确认，不能称GPU可见。

科学图导出PNG/PDF/SVG，网页离线可读，提供拓扑、双端统计、数据和图的关联。只使用本轮320卡实际结果，不复用EP4曲线。网页提供原件hash与复现命令；原始数据不提交Git。先独立验证，再保存本地研究提交。
