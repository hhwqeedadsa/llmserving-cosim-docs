# 立即完整副本的延迟收益与代价

本方法在无冗余网络执行前固定。研究对象是四份真实R1-AWQ/MMLU路由的两层、一个Decode步片段，不是完整请求、满载集群或新算法。立即副本是成熟基线；本轮只估计它相对无冗余SR的条件收益与成本，延迟备用仍缺原生定时唤醒接口。

## 对照与不变量

保留128端点Clos、16模拟服务器、8ToR/8Agg/4Core、两个EP64部署、各层400Gbps及1µs/link。保留原始1472/1808/2675/6447、源rank0/2/4/6、原层3/4、首Decode入口、计算单位成本、BF16 TokenLayout、rank合并、完整EP门限、持久连接绑定、SR和参考DCQCN。复用既有eager正常/局部故障结果，不重新运行。

新增控制只取消第二组的显式重复执行，使用`sparse_active_groups/1`允许组1保持空闲。不改变端点数、EP大小、专家归属或原尝试图，不给备用组虚构请求/计算/KV。两组专家部署声明和全部232连接保持；备用请求的重复KV与计算/通信少一份是策略成本差异，单独报告，不以固定流量宣称相同工作量。比较保持相同逻辑输入，不保持物理冗余工作相同。

normal不额外注入故障；local仍为GPU28、DATA、`[0,20µs)`全丢，控制包不丢。相同规则不保证内生包数相同，要分别报告真实到达和丢包。不是链路故障、整机失效或全网高丢包。

## 竞争解释与判据

1. 正常时重复任务占用共享网络，eager可能变慢；比较原图实际门限、ECN、控制通知与客户端就绪，不把网络排空代替结果。
2. 故障时健康副本可能避开原地SR等待；必须以无冗余条件的完整图完成作对照，不能以同一次运行内原/副本首尾差替代收益。
3. 健康副本的路径、源位置和共享竞争与原尝试不同，因此本轮收益只属于该部署与固定故障条件，不推广至任意MoE/故障或相同流量负载。
4. 先验证原始来源、整个primary图、协议和拓扑相同，全部原门限、接收、ACK和退出真实发生；不满足即停止收益解释。

指标：有限片段结果就绪、全部尝试完成、服务排空分别记录；唯一有效字节、实际源发送字节（含重传）、源包数、声明计算工作量（各rank累计）、实际物理尝试数及KV声明分别报告。空闲端点数与数据活跃rank不同。数值/KV等价、初态建立、取消、其他独立请求负载、GPU校准和吞吐未模拟。

可用这四个确定性结果做一个有条件的期望延迟计算：假设任务只可能是本normal或本local，故障概率为p，且无其他负载或成本，用两条件线性加权求期望。若正常额外等待和故障节省均为正，临界p为`正常额外等待 / (正常额外等待 + 故障节省)`。这不是测得的生产故障率、总体统计、经济收益或包含资源成本的盈亏点；各条件一次执行不产生置信区间。

## 执行限制

新根`runs/whole_control_20261030`，累计900受监控秒/新增512MiB、保留8GiB。无冗余normal/local各一次，native60秒/RSS1GiB/地址2GiB/模拟5ms/128MiB产物/200000完整包事件；CPU每项120秒。零构建/依赖修改/下载/GPU。失败保留，不扩限、不重跑成功网络。平台提交先冻结；实验只调用公开CLI及读取已保存结果，不导入测试驱动。
