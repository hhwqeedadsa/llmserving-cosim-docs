# 32位通知事务功能验收

本次补齐原生MRT1事务的4B通知功能，不是通信优化算法。`fetch_add32`和`local_wait.bits=32`显式选择位宽，原`fetch_add`及缺省等待保持64位。接口、独立准备/执行/审计命令见[公开示例](../../examples/scaleout_atomic32/README.md)，要求见[规范](../../docs/tasks/atomic32_spec.md)。

交付[网页](report.html)及[源码/输入/二进制/资源摘要](verification.json)。原始日志与结果保存在`runs/atomic32_transactions_20261030/`，不提交构建和大文件。版本化脚本可重新生成独立输入，不依赖该历史目录；已有成功网络不需要为阅读报告重跑。

## 验证结果

| 条件 | 请求/回复帧 | 去重载体字节 | 源实际发送字节 | 最终窗口 |
|---|---:|---:|---:|---|
| 正常静态 | 9 / 7 | 608 | 608 | 一致 |
| 两次丢包、静态 | 9 / 7 | 608 | 792 | 一致 |
| 两次丢包、在线前端 | 9 / 7 | 608 | 792 | 一致 |

三种条件均为128端点Clos、20交换机，仅四个rank活动，三条持久连接共六个有向流。一次丢首个32位请求，另一次丢首个原子回复；每条规则实际命中一次。每条件只运行一次，目标只应用9个请求；原子源完成须等请求ACK、对应旧值回复和本连接前序退休，后继复制/发送由实际事件推进。相邻哨兵未变、无活跃源或复制保护、队列关闭且物理排空。在线回调逐项对应原生进度时刻和旧值。

独立审计从实际source TX及目的端`payload_delivered`重建MRT1帧，不调用平台解码器。跨流内存事件按`order`重放，每条件25项；再比对完整最终窗口和显式预期。重复发送不等于再次目标应用。源码缓存的帧重放另由CPU测试在计数器已清零后验证，网络重传由载体去重，两层保证分别核验。

恢复条件额外184B来自五次重复发送：请求stream0的[48,84)在25.012µs重发36B；回复stream1于41.031/41.032µs发送[0,36)、[72,112)，合76B；46.017/46.018µs超时发送[0,36)、[112,148)，合72B。首个快速重传反馈仅确认[36,72)，后两段的实际反馈尚未到源；超时也早于缺口累计ACK到达。它验证既有恢复语义，不是32位功能的性能收益，不据此修改恢复策略。

新32位核心通过4,279项断言、196个独立算术/位置组合；旧64位核心7,085项断言，唤醒核心50项断言。Python相关单元共53方法（4＋27＋15＋7）。九类非法输入在Python及两个新原生可执行程序均拒绝，后者共18次在Fabric构造前拒绝，无网络。六类结果篡改拒绝：旧值、提前退休、等待位宽、邻居字节、交付字节和不完整包捕获。

公开`rdma-build`从固定原生提交构建，442个编译单元检查为O3、保留Wall/Wpedantic。逐项核对构建时源码与当前源码、执行时输入/二进制、加载的原生库及其hash；13项固定依赖核查通过。构建431.050秒，采样进程组峰值RSS1,831,403,520B，保持既定预算。完整累计资源见JSON；初步只读审计曾把包表第10列队列长度误当负载长度，已按列名读取，未重跑网络。

## 适用边界

人工字节、稀疏活动rank、本地7ns声明成本；没有真实路由、完整671B模型、GPU执行或硬件校准。MRT1 verb4/5及反向可靠流不等同RoCE扩展原子、Atomic ACK或GIN硬件完成。上下文计划编译器仍生成其原64位操作；完整旧低延迟索引计划还未绑定本次网络，现代direct不套用旧库规则。后续须保留真实通知、发送发布及资源释放语义完成绑定，才能进入完整真实专家通信的研究比较。整体目标保持active。
