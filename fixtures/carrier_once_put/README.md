# 有序put目标状态验收

平台基线`cb67c6f`。新增显式`buffer_model.target_delivery="carrier_once_put/1"`，要求完整请求缓存额度0；只用于既有v4注册源put。默认请求重放缓存保持。[规范](../../docs/tasks/carrier_once_put_spec.md)与[公开用法](../../examples/scaleout_rdma_transactions/README.md#有序put不保留完整请求缓存)说明适用合同及拒绝条件。

## 实际检查

8GPU小Clos，GPU0→GPU4一条持久连接，6次40B帧（32B功能头+8B数据）依赖前一次真实完成并复用同一目标地址。源池40B；新模式完整请求缓存0，默认对照缓存240B。相同网络、操作、窗口、路径与完成条件不变，配置及缓存状态分别报告。

| 条件 | 实际结果 |
|---|---|
| 旧/新默认足额缓存 | 完整result逐字节相同 |
| 默认/新模式健康 | 去除明确的策略与缓存字段后完整结果相同；均完成6次put，finish为72,360ns |
| 新模式一次数据丢失 | 真正drop1包、源发送7包、目标应用6次；finish为92,360ns |
| 新模式一次ACK丢失 | 真正drop1包、源发送7包、目标收到1个重复包，仍应用6次；finish为92,360ns |
| 公开在线入口，ACK丢失 | 实际回调继续追加6个操作；包、序号和窗口独立核验通过 |
| 既有源隔离回归 | 新程序默认结果与前轮已保存原件逐字节相同；原部分失败和目标缓存保留不变 |
| 拒绝 | CLI/native各6类无效策略或缓存组合，在产生result/输出目录前拒绝 |

39项不同Python单元（有界缓冲13、事务17、在线定时器9）、内存核心7,085项断言、稀疏核心6,483项断言及13依赖检查通过。后两者是断言数，不是网络样本或独立单元数。只增量构建3个事务消费者/2入口及2个内存检查程序；固定库与旧程序未改。

严格编译首次发现旧测试10个`Window`聚合初始化省略pages。仅补全测试中的`logical_bytes=0,pages={}`，保留原件与失败日志；没有关闭警告、改变生产默认值或重跑已构建消费者/网络。一次临时结果查看错误读取`faults`键，实际字段为`fault_drops/fault_injection`；后续核对已有结果，不重复网络。最终检查和脚本留在持久目录。

## 独立核验与迁移

`audit.py`只用标准库，适用于本组单帧put。按实际捕获RX独立重建连续字节前缀，重复旧包不再生成帧；解码实际MRT1数据，重放目标窗口，核对源池、线上ACK、lease和目标序号/缓存。分别拒绝篡改包、池峰值、目标内容、缓存字节和重复应用事件。新增第五项篡改后，仅重新审计已有六份结果，没有重跑网络。

```bash
python3 -B fixtures/carrier_once_put/audit.py \
  --result /path/to/ack/result.json --work /path/to/inputs/once.json \
  --output /path/to/new-audit.json
```

7次初始网络（6功能+1回归）和1次迁移后的公开健康网络，共8次。持久入口为`runs/carrier_once_put_checkpoint_20261024/README.md`；包内有源码、输入、结果、2个原生入口、2个内存程序和8个固定ns-3库。新源码根/空cwd重新生成拓扑并运行公开示例，8库从包内加载；事务与端口执行字段相同。普通公开协议没有原始capture/queue_metrics，因此不声称完整result相同。六份离线审计复算逐字节一致；同Linux宿主验证不等于跨平台构建或硬件校准。

小摘要见`verification.json`、`recovery.json`、`closeout.json`及六份`*-audit.json`，大原件和命令/日志/最终收据在持久包内外。前期外层驱动与临时查看并未全部监控，资源统计只声称保存的监控范围，不称完整日历耗时。

本能力减少的是完整请求内容缓存；序号、解码临时数据、包和观察副本仍存在，不是总内存0。不能处理应用层重放或原子返回值，也不撤回晚到包、不回收失败源lease、不授权远端地址复用。原有32远端操作等预算保持；不是无限连续服务、现代GIN实现、新恢复算法或论文性能收益。研究影响见[集中报告](../../docs/reviews/有序载体与目标缓存_恢复强基线修正_20261024.md)。
