# 贡献与尝试生命周期验收

范围是调用方事件驱动的无计时CPU核心及公开`contribution-check`，不包括ASTRA/ns-3服务接入、自动副本恢复、GPU模型、数值张量或创新收益。没有运行新的小网络，也没有重跑历史网络。

14项新增单元检查通过，其中覆盖四个结果在同一时刻到达的24种顺序、完整不重叠覆盖、原/备用任一先到、重复/迟到、错误身份与版本、取消后已发计算、全部失败、资源所有权、ID使用记录、预算及非法事件原子拒绝。21项相关回归通过，覆盖原token传输、阶段完成与消息准入。

[公开命令流程](../../tests/integration/check_contribution_workflow.py)从新目录运行五次CLI调用，验证完整人工输入、仅逻辑到齐的合法前缀、错误结果拒绝、拒绝覆盖、输入迁移后报告逐字节一致。样例25事件中，贡献在人工标签7到齐，原租约12关闭、13退休，14迟到结果不重复提交；这些是人工回调标签，不是测量时延或性能收益。原/备用都失败时，退出资源也不会补出缺失贡献。

入口见[示例](../../examples/contribution_attempts/README.md)，规范见[接口说明](../../docs/contribution_attempts.md)。详细命令、退出码、源码身份和资源见[收据](receipt.json)，人工完整输出见[报告](example-report.json)。宿主原件留在`runs/contribution_attempts_20261030`。本轮零构建/下载/安装/GPU/依赖修改，全部后端行为保持原定义。

下一步需把身份与租约绑定到同一次实际服务的回调、共享物理资源及旧尝试排空；当前核心只验证调用方声明，不能发现物理缓冲别名、跨实例资源或虚假的回调。不能将该功能验收写成真实流量恢复已跑通。
