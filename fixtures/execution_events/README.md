# 实时被动执行事件验收

该增量把同一次ASTRA/ns-3服务的节点issue/complete、消息post、接收完成、发送确认、任务图退出及网络排空实时交给Python。默认关闭；不是离线推测时间，也没有实现备用专家调度或取得恢复收益。配置及稳定接口见[用户说明](../../docs/execution_events.md)。

## 方法

执行源码固定于`b405711bc65ef23e2e8bb09bd1e9d9485c18dae1`；ASTRA依赖补丁`04948bc1dd88`、LLMServingSim指针`77da4a672047`。`build.py`读取已有Ninja依赖记录和编译数据库，对`Workload.hh/astra_adapter.hh`的27个受影响对象重新编译，在独立目录重建archive并链接新服务。旧输出逐项hash保持一致；没有重新配置、下载或安装，不是冷构建验收。

CPU检查覆盖接收完成与发送确认分离、未完成图不得退出、前驱和声明计算耗时、重复/乱序/字段/身份/预算拒绝、完整前缀不冒充排空及默认控制入口兼容。8项新增与37项相关检查共45项通过。人工回调只检查逻辑，不用于性能。

两个新的功能条件从[128端点Clos人工示例](../../examples/scaleout_token_transport/README.md)准备，公开`scaleout rdma-run`各执行一次，仅改变顶层`execution_events`配置。拓扑为16服务器×8端点、8ToR/8Agg/4Core、168链路、单rail/plane、每层400G、1us/链路。两个EP64、E256/Top8、H256、两层两步，每rank每层4专家；四份不同人工请求，31个数据活跃rank。使用按目的rank去重、卡内合并、每份额外贡献100ns声明成本、相同SR及参考DCQCN。未注入故障，不是满载集群、真实R1或GPU测量。

`tests/integration/check_execution_events.py`只检查已经保存的两次执行，既不重放网络也不构建。它逐字节比较全部任务图，逐字段比较除新增事件计数外的完整网络结果（含逐包、队列、消息及所有时间），并对照独立ASTRA节点日志。另复制完整运行，使用公开`rdma-check`完成可迁移检查及五种篡改拒绝检查，原件hash保持不变。

两次完整网络结果在去掉唯一新增的`service.execution_events`计数字段后完全一致。在线事件为7416条节点事件、248条消息事件、4条图退出及1条排空；不包含bootstrap，序号连续，没有丢失或采样。真实例：消息2、rank0→6，在1.030us提交SEND，3.058us接收回调，5.060us发送确认；中间2.002us只表示两个生命周期里程碑的差，不是优化收益或可以直接释放原资源的依据。本例62条消息的接收回调均早于发送确认。

公开检查拒绝缺少drain、错误接收rank、改写回调时间、重复事件和截断末尾；正确副本通过检查。首次离线检查误把包事件数量和数组字段颠倒，修正检查程序后完成，未重跑网络。首次回归选择表达式不支持`|`而选中0项，保留失败后改用明确文件清单。依赖提交首次缺少子模块作者配置，使用主仓库已有身份的命令级参数完成，没有修改全局配置。

预算根`runs/execution_events_20261030`累计1200受监控秒/新增1GiB/卷保留8GiB；构建300秒/RSS2GiB/地址4GiB/jobs1，实际27对象闭包96.027秒、峰值采样948498432B。每个native限60秒/RSS1GiB/地址2GiB/模拟5ms/128MiB产物/完整包200000条；执行事件上限32768。两个网络各一次，未升级依赖、下载、运行GPU或重跑既有成功网络。完整资源和命令保存于[收据](receipt.json)及本机原件；[独立核验](verification.json)保存精简结果。
