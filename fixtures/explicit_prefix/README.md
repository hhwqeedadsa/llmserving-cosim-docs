# 原生显式修复段功能验收

公开输入和运行方式见[128Clos示例](../../examples/scaleout_explicit_prefix/README.md)，要求见[执行规范](../../docs/tasks/explicit_prefix_execution_spec.md)，可读结果见[网页](report.html)、[独立检查](verification.json)及[来源/资源收据](receipt.json)。本目录为平台功能验收，不是论文方法的收益实验。

生成全新128端点、20交换机Clos及4条人工持久双向字节流；每流先发64KB，再在100µs之后发16KB，总唯一业务字节320,000B。固定端口用于覆盖Agg132的DATA和ACK，保留选择性重传和DCQCN参考。六个条件各执行一次：旧/新默认正常、只过滤旧候选的故障、实际封装显式段的故障、12µs恢复链路、零延迟全局改路。首轮、末业务ACK与网络排空分别报告，不能把首轮改善当完整推理加速。

`audit.py`复用已有独立逐字节区间/SACK检查，再核对实际物理TX/RX及包长/序列化、原生队列积分和MMU终态、每流一个QP与原ACK完成。新增检查逐封装包的132→129→133三动作、真实38B外层在两跳的开销、拆封后包长、GPU入口无外层，以及普通转发的已到控制通知与原ECMP哈希；不是只看意图日志。4类篡改覆盖缺失外层开销、错误物理出口、缺失合流及虚构ACK。

CPU检查另验证DATA/ACK/NACK/CNP四种实际序列化字节往返及CE传递、8类非法包头/多NIC输入、16个原生计划与独立Python计划一致；不执行Simulator::Run。3项公开Python配置方法及23项相关回归覆盖现有模式、临时恢复、非法字段/规模/plane/NIC。9项原生非法输入要求在分配网络前拒绝。

首次CPU断言误把L2开销假设为14B，实际固定后端PppHeader为2B；原测试及失败日志保留，修正预期为2+20+8+2×4=38B，未修改协议算法或原生依赖。原始资源根`runs/explicit_prefix_execution_20261030`保留全部命令、输入、失败和结果。预算1800受监控秒/2GiB/留8GiB；构建compile600秒/外层900秒/RSS2GiB/地址4GiB，其他阶段120秒/RSS1GiB/地址2GiB；每网络60秒/模拟5ms/包及队列200000行。失败不扩预算，成功网络不重跑。

首版独立检查漏统计真实绕路的CNP合流，因总动作数不一致而失败。保留原检查器与日志后，补查全部CNP路径；本例每对端点只有一条声明流，CNP哈希的fid据该输入还原，不读选中的路由或未来记录。没有改平台、调故障、删CNP或重跑网络。

封装是项目内IPv4协议250，不是标准RoCE、MPLS、Remote-LFA或TI-LFA。实际头部和原生服务开销已计入，额外处理/检测/路径分发/MTU碎片仍未建模；原生控制队列不计数据MMU。没有模型或GPU执行，没有升级依赖，没有真实MoE收益或新协议创新结论。后续在该更强基线上另立真实专家选择的研究对照。
