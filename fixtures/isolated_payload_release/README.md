# 失败源隔离后的复制池回收验收

平台基线`ac413a3`。[规范](../../docs/tasks/isolated_payload_release_spec.md)和[公开示例](../../examples/scaleout_rdma_transactions/README.md)对应可选的`release_copied_payload/1`。原生ns-3及全部依赖保持锁定版本。

## 检查对象与结果

人工8GPU小Clos中，GPU0的两条连接共享40B复制池，每次put包含32B MRT1功能帧头和8B数据。连接0失败，连接1健康；健康操作2等20μs本地操作，操作3等操作2实际完成。操作4属于失败连接。

| 条件 | 实际结果 |
|---|---|
| 旧程序/新程序默认 | 完整result逐字节相同；池持续被占用，操作2、4未发布，操作3因前驱未完成而未提交 |
| 开启，持续丢最终ACK | 60,000ns实际隔离后回收副本；操作2、3分别72,060/84,120ns完成 |
| 开启，持续丢数据 | 同样释放池并允许健康连接完成；失败事务没有ACK或完成 |
| 开启，1μs重传计时器 | 3,000ns隔离并回收后，旧包仍在6,036ns到达并写入目标；源lease保留 |
| 健康关闭/开启 | 去除声明的策略元数据后，原执行结果完全相同；没有隔离丢弃 |
| 在线会话 | 先拒绝超出目标缓存的整批请求，无部分接纳；随后原有效批次正常推进健康连接 |

失败条件保留`passed=false`、5ms截止、原生退出1及部分结果；没有把功能验收通过写成全部事务成功。失败操作0、4的源lease仍保留；目标去重缓存和应用队列信用没有因副本丢弃释放。重叠lease引用字节不能加成物理内存。

初始8次功能网络、2次受影响公开回归、1次恢复后的公开健康网络，共11次实际网络执行。非法策略CLI/native各8类拒绝；49项不同单元通过（有界缓冲10、事务17、持久流13、在线定时器9），13固定依赖检查通过。只增量构建受布局影响的5个消费者、链接3个程序，没有重建或修改依赖。

## 独立核验

`audit.py`只用标准库，针对本组单帧put输入，从真实池事件重放占用，按实际包字节解码MRT1，并根据目标连续接收重放窗口；核对线上ACK、失败后无源TX、保留lease和目标缓存。它不导入平台执行实现。修改包内容、池峰值均被拒绝；存在隔离丢弃的条件还拒绝提前丢弃和伪造失败ACK。

```bash
python3 -B fixtures/isolated_payload_release/audit.py \
  --result /path/to/isolated-ack/result.json \
  --work /path/to/inputs/enabled.json --output /path/to/new-audit.json
```

`online.py`通过公开`NativeTransactionSession`执行整批拒绝及后续有效提交；命令参数见`--help`。这些脚本是功能验收工具，不是研究实验入口。

初次单元检查因旧手写拓扑缺`delay_ns`失败，仅修正测试输入，断言与生产校验不变。首个结果检查器误以为未启动的操作3已经注册，读取既有结果后更正。原脚本、失败日志和`checker-correction.json`保留；没有重跑已完成网络或提高预算。

## 检查点与边界

版本化摘要见`verification.json`、`recovery.json`、`closeout.json`和`*-audit.json`。本机持久包位于`runs/isolated_payload_release_checkpoint_20261024/checkpoint.tar.gz`，12,361,002B；SHA-256为`567f4b7d83ff79ae609c806f0dd58df418d199e427dd10966d886017c58839f6`。同目录README说明恢复操作，完整监控和最终收据另存包外。

568成员含清单、源码、小例、原始输入/结果、三个程序和八个原生库。在新源码根、空cwd重新生成公开拓扑并实际执行健康示例，八库从包内加载；事务和端口执行字段相同。公开普通协议没有capture/queue_metrics，因此**没有声称完整result逐字节相同**。恢复的8次独立离线审计均逐字节相同。这是同Linux宿主检查点，不保证跨平台编译或硬件校准。

副本回收依赖当前载体的实际复制与源冻结语义；它不撤回在途包，不释放源窗口，不保证远端旧访问退出，不等价GPU DMA或现代GIN。观测仍保存包内容，不能由池字节减少推断总RSS/HBM减少。这是平台生命周期修正，不是论文性能收益或新的恢复算法；研究后续见[集中说明](../../docs/reviews/失败连接复制池回收与晚到写入边界_20261024.md)。
