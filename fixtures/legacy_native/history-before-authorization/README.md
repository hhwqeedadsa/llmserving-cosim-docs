# 完整旧低延迟计划接入：未完成验收记录

本轮实现了专用`scaleout deepep-run`，把完整旧DeepEP v1.2.1 BF16索引计划连接到原生持久流、32位目标内存与同步四条发布核心。首次完整运行失败；**当前不是已通过的完整通信基准**。可查看[网页](report.html)、[核验/源码/资源摘要](verification.json)和[公开操作](../../../examples/legacy_native/README.md)。

## 已取得的证据

- 新公开构建成功：444个编译单元为O3，固定13项依赖检查一致。BF16消息按固定源码跳过16B元数据后读取功能专家输入，未执行数值专家或GPU。
- 完整EP32/E256人工计划有16,448操作、66,144事件，保留零token count/flag；仅4个源rank各1个Top8 token。物理网络为128端点Clos、20交换机、168链路，EP与网络端点数分列。
- 第一次正常条件在4,237ns异常退出，`execution_error`为`reference feedback event budget exceeded`。已记录10,000条全是实际`source_sent`，其包UID均能对应实际源包记录；完整无丢包条件至少需要32,464条同类日志。
- 当时宿主原生执行约1.72秒、采样RSS约451MiB；这是显式参考日志上限，不是磁盘不足、内存超限或推理完成时延。原始25MiB结果保留于`runs/legacy_native_20261030/normal/`，未覆盖。
- 之后新增Python和原生构网前容量检查，显式计算帧头、请求、反向原子回复及按工作边界分包的必需发送数；拒绝整个不可能的输入，不删除通知。4项新Python方法、39项流相关回归、1类公开入口及8类原生输入拒绝均通过。此前16项C++图断言、6项索引及4项32位输入回归见原始CPU日志。

## 尚待验证

2026-10-31逐包审计补强：按实际包UID、端点/NIC、序号、长度和内容绑定源TX、目标RX及连续交付；重复发送按字节区间去重。“normal”表示不额外注入故障，不能要求其必然零重传。另增加最终计数器/数据项的完整覆盖、唯一工作与时间顺序检查，防止缺失的记录被误判为通过。4项CPU方法覆盖14类包记录篡改及5类存储覆盖错误；这些手工记录不是网络执行。

只读核对4份已有128端点原件：旧EP32中断条件10,001个源包、3,562个已交付包，发送454,884B、连续交付175,656B；这是含MRT1帧头的载体负载，不是模型激活有效字节、完整业务结果或新性能收益。另3份历史32位事务小例（稀疏活动rank）中，正常608B唯一/608B发送，静态与在线恢复均608B唯一/792B发送，额外184B正确计为重复发送。所有原文件hash保持，零新网络；这3份旧事务成功不能替代本轮完整EP32验收。

2026-10-31补充核查与修复：新增每远端上下文的最小发布跨度检查。本例为2、配置32；深度1无法让一条数据及随后通知都准备完成，未发布数据又不可能产生ACK。真实队列核心CPU检查覆盖0..16 token、1..4轮、6档深度及两种显式完成调度，共816情形/1,384断言；旧发布核心1,461断言/108状态、5项Python方法通过。公开及原生入口各新增一次深度1拒绝，均在构网前；这些CPU小逻辑检查不执行任何小规模网络。

同时，旧失败原件中264项本地copy/store全部带有远端队列票据和网络ACK时间，另256项还有回复时间。当前代码已将本地操作绕开发送队列：WQE、发布、ACK和回复字段均−1、返回值null，实际本地应用与完成独立记录；远端原子也仅在反向回复实际到源后填写返回值。原生构建已通过，修复后的本地执行、输出及完整审计尚未由成功网络验收。原失败结果不修改，不能按新语义重新解释。

完整正常执行、故障执行、全量DAG/内存/双buffer重放及网络排空均未验收。`audit_legacy_native.py`已经提供独立解码和重放逻辑，但尚无完整成功样本，不能以脚本存在或部分回调代替通过。故障输入已经准备，未启动故障网络。

## 只读复核

保留原始运行目录时，可将摘要输出到一个新路径；此命令不启动网络：

```bash
python3 -B tests/integration/summarize_legacy_failure.py \
  --root runs/legacy_native_20261030 --output /path/to/new-summary
```

脚本逐项核对旧输入hash、实际发送UID、容量下界、构网前拒绝、当前构建源码及加载库身份，并汇总已有外层监控阶段。计时不把内层编译/原生监控再加一次；生成摘要和之后文档检查不包含在该快照的累计数内。监控根预算1800秒/1GiB/卷留8GiB，未自动提高任何限额，没有重跑成功网络。

MRT1反向可靠流不是RoCE Atomic ACK；功能可见性/专家拷贝零成本，没有GPU或生产硬件校准。本轮是平台实现与问题修复，不是新的恢复算法或研究收益，整体目标继续进行。
