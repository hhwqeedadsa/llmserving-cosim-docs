# 旧低延迟同步发布策略验收

本项在已有GinWorkQueue上增加独立[策略核心](../../backend/rdma/low_latency_posting.hh)，不重做已存在的准备/发布核心或现代事务staged_prefix。公开构建运行见[CPU示例](../../examples/low_latency_posting/README.md)，实际命令、代码hash、退出状态及功能输出见[验收摘要](verification.json)。

新C++检查包含1,461项断言，独立oracle枚举108个合法交错状态；公开示例21组参数组合完成，3组非法输入返回预期失败。旧队列回归4,976项断言通过，原有单条/批量状态枚举分别49/122个。编译使用已有C++17工具链及`-Wall -Wextra -Werror -pedantic`，无编译警告或测试失败。

| 检查对象 | 已验证行为 |
|---|---|
| 0/1/3/4/5/8/9条put | 四次阈值按逻辑message index判断，独立于每条put的WQE个数 |
| 每put占1/2/3个WQE | 注册边界拆分保持数据字节；发布覆盖完整reservation，不截在put内部 |
| 尾部通知 | 0条数据也可通知；不足四条的数据不会自动发布，通知可推动同QP前缀 |
| 准备空洞 | 后一生产者描述符就绪但前缀有洞时不可Post；补齐前项后才能继续 |
| 迟到旧发布 | 后面通知先发布后，较早的条件Post取max，保持原发布前缀且不重复消费 |
| 完成与槽复用 | 发布和消费都不归还额度；外部合法累计完成才允许复用整段槽 |
| 生产者未返回 | 较后操作已发布且工作完成，较早生产者尚未处理Post时仍不能关闭 |
| 空闲后追加/多队列 | ticket与前缀保持递增，另一个QP不被发布或完成 |
| 输入与资源约束 | 拒绝地址溢出、空洞注册区、错误跨度、重复ID、非法message index和超预算跨度；拒绝不占用ticket |

独立oracle只用每条WQE准备位、每个生产者返回位和NIC/CQ位置生成合法动作，不通过被测类的CanPost/CanPrepare选择动作。比较保留、准备、发布、消费、完成位置；这仅覆盖指定的有限状态，不是GPU并发或任意实现的形式化证明。

实际运行根`runs/ll_posting_core_20261030`，两个监控阶段合计3.530秒，峰值采样进程组RSS163,192,832B、监控产物峰值835,584B。预算600秒/128MiB/留8GiB，单阶段120秒/RSS1GiB/地址2GiB；预检与最终文档检查不在监控总数内。只编译两个新CPU程序和旧队列检查，没有完整模拟器构建、网络运行、安装、下载、依赖修改或GPU。

源依据固定DeepEP v1.2.1的同步分支。注册表、message index和外部完成均由调用方明确提供；示例的完成是人工功能输入，不是ACK/CQE观测。正常availability及每reservation不超过深度是有界核心的支持条件，不声称精确模拟低延迟库跳过槽检查。独立策略没有改变PersistentStreams或RemoteTransactions的默认行为，也没有接入modern direct或推理前端；实际网络仍须在128/256/512端点Clos上另行验收。

后续须解决完整旧低延迟EP32/E256操作表示与预算、实际QP绑定和相应通知/完成事件，按[规范](../../docs/tasks/posting_boundary_spec.md)接入。不能把本项CPU通过写成完整DeepEP、网络性能改进或论文创新收益。
