# M10 CANN 构图的等价索引

本步仅调整 `cann.py` 单次构图内的计数和查询。状态计数预先按 `(src_rank, expert_id)` 累计；贡献按源/目的 rank 保存有序引用；传输按 Dispatch/Combine 和源/目的 rank 保存有序引用；芯片归属及 rank 序号各建立一次。索引随构图调用结束释放，不进入执行计划或跨轮缓存。

消息、传输和图节点仍按原循环顺序创建。Combine 的专家/源 EP 序号/Token 排序、lane 内旋转、零计数发布、同芯片本地准备、数据就绪与发送完成依赖、分块、来源和费用保持。没有删减 Python 重构校验或独立 C++ 校验，没有修改全模型深复制、图合并、协议或调度。

## 等价性与首层测量

[golden.json](golden.json) 在修改生产代码前由 `f9b3751` 保存，含旧源码和用例生成器摘要及 24 组完整计划 SHA-256。比较保留对象字段与列表顺序，覆盖 EP2/3/5、非连续 rank、每 rank 三专家、不同 Top-K/批次、零 Token 成员、无物理部署、三种本地性、lane=1/2/3/48、H=1024/1025、分块=257/8192 和发送槽=1/2。独立贡献/字节/依赖测试继续运行，另验证篡改计数、来源及依赖被拒绝。

全组无 Token 的图仍按旧规则拒绝；空服务由服务层处理。最初构造基线用例时误将全空图作为有效输入，被未修改的旧校验拒绝；记录该失败后将有效用例改为单请求且其余成员为零 Token，并单独保留全空图拒绝测试，未修改生产规则。

实际目标首层使用上次核验的同一 bundle，在独立受限进程中分别调用旧/新构造器，保留全部生产校验，再对完整计划及逐记录来源计算摘要。旧代码从固定本地 Git 提交读取并核验 SHA，无联网或替换当前模块。测量如下，只有一次新旧样本，不代表所有输入稳定达到同一加速比：

| 指标 | 旧实现 | 本步索引实现 |
|---|---:|---:|
| 构图（含原校验） | 34.851 s | 4.193 s |
| 交付 | 64992 | 64992 |
| fabric / local | 64556 / 436 | 64556 / 436 |
| 节点 / 依赖边 | 130694 / 2391386 | 130694 / 2391386 |

完整计划与来源摘要均为 `d93005bbb587d8c5333e4e2a3001350157af53381364e2d5cab8a920121700dd`。该样本构图约快 8.31 倍；摘要序列化、输入读取与退出清理不计入表中构图时间，仍计入外层进程总时间和采样峰值。它只改善生成图所需的现实时间，不改变仿真时间，也不声称减少完整图驻留内存。
