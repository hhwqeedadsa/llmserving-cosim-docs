# M10 完整模型构图后直接导出

`generate.build_export_full_model` 接收构图输入，调用原 `build_full_model` 完成子图验证、身份分配、完整重构与逐字段检查，然后立即调用内部写出函数；只有写出完成后才向调用方返回可变计划和目录。构图器和校验器没有改动，减少的是同一次封闭调用中、紧接构图校验之后的重复完整重构。

既有 `export_plan(plan, output)` 仍完整校验调用方提供的计划。新入口不接受现成计划、跳过校验开关、验证凭据或任意修改计划的回调，没有跨调用缓存。返回计划若再被修改，后续通用导出仍检查并拒绝非法内容。原离线入口的来源声明只写入相同的非执行字段并复制外部证据，不改变图或计算。

写出函数只是从原导出器中提取出来，其语法树与旧校验调用之后的写出主体一致；Chakra 编码、JSON 格式、文件摘要、资源上限和清单均未优化。完整首轮探针采用新路径并记录实际进入写出函数的阶段。普通服务仍使用通用可变计划导出入口；服务调度没有改动。

## 等价性与拒绝检查

[baseline.json](baseline.json) 固定旧提交 `3bf0f90` 与原源码摘要。单元测试从该本地 Git 提交加载旧导出器，比较四组完整图及 plan.json、generation.json、各 rank Chakra 的全部字节，覆盖单 MoE、dense 穿插、无 shared、八块/32 请求/小分块、上下文、零 Token 成员、来源及非默认身份。新路径仍调用一次完整模型验证，共两次合并（构建、重构校验）；旧构图后通用导出共三次。

19 项相关单元测试通过。调用方输入与来源证据保持隔离；修改返回计划或 JSON 重新加载的普通计划之节点、依赖、来源、传输字节及费用后，通用导出仍在创建目录前拒绝。非法构图输入被拒绝；注入写出失败时没有成功清单，失败后新调用不沿用任何验证状态。测量包装正常和异常退出均恢复原函数。

首次测试因动态加载旧导出器时未设置 `__file__`，无法找到锁定 Chakra schema；修正新测试的模块位置后通过，生产校验和预期产物未改。另一次预检在新资源对照尚未写完 result.json 时提前读取失败；等待原对照正常完成后再次核验，没有重跑或改变测量输入。失败日志均保留。

## 完整目标实际结果

原 61 块/58 MoE、128 rank/1024 请求在相同预算下完成构图与全部校验，并进入实际写出；随后触及 900 s 上限，导出未完成。[result.json](result.json)保存阶段、资源、计数、文件大小和日志摘要引用。

|---|---:|

| 首次完整合并返回 | 584.414 |
| 校验中的完整重构返回 | 887.708 |
| 全部构图校验返回 / 进入实际写出 | 896.514 |

完整计数为 7655238 节点、3767694 次传输（3741764 fabric / 25930 local），与原独立预检相同。只发生两次完整合并，没有导出前的第三次重构。采样峰值 RSS 为 33902088192 B，约 31.57 GiB，低于原 32 GiB 上限。停止原因是 wall_limit，worker 被 SIGTERM 终止（-15），外层退出 1，无残留进程；没有内存或产物触限。

保留了 layer.0.et 至 layer.5.et 六个 Chakra 文件和 schema，最后一个文件可能被截断；没有 plan.json、graph-resources.json、generation.json 或 export_end。built.json 仅为计数，部分文件不代表完整可加载图。目标 C++ 加载、目标网络执行均未开始。本次构图器没有改动，构图 896.5 s 与上步 876.6 s 的差别只作单次观测，不声称完整目标提速。

## 回归与交接

完整目标停止后，串行执行真实 UB 回归。原完整服务基准仍为 5 轮、305 次写、113664 业务字节、131279 ns；8 组服务对照、空服务及 6 项后端篡改拒绝通过。新入口生成的 61 块小 EP 图完成 754 次写、986 次交付、3102 节点，耗时 315509 ns；穿插 dense 且无 shared 的图完成 26 次写、34 次交付、114 节点，耗时 10829 ns。依赖、计算时长、收发回调和资源清零均核对。

小图 C++ 加载为 171 节点、39 fabric/12 local；修改 JSON 和截断 Chakra 正确拒绝。四块、61 块、穿插 dense 三组历史小图的计划、生成清单及 Chakra 共 15 个文件摘要一致。1304 个受保护文件与 13 个递归依赖未变；复用的三个二进制各自仅链接对应构建中的 ns-3-UB，没有 C++ 重编译或子模块修改。

本步骤完成并本地提交，不推送；M10 最终验收仍未完成。下一项建议测量并处理实际序列化与文件摘要开销，须考虑当前构图和校验已消耗约 896.5 s，不能保证仅优化写出就能在原上限内完成。此候选尚未实施，等待用户确认。完整服务规模、64 步累计持有、AWQ4 路由来源与 INT8 容量参考的差异、参考费用及未校准状态均保持原记录。
