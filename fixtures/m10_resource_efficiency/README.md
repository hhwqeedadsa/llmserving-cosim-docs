## 成功结果与验证边界

完整首轮的构图、加载、网络执行和导出均完成；五类网络结果对照、8/32 轮释放、完整网络四块等价性以及损坏输入拒绝通过。UB 的 `a9539dd` 只在网络实际空闲后清理已结束 Jetty 的 TA 历史，保留 TP、MSN/PSN 累计状态和业务事件；8/32 轮序号历史峰值均为 118，排空后清零。

本任务原始首轮执行发生在这项 UB 回收补丁之前，补丁等价性由完整网络四块和小型多轮对照验证。后续[正式首轮重放](../m10_research_slice/README.md)另核对完整目标，不将上述阶段混成一次运行证据。

本任务累计磁盘预算为 20 GiB，实测峰值约 18.85 GiB、最终保留约 10.25 GiB。大图、成功执行及停止的测量均先建立清单，顺序重读归档核对大小、SHA-256 与路径集合，再回收登记的展开副本；历史保护文件和原始路由保持。归档成功只证明文件可恢复，不会把失败运行变为成功。

监测器按 PID 与启动时间跟踪本次进程树，包括另设进程组的后代；终止后回收孤儿且不影响启动前已有进程。磁盘按唯一 inode 计算，文件内容与实际分配取较大值，不跟随文件符号链接。RSS 和磁盘为采样值；这些宿主预算与模拟 HBM 分开。

## 保留的失败与范围变更

- 旧整树加载和单独 JSON 解析触及 48 GiB RSS 上限；后续逐层加载才完成。
- 首次首轮运行在约 5.2% 写完成时，辅助文本接近 1 GB，因累计磁盘预算主动停止；后续减少辅助诊断。
- 第二次运行测得原 3600 s/3 GiB 限额不足，主动停止；随后单次首轮采用 7200 s 宿主时间、6900 s 后端等待和 4 GiB 压缩记录预算，内存及累计 20 GiB 磁盘不变。
- 完整网络和大图共同驻留诊断、交接时 RSS 测量暴露了额外峰值，因此又释放重复描述符和空闲堆页；计数清零本身未被当作内存足够的证明。

[final-run-budget.json](final-run-budget.json) 和 [final-run-inputs.json](final-run-inputs.json) 保存原 64 步运行候选及输入摘要，**该命令没有执行**。2026-10-05 用户将收尾改为复用完整首轮、离线采样和后端重放；七天服务/两天导出/320 GiB 的旧候选不再是当前实验要求。完整 64 步、长期持续并发和目标硬件校准仍无运行证据。
