# 原生完整目标首轮验收输入

本目录声明完整目标的原生操作、记录和预算。执行状态与最终证据只在[当前任务](../../docs/tasks/current.md)登记；下列输入和预检命令不表示完整规模已经通过。

目标保留 [CM384/R1 参考场景](../../docs/scenarios/cm384_r1.md)的 128 rank、1024 个独立真实请求来源、61 块、七平面完整物理网络，以及首个 Decode 入口和参考计算成本。Dispatch 向量改为 STORE，Combine 向量改为 LOAD；应用状态和每段 LOAD 的 32 B 供数通知使用真实 STORE。必须重新构图，不从旧 WRITE 图替换枚举或复用历史包时刻。预计 4,703,152 次交付（其中 4,677,222 次网络、25,930 次本地）与 9,526,154 个节点；唯一网络业务量仍为 10,058,044,416 B。

`config.json` 显式选择每端点一个原生 worker，STORE 请求/LOAD 响应粒度为 4096 B，每 worker 最多 32 个未完成请求，每发起方最多 256 个线上请求编号；每 rank 一个逻辑发送槽、向量分块 8192 B，seed/run 均为 1。固定路径候选、逐包喷洒、CBFC 和既有物理拓扑由实际对象核对。选择一个 worker 和 4096 B 粒度是本次声明的模型参数，会影响包数和时序，不是对宿主运行无影响的优化，也不代表目标硬件的线程数或请求粒度。

观察 42 个物理出口：每个平面上服务器 0、7 的 L1 各取设备口 0 和上行口 16，并取该平面第一个 L2 的服务器口 0、7。它覆盖所有平面的所选 L1/L2 方向，但没有观察其余端口。基础窗口 100 µs，声明 `[0,1 s)`；只有 L1 节点 768 出口 16 的前 100 µs 保留详细事件。五类应用消息真值、操作阶段和 VOQ/FIFO 等待统计均开启。这是功能及规模验收配置，不能据此声称保存了全网最细粒度事件。

构图输入来自 M10 已逐文件核验的首入口 bundle，先核对固定摘要，再保留所有路由、成本、层和部署，只新增明确的原生映射。来源账户与大文件未随 Git 提交，也不会在此下载；迁移机器需要先取得对应原始输入或已核验 bundle。生成器和最小公开示例分别为：

```bash
PYTHONPATH=python python scripts/prepare_native_target.py \
  --prepared 已核验的prepared.json --output-dir 新的输入目录
```

实际执行时该命令及后续重型操作须置于当前任务声明的 `host_probe` 预算下；它本身不执行网络。输出的 `full/prepared.json` 包含完整图输入，`prefix/prepared.json` 只用于资源预检。`--prefix-moe-blocks 2` 可测第二个前缀，不能把前缀结果当作完整首轮通过。构图沿用 `python -m moe_ub_cosim.full_round_probe target --input ... --compact-plan --output-dir ...`；该命令仍调用生产构图和完整校验。

`scripts/run_native_target.py --help` 列出图、来源网络、后端和配置参数。它使用生产 `cosim/1` 重放驱动，只提交重建后的首轮图，由当前 UB 网络完成事件推进；它不运行 64 轮服务，也不声明请求调度器完整执行。每个阶段保留输入、命令、退出状态、实际计数与资源退出。研究导出使用生产流式导出器，继续独立检查字节、回调和来源守恒。

无需外部数据的小型完整操作见[原生首轮示例](../../examples/native_first_round/README.md)，对应自动检查 `tests/integration/check_v04_workflow.py`。新增 `resolve` 和后续 `run/slice/sample/replay/validate` 共 14 条公开命令已在新目录检查；定向限速改变后续实际时刻，未记录范围的采样在创建输出前拒绝。

前缀构图测出原生路径曾重复复制大图、对私有 CANN 中间图反复重建自检。当前内部使用自有图并索引各 rank 的收发；完整原生规范重建、逐字段比较、完整模型重建和 C++ 图校验仍执行。`tests/integration/check_native_graph_equivalence.py` 比较优化前后计划、128 份 Chakra 文件、生成摘要和 schema 源码的精确字节；编译命令中的输出路径与 Python 缓存中的文件路径、时间戳单独说明，不视为任务差异。非法依赖、字节、来源及计算耗时仍拒绝。首次资源脚本误把图目录视为平面目录，已修正为递归处理，失败日志保留于 `runs/v04-platform/m16-prefix-native/`，当时未启动网络。

资源前缀及构图优化证据见 [preflight.json](preflight.json)。两次原生后端前缀峰值约 5.50 / 6.27 GB，线性外推约 45.80 GiB，只是预检估算；实际完整运行仍由 48 GiB RSS 上限监管。已将三份预检图共约 810.5 MB 封存为约 58.9 MB，并逐文件校验归档后回收所有登记的展开副本，保留原基线、实际结果与失败日志。维护入口为 `scripts/archive_v04_graph.py`，只允许当前任务登记目录中的确切文件和显式 hardlink 副本；完整目标图也将在完成后封存，再进行研究导出。
