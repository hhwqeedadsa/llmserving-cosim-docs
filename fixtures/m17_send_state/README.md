# M17：端侧发送资源记录验收

本任务补充真实调度队列与发送资源集合的被动记录，不修改发送槽模型、完成事件或网络协议。用户输入和操作在[发送资源小例](../../examples/send_state/README.md)，字段与覆盖定义在[输出说明](../../docs/record_storage.md#端侧发送资源状态)；此目录只保存验收范围和结果。

## 输入与检查

使用仓库内合成输入：三个非连续编号 rank（2、7、12），一个稠密层及三个 MoE 层，原生 STORE/LOAD、供数通知、两条逻辑发送序列、逐包喷洒和有限出口速率。单槽用例运行两轮并关闭来源真值，双槽用例运行一轮；两者各自比较采集关闭/开启，业务和其他配置完全相同。它们用于覆盖不同功能，不能按这两个不同轮数直接计算单槽/双槽性能收益。

稳定检查入口为：

```bash
python tests/integration/check_send_state.py \
  --build-dir build/m17-send-state --output-dir runs/my-send-state-check
```

检查程序通过公开命令解析、运行、保存切片、采样、重放和校验，不使用旧运行资料。执行前应按宿主预算选择新输出目录；本次实际采用 8 GiB 驻留内存、12 GiB 地址空间、单阶段 1800 秒、共享累计产物 48 GiB、至少 20 GiB 空闲。公开小例内部使用更小的单阶段预算。完整命令、工作目录、退出码和日志在 `runs/m17-send-state/`；各累计目录与限额见 [result.json](result.json)。

独立核算逐段比较：从任务图显式依赖和实际节点执行构成“就绪到提交”“提交到释放”区间，核对每个正时间段的待发数和占用数；各 SEND 再与真实网络事务或本地交付回调对应。此核算仅用于平台测试，不作为公开观测的生成方式。同刻更新由连续序号保留，扫描内部的瞬时变化不冒充采集结果。

## 结果

2026-10-08 验收通过，详细值和二进制摘要见 [result.json](result.json)。

| 用例 | 完成轮数 | SEND 节点 | 状态记录 | 就绪待发累计 node·ns | 仿真完成 ns |
|---|---:|---:|---:|---:|---:|
| 单槽、来源真值关闭 | 2 | 234 | 281 | 34,697 | 90,224 |
| 双槽 | 1 | 117 | 145 | 0 | 47,193 |

双槽可同时容纳该输入的两条发送序列，因此零等待是明确检查项。单槽峰值占用为 1，双槽为 2；均覆盖计算进行但没有待发任务的区间。单槽跨两张图保持记录连续。数据就绪早于发送资源释放的事务分别有 138 / 69 条，LOAD 分别有 36 / 18 条，计数始终归属发起方实际占用。

采集开关前后，实际节点、网络和本地传输、原生任务事件、既有端侧操作与阶段、包与队列表逐项一致，各端口的包字节及发包时刻摘要相同。另通过：只复制 `observed/` 的独立校验、rank 负偏移与漂移的采样、冻结图后端重放、未采集旧切片拒绝升级、记录不足时明确失败。旧切片拒绝不创建输出；预算失败保留失败清单和原因。

相关 Python 单元检查 28 项通过；C++ 检查覆盖实际槽容量/占用/释放，以及状态去重、同刻顺序、未排空拒绝、初末边界和记录上限。新目录原生构建成功；保存依赖提交后，公开 `moe-ub build` 入口再次核对锁文件并完成构建与链接检查，仅使用该构建的 ns-3-UB。207 个文档本地链接目标存在。

运行阶段约 0.84～1.05 秒，采样进程树峰值约 102～104 MiB；后端重放约 0.34 秒。独立构建约 480 秒、采样进程树峰值约 1.80 GiB。小型运行有采样波动，不据此推断记录开销的性能改善。共享磁盘扫描增加了外层监控时间；外层短进程可能未被 RSS 采样捕获，运行内层报告与编译报告分别保留。新增构建与全部验收产物约 110 MiB，共享累计约 37.91 GiB，未删除旧产物或提高预算。

两次检查驱动失败也保留：第一次将 `LOAD` 字段错误写成小写；第二次错误要求双槽用例仍产生等待。修正为实际格式与“两条发送序列、两个槽”的明确零等待断言，保留单槽非零等待和全部独立计数核对。使用 `--resume-completed` 复核并复用已成功命令，未重复这些已完成仿真；所有失败日志仍在原目录。

以上是合成输入上的功能验收，不是新增观测对关联算法的信息增益实验，也未增加硬件校准或完整目标规模的结论。
