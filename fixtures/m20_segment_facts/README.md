# M20 有限层段与内部事实验收

用户输入及完整命令见 [A3 层段小例](../../examples/a3_segment/README.md)，格式见[输出数据](../../docs/record_storage.md)。本目录只保留验收摘要；详细命令、输入副本、退出状态和资源报告在 `runs/m20-segment-facts/`。

- `public-4/results/`：原始第 2、3 层，3 个请求、3 个 rank；完整模型容量保持。448 个节点、66 次交付，仿真结束 3414 ns。内部事实覆盖、缺少范围拒绝和数量超限失败均通过。移动保存目录并隐藏来源后，在不加载前端依赖的环境中采样和真实后端回放，所有有界执行表逐行一致。
- `load-check/`：C++ 普通与紧凑保留模式一致；拒绝修改初态、起始层、上下文、格式声明与工作量的五种输入。
- `python-regression/`：29 项层段、A3、完整模型、存储与首轮边界检查通过。
- `legacy-public/`：原首轮示例的运行、保存、搬移、采样、回放、有效输出与非法输入检查通过。
- `build-2/`：实际构建 `cosim-service`、`cosim-plan-load-probe` 通过。

失败保留：`build-1/` 是 C++ JSON 到字符串集合插入的重载歧义，已显式转换；`public-1/2/3/` 分别发现示例格式与端口服务字段不匹配、物理放置与生成网络不一致、缺少聚合采集要求的图资源预算，均修正示例后验证。没有提高宿主预算或修改验收断言。

构建与检查采用 RSS 8 GiB、单进程地址空间 12 GiB、1800 s 和既有累计 48 GiB 的外层监控；公共命令还有示例自身较小上限。记录导出是离线操作，前后封存产物校验不变；新模型采集启停的在线对照纳入 M21。以上证明功能与一致性，不是硬件精度或真实业务瓶颈结论。
