# M3.4 服务边界输入

沿用给定就绪 KV、四成员 EP 组、每 rank 每轮最多一个真实 Token 和既有单层计算配置，不添加虚构请求。没有本地 Token 时省略 attention/打包、Combine 解包合并和后续本地计算；没有专家输入时省略专家计算与专家局部合并。省略计算后保留必要的本地收发依赖，完全没有工作时导出仅含元数据的成员图。整组全部图先装载再激活，仍等待四成员各自完成。

`sparse.json` 只有 rank 0 的请求 101，三步路由为 [2,4]、[0,1]、[6,7]。第一步 rank 1/2 只执行远端专家任务，rank 3 图为空；第二步全为 rank 0 本地工作，没有业务网络传输；第三步 rank 3 从此前空闲变成远端专家计算成员。两专家同在 rank 3 时按原模板去重，输入和结果各传一份。使用既有 `fixtures/m2_single_layer/network`。

`uneven.json` 使用既有 M3.2 八 NPU 网络。ep0 的 rank 0 请求 101 在 0 ns 到达、执行三步；rank 1 的请求 102 在 5200 ns 到达、执行一步，rank 0 的请求 201 在 5500 ns 排队、执行一步。ep1 的 rank 4 请求 301 在 0 ns 到达、仅执行一步本地专家计算。用于核对组内忙闲与结束不均、同 rank FIFO、独立组提前完成以及输入耗尽后仍在途。

集成检查已执行 sparse 来源开启/关闭/不挂观测/重复四次，uneven 一次，以及单步纯本地与空请求两次，共七次正常运行。逐个真实 Token 核对专家与传输字节、局部计算时刻、完整组完成、请求进度和最终资源。若出现填充 Token、无工作耗时、空闲成员永久等待、组内提前换图或输入耗尽即退出，则验收失败。

失败检查包括初始/中途 EOF、没有工作和未来唤醒的前端状态、后端仿真上限、运行中真实后端进程被终止、坏成员图整组拒绝，以及独立 `cosim-service-deadlock-test` 故意不激活一个成员所造成的等待。测试目标和进程故障驱动不用于正常服务。保留原始 stderr、协议、前端 failure.json/manifest.json 及可捕获异常的执行目录 failure.json；信号直接终止时不声称 C++ 已正常清理。

正常结束仍须网络排空。运行中无后续事件的等待按实际事件触发检查，不用固定步长推进；仍有网络队列或未完成事务的异常由失败上限记录当前资源，不能把上限触发称为已证明死锁。上述均为未校准的合成功能输入，不包含丢包恢复或 P/D。

实际七次正常运行和七项预期失败均通过，命令和日志见 [环境记录](../../docs/environment.md#2026-09-29m3-4-service-boundaries)。sparse 三步分别在 12920、28920、45502 ns 完成，写次数为 4/0/2，合计 49152 业务字节。uneven 的 ep1 在 16000 ns 完成，ep0 四轮于 12920、30343、43263、59263 ns 完成，总计 16 次写、131072 业务字节。纯本地一步耗时 16000 ns、无网络包；空请求为 0 ns、无业务图和包。

初始与中途 EOF 分别在 0/12920 ns 报错；坏空成员图在激活前被整组拒绝。遗漏成员激活在 19513 ns 报告死锁，保留 rank 3 未登记发送而对端等待接收的身份；上限测试在 5200 ns 报告尚未完成的任务。真实后端被 SIGTERM 终止时退出码 -15 得到保留，前端未把尚未收到的完成通知写成成功。
