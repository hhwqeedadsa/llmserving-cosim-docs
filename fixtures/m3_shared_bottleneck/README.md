# 共享瓶颈功能对照

本用例检查同一仿真中的两组通信争用，及网络完成时间向计算与下一轮服务调度的反馈。沿用 M3.2 的两个四成员 EP 组、八专家、Top-2 人工路由、给定就绪 KV 和每请求三步解码。保留每 rank 每轮一个真实 Token、单发送槽、8192 字节分块和原单层计算时间，不加入模型层或真实数据。

`service.json` 保留请求 101～104（ep0，rank 0～3，0 ns 到达）与 301～304（ep1，rank 4～7，5500 ns 到达）。`network/` 明确连接偶数 NPU 到交换机 8、奇数 NPU 到交换机 9。八条接入链路为 400 Gbps、20 ns，两交换机的端口 4 之间为 10 Gbps、20 ns。组内跨奇偶 rank 的传输必经共同链路；正反方向各自排队。路由、TP、专家映射显式列出，所有对照保留同一拓扑和路径。

`observation.json` 选择交换机 8 的端口 4 出口，按 5000 ns 窗口累计成功发送开始时的整包字节。原属性文件逐字沿用 M3.2，重传、故障和拥塞控制关闭，CBFC 保留。功能后端继续禁用原生周期队列记录和自动解析，使用事件驱动审计，不以定时采样推进仿真。

实际运行以下矩阵，除列出的差别外保持输入相同：

| 场景 | ep0 | ep1 | 目的 |
|---|---:|---:|---|
| solo-a | 0 ns | 无请求，保留四个空闲 NPU | 第一组独立基线 |
| solo-b | 无请求，保留四个空闲 NPU | 5500 ns | 第二组独立基线 |
| overlap | 0 ns | 5500 ns | 同一网络真实重叠 |
| staggered | 0 ns | 500000 ns | 只改变第二组到达，移除重叠 |
| overlap-off / absent / repeat | 同 overlap | 同 overlap | 来源关闭、不挂观测、重复执行 |

预期 10 Gbps 出口产生可观测的连续发送与排队，overlap 至少有实际传输和依赖计算晚于独立运行，相应 wave 完成及下一轮提交随之变化；不要求每条传输都变慢，也不预设平均带宽。若两组未经过相同出口、第二组开始时旧队列已不存在、争用未影响依赖/下一轮调度，或错开后仍存在重叠，本次输入不能证明 M3.3 目标，应保留失败并检查原因。

逐次保存协议、生成图、请求进度、真实传输回调和原始 ASTRA/UB 日志。内部 `egress-queue-audit.jsonl` 记录物理出口 FIFO 的入队、出队和发送开始、报文 UID、整包大小、事件后的排队字节及真实端口忙碌截止时刻；该 FIFO 不含交换机 VOQ、信用等待或正在序列化的包，不能据此声称测得全路径排队。审计不修改包，不增加仿真事件，且不进入 `observed/`。`truth/packet_ranges.jsonl` 与操作、传输登记用于内部核对两组窗口贡献；`observed/` 仍仅含聚合端口计数和端侧记录。

集成检查按实际收发事件验证局部前驱，按组比较相同 Token、专家、传输端点/字节与计算耗时；运行内身份可因提交交错而不同。对照只比较分别执行的结果，不把它们拼成重叠流量。所有结论限定为未校准的合成单层功能模型，共享链路效应不代表任意并发都变慢。
