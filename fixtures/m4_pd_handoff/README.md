# 单请求预填充与 KV 交接

本输入验证 M4.1 的 `between_iterations` 生命周期。`model.json` 明确声明合成模型 `cosim_tiny_moe`：一层、hidden 256、intermediate 512、八个专家、Top-2、八个 MHA 头、head_dim 32，TP=PP=1。没有下载或运行实际模型权重，计算继续采用未校准的单层功能耗时。

`service.json` 指定 P 组 p0（rank 0～3）与 D 组 d0（rank 4～7），每 rank 放两个专家。请求 401 在 0 ns 到达，在 rank 0 处理四个 prompt Token；预填充路由逐 Token 给出为 `[2,4]`、`[0,1]`、`[6,7]`、`[2,5]`。预填充完成产生第一个输出 Token，交接到 rank 4 后再执行两步，路由为 `[2,4]`、`[0,1]`，共生成三个输出 Token。服务前端从实际请求进度替换 `layer.json` 中的图身份、组、rank 和 Token 样例；该文件提供通信与计算参数。

## 字节与容量

缓存布局两端均为 `layer-kv-token-head-dim-tp1`，单个 attention rank 持有本请求全部缓存。有效 BF16 KV 为 `1 层 × 2（K/V）× 4 Token × 8 头 × 32 维 × 2 字节 = 4096 字节`。K、V 各 2048 字节，分别按 768/768/512 拆分，共六次ns-3-UB 写。分片来源保留请求、层、Token/头范围、dtype 和布局；不传 Q。KV 图覆盖八个成员，rank 0 只有 SEND、rank 4 只有 RECV，其余为空图；没有解析通信时间或填充计算。

每 rank 的总内存为 4194304 字节，原生 MemoryModel 计算的权重为 2233856 字节，另预留工作区 65536 字节、通信缓冲 8192 字节。原生 KV 池剩余容量为 115 个块，每块容纳 16 Token，即 16384 字节。请求在源、目标各占一个块，传输只覆盖其中 4096 字节有效数据。只改变 `kv_dtype` 为 fp8 时，有效 KV 为 2048 字节、块为 8192 字节，权重、计算及激活 dtype 保持原输入。

目标块在发送前分配，D 尚无 running 请求或计算批次。P 的源块保留到全部接收、发送事务和八份图完成。后端通知 `KV_DONE` 后，前端释放 P 块，并让 D 的 `add_decode` 复用目标预留；原生调度、请求进度和块池均实际调用。输入检查拒绝超所选组总容量或显式目标 rank 容量的请求，不跨 rank 隐式重新放置。布局转换与容量争用排队不在本步范围。

## 网络与实际结果

八个 NPU 通过两个交换机连接，偶数 rank 接交换机 8、奇数 rank 接交换机 9；接入 400 Gbps、交换机间 10 Gbps、每条链路延迟 20 ns。本次在组内 EP 通道基础上显式增加 rank 0/4 的双向路由及 TP（双方 TPN=4）。KV 走 `0 → 8 → 4`；本例的 KV 不跨交换机间瓶颈，也没有独立组与 KV 同时竞争。观测取交换机 8 的端口 2，窗口 5000 ns。

| 场景 | P 完成（ns） | KV 最后数据就绪（ns） | KV 事务完成 / D 开始（ns） | 请求完成（ns） |
|---|---:|---:|---:|---:|
| BF16 基线；来源开/关、不挂观测、重复运行 | 40159 | 40830 | 40876 | 69994 |
| 仅 rank 4 接入延迟改为 2020 ns | 40159 | 62830 | 64876 | 101792 |
| 仅 KV 改为 fp8 | 40159 | 40564 | 40610 | 69728 |
| 仅请求到达改为 9000 ns | 49159 | 49830 | 49876 | 78994 |

BF16 基线共四份逻辑图（P、KV、D、D）、20 次 UB 写、11264 业务字节；三次真实 schedule，TTFT 为 40159 ns，两个 ITL 为 13835/16000 ns。ITL 包含实际交接等待。每份写只有一个业务任务、一次接收回调和一次发送回调，网络排空后正常结束。

`tests/integration/check_pd_handoff.py` 执行上表七次运行，以及布局、策略、dtype、总容量、KV 大小、Q 分片、字节范围、末成员图损坏、缺少组成员、组忙时交接、后端被信号终止共十一项失败检查。信号用例截住真实 `KV_DONE` 后终止后端，前端保留尚未确认的交接和两侧容量，不生成成功结果。来源开/关、不挂观测和重复运行的业务、协议及原生网络日志相同。
