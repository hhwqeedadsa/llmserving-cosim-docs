# 主服务消息缓冲隔离验收

本轮为平台功能，不是新的恢复算法或收益实验。前置方法登记于 `0678871966`，范围见当前任务。可直接查看[网页](report.html)、[机器可读证据](summary.json)、[配置与边界](../../docs/message_buffers.md)及[独立复现例](../../examples/scaleout_message_buffers/README.md)。

实际原生网络共两次，各运行一次，都为128端点Clos、SR和参考DCQCN。人工输入为四份独立人工请求、两个EP64组；真实输入来自用户提供的R1-AWQ/MMLU四份原件1472、1808、2675、6447，分别进入四个EP32组。两条件都只有两层、两步Decode、每rank最多一个源请求，路由专家E256/K8；真实条件隐层7168。标记载荷、声明计算、已部署备用专家和零控制放置耗时均不能写成真实生产推理性能。

两网络均为20个交换机、逐链路400Gbps/1µs，DATA载荷和chunk上限9000B；机内旁路关闭。GPU标签为H100，没有真实H100执行或计算Profile校准。SR初始RTO80µs、最大640µs、最多3次重试；这些是固定参考配置，不是生产RoCE参数测量。

| 条件 | 消息数（含备用） | 实际目标写入 | 源发送含重传 | 源/目标缓冲峰值 | 最终保留 |
|---|---:|---:|---:|---:|---:|
| 人工功能例 | 64 | 38,912 B | 39,552 B | 19,072 B | 0 B |
| 四份真实专家选择 | 216 | 3,117,312 B | 3,131,776 B | 1,832,640 B | 0 B |

两次各完整退休一个备用贡献。人工条件在前20µs丢弃发往GPU6的DATA，真实条件以首组首层Dispatch字节量选GPU32；实际丢包分别1包、2包。原消息、ACK、阶段门限与后继保持。真实例原件输入在83.502µs完整到达、85.504µs确认；备用结果在26.073µs到达、28.075µs确认并退休，原件目标范围仍保留到129.271µs整图退休。该差异证明并发在途数据和分开清理，不是已实现的应用加速。

纯C++核心通过45项内容/范围/生命周期断言；Python新增8个测试方法，含独立FNV向量、SR乱序/重复/跨消息边界、GBN字节、同纳秒ACK/新post副本峰值上下界及非法配置/历史。arena峰值按事件精确重建；副本ACK在原生回调先释放，而服务ACK稍后同刻执行，不能强制二者峰值相等。受影响流接口39项、helper接口11项回归通过。两次公开 `rdma-run` 自动检查及随后独立 `rdma-check` 均通过；保存结果再分别拒绝10类篡改，共20项，包括错误源/接收字节、源目标地址别名、提前释放、伪造scope、重复写入、错误摘要、占用错误、缺失释放和未释放传输副本。

一次全新公开完整构建通过，显式使用本机已有CMake/Ninja/Protobuf；13项依赖状态检查通过。旧默认条件公开只读检查通过，369份旧文件SHA256全部不变。没有新增第三次默认网络；旧记录通过不等于新构建默认网络已重跑。网页为静态内容与本地链接核查，不声称浏览器渲染。

失败保留：最初C++测试驱动把后续消息时间倒退，核心拒绝后修正驱动；第一次构建调用在配置前因PATH缺Ninja失败，随后显式指定已有工具；第一次真实输入准备由于三个无源EP组被拒绝，改为四组各一个不同请求。最终材料核查曾误把queue_capture字符串当对象，保留失败并按实际字段修正。没有放松原准入断言、缩减端点、下载依赖、扩增事前宿主预算或重跑成功网络。
