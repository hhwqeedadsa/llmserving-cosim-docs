`audit.py`只用标准库，从完整、覆盖全部所选交换机的实际BEgressQueue入出队事件重建每优先级队列，独立核对快照及MMU计数。仅针对本例原生UDP优先级3/控制优先级0；不泛化到未知优先级策略。对三份结果各进行改队列、改共享计数、删端口的篡改拒绝。它没有把内部真值供给在线策略。

`verification.json`、三份`*-audit.json`、`recovery.json`及`closeout.json`保存摘要。完整命令、源码、结果、构建和监控在`/dev/shm/moe-mmu-snapshot-20261024/`；本机持久包为`runs/mmu_snapshot_checkpoint_20261024/checkpoint.tar.gz`，11,749,459B，SHA-256见`recovery.json`。持久目录另存最终收据、失败及监控，`manifest.json`校验这些外部记录。

## 离线复核与恢复

包内`manifest.json`为482成员中的文件清单，`source/`含Python/后端及小例，`evidence/`含输入、结果和三种探针程序，`runtime/lib/`含八个固定ns-3库。源码快照用于审计，不含完整第三方构建树；这是同Linux宿主的运行检查点，不是跨平台编译保证。

在新目录核验SHA-256后解压，可从空cwd执行：

```bash
python3 -B /path/to/restored/source/fixtures/mmu_snapshot/audit.py \
  --result /path/to/restored/evidence/queued/result.json \
  --output /path/to/new-queued-audit.json
```

新源码根/空cwd实际执行了公开`rdma-probe`，使用包内已hash核验的拓扑和示例输入，八个ns-3库实际从包内加载。结果仅加载库路径变化；完整诊断逐字节相同。三份离线审计也逐字节相同。该重放是为核验迁移可用性，不能当独立研究样本。

恢复检查的拓扑再生成曾被错误的产物监控范围在创建子进程前拦截：将整轮静态输入/恢复库113,631,232B计入了单命令64MiB，而全轮预算为192MiB。保留失败，不提高限额、不重试该拓扑命令；后续仅执行尚未开始的公开网络与离线检查，按单命令输出范围和全轮总量分别计量。因此不能声称在恢复根重新生成过拓扑。具体见`artifact-monitor-correction.json`。

57份监控保守合计38.68秒，峰值采样RSS约722.55MiB，原件/恢复/持久副本合计约122.27MiB，加128KiB末次收据预留仍低于192MiB；450秒及单命令60秒/1GiB/地址2GiB/64MiB保持。无遗留受监控进程。只增量编译Fabric和普通probe，链接受影响事务入口；没有重建/修改依赖、安装下载、GPU或旧失败研究重跑，仅本地提交不push。

该能力使后续物理故障试验的缓冲会计可核查，不构成硬件校准、完整链路恢复或论文创新证据。
