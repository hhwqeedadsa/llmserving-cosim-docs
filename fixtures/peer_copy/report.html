收到的跨机字节，可以继续走机内网络，再发回远端

本次补上持久事务缺少 GPU 间机内转发的实现。机内和机外共用一个 ns-3 时钟，目标只在实际交付时写入，后续任务由完成通知推进。

4 / 4预定功能网络通过
512 B机内实际转发字节
2 个 / 576 B远端源数据包 / MRT1载体

传递链路

服务器 A：GPU0、GPU1 → GPU2 → 跨机网络 → 服务器 B：GPU4 → GPU5 → 跨机网络 → GPU0。

GPU0/1 各提供128B不同字节，GPU2 合成256B发送。GPU4收到后把同一组字节交给GPU5，GPU5再从窗口读出并回传。后续阶段没有重新生成标记。

验证了什么

  • GPU2目的端口共享：两条128B转发分别在276/340ns完成，端口繁忙256ns、最大等待128ns。
  • 独立重放20项内存事件，核对源保护、开始时捕获、完成时提交和最终字节。
  • 逐项核对实际物理发送/接收、路径两端口、序列及ACK，共24次逐跳发送；机内转发不增加物理RDMA包。
  • 直接执行与依赖前端的核心结果相同；迁移后的完整结果只允许已核实的运行库路径和枚举顺序差异。
  • 7类非法输入在创建输出和启动后端前拒绝；7类证据篡改被独立核验器拒绝。

这一步能支持什么研究

可以继续接入“跨机先送到某张GPU、再在机内转发”的分层通信依赖，避免把域内转发误算成机外RDMA。它补的是模型正确性，尚未建立新的仿真创新或性能收益。

本例为2台服务器×4张逻辑GPU，机内8Gbps、每跳10ns、64B分块，机外100Gbps、每跳1µs。GPU类型为NONE，属于声明参数；不是GPU执行、NVLink/TMA/GIN/RoCE成本校准、真实MoE调用或千卡实验。

新增路由数据的来源已确认为DeepSeek-R1-AWQ/MMLU；本次人工功能例没有使用这些文件。完整Hybrid的slot、屏障、计数、Combine执行及强基线收益验证仍待完成。
