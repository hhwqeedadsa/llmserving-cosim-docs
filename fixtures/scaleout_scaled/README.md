# 显式规模预算、完整形状模型与机内织构验收

本目录记录非 UB Scale-Out 新增 schema 的独立功能证据；输入在 [examples/scaleout_clos128](../../examples/scaleout_clos128/README.md)，平台不导入研究实验代码。

[evidence.json](evidence.json)保存最终实现的 16 卡与 128 卡真实运行校验、模型容量、资源、源码/二进制哈希和持久压缩证据摘要。128 卡实际执行 Qwen3-30B-A3B 完整 48 层、两轮 ready-KV Decode：195082 条消息、489492 个节点，完成于 2121369 ns；同机/跨机消息均由同一个 Simulator 反馈。模拟计算为声明成本，专家路由为合成输入，未执行数值模型或做 H100 校准。

先前 128 卡运行退出正常，但约 110 MiB 滚动日志覆盖早期事件，独立校验拒绝。新增不滚动的 `astra_nodes.log` 后修复，旧失败仍保存在原记录中。资源表示优化包括：空闲 KV 元数据按需分配、ASTRA 完成组才控制往返、不重复保留完整图 JSON/消息描述、终态转移及流式序列化。最终 128 卡结果与改动前紧凑版本逐字节相同；旧 8 卡基线除加载库路径及空控制往返计数外，网络及业务结果相同。该比较证明相应表示改动的结果保持，不冒充同一版本两次独立重跑。

机内 1 MiB 单源为 2605 ns；双源同目的为 4936/4973 ns，检查目的出口共享。两条相同线端口号、不同端点的 RDMA 消息恰好一次完成。完整消息身份保留 int32 tag，端点/端口身份冲突拒绝，不静默覆盖。

检查：34 项 Scale-Out 单元、2 项稀疏/原始块池等价检查、5 项共享服务回归、13 个锁定依赖通过。共享服务检查初次缺少 PATH 中的 protoc；补入已存在工具路径后通过，无安装/升级。完整模型首尾/层数、上下文成本、GQA KV、身份和机内消息的独立核算见单元检查与实际校验。百卡预算仍为单例300秒、RSS6 GiB/地址空间12 GiB、阶段累计3 GiB，不通过自动加预算挽救失败。

原始证据持久保存在本地 `runs/scaleout_clos128_20261016/evidence.tar.gz`，包括失败/修复/优化运行及构建 provenance，不包含编译对象或外部依赖源码。Git 保存必要小型摘要；复现使用公开 `scaleout topology/rdma-run/rdma-check`，构建使用锁定依赖，见用户示例。千卡多组执行另由[规模实验](../../experiments/scaleout_scaling/README.md)验收，不能从本目录百卡结果外推。
