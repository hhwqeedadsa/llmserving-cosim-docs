# 多步完整片段的执行边界

[执行前证据](pre-network.json)记录71项不同CPU检查、10份旧真实网络结果的只读兼容核验、公开独立人工输入与15份真实路由两步输入的准备。实现见[完整备用接口](../../docs/whole_call.md#多步decode的完整备用)，操作见[双任务示例](../../examples/scaleout_multicall/README.md)。未编译、修改依赖或执行GPU。

新增检查覆盖：首步完成不提交片段结果、不跳过备用；实际前驱完成驱动后步；最后一步提交唯一赢家；已启动输家继续完整执行；缺步/重步/错组/提前或滞后后步/首步冒充完整结果被拒绝；不同步数具有不同输入身份；真实LLMServingSim调度器在中间步保留备用KV，仅最后一步释放；旧格式继续拒绝多步。

多步通过显式replication/4准入，不放宽原格式。执行前检查不证明实际新网络已成功或研究收益。网络验收与研究对照分开记录；任何成功结果都必须保留全部原生图、阶段门限、接收/源确认与最终释放。

首次实际两步网络完成并排空后，公开run的离线检查错误地将后续提交图名写死为`gN.w0`，因此run返回失败。修复只改变检查器的下一图身份核对，新增复现检查；原生程序及运行时核心方法的AST均未改变。对已保存原件执行公开`rdma-check`通过，未重跑网络。原失败日志保留，只补存缺失的离线verification报告；既有每个原文件SHA不变，见[修复与原件依据](verification-correction.json)。执行前71项检查之外，新增此一项，累计72项不同检查。

[实际网络验收](post-network.json)将正常/局部故障的两份多步结果各迁移一次并公开核验；每份拒绝16类篡改，共32项。额外覆盖缺失最后一步、把中间步冒作完整结果、后步提前提交、第一步就释放备用KV。全部原件与恢复副本SHA一致，没有新网络执行。复核命令为 `PYTHONPATH=python .venv/frontend/bin/python -B tests/integration/check_sequential_run.py --run <已保存多步双任务结果> --output <新目录>`。
