# 交换机计数存储的功能与资源验收

事前范围见[平台规范](../../docs/tasks/switch_counter_storage_spec.md)，普通使用见[公开示例](../../examples/scaleout_counter_storage/README.md)。这里是平台验收，不是研究性能实验，也不运行已关闭的旧研究条件。

`run.py`只通过公开CLI生成拓扑和执行输入，按small→large分步推进；native阶段单独编译对象检查器。每个网络条件只执行一次，失败保留，成功的小例不会为了补分析而重跑。完整原件在本机`runs/switch_counter_storage_20261027/`，不提交生成的大型结果。

`verify.py`比较旧默认、新默认、显式legacy和port的所有动态结果；只规范化已登记的加载库路径，保留列表顺序及库文件名。非零计数独立核对物理degree+1、存储槽/载荷总量；小例的优先级0计数从实际到达/入队独立重建。沿用两份仅依赖标准库的独立验收器，分别核对小例全部物理包、最短路径、队列积分和回调，以及千端点的端点字节前缀、工作依赖、全网最短跳字节守恒。后者没有中间节点完整逐包采集，不能声称逐条中间路径已验证。

离线复核已有结果，不重新运行网络：

PYTHONPATH=python python3 -B fixtures/switch_counter_storage/verify.py \

`report.py`从核验JSON生成中文HTML。`checkpoint.py create/restore`保存来源源码、输入、结果、已结束监控和依赖增量bundle，并从复制源码/空cwd重算核验、报告、所有输入及4项输入检查。归档不包含二进制，不等同于完整构建的离线复现；增量bundle需要其记录的三个原固定提交。

阶段结束后在本目录保存`verification.json`、`identity.json`、`recovery.json`、`closeout.json`和[报告网页](report.html)。载荷内存、整次运行采样RSS和一次宿主耗时分开说明；不把资源改进称作MoE网络优化或已经成立的两项论文创新。

本轮功能与资源对照完成，**全部验收尚未完成**：4项新增Python输入方法、153项Scale-Out回归通过；一次完整公开Release构建成功（448项构建任务），独立对象检查器漏链接applications库而失败，8个初始化/索引条件未执行。修正后的链接命令尚未执行，两次构建额度已关闭，不将它们计为通过。

8次网络各执行一次。新默认与旧二进制默认完整一致；显式legacy/port在共享拥塞、断链失败及新1024短任务的动态结果与计数快照一致。健康4流产生101个CNP；断链条件在1,500,000ns有限失败，实际1,773次物理TX、1,767次RX、6次到达丢弃和1,318次本地丢弃。路径检查改为源码真正选择出口的入队时刻，原TX时刻检查会误拒绝跨路由更新保留的队列；原检查器和失败日志已保存，只重算离线结果。

目标实际32ToR/16Agg/2Core、1104链路、3072连接/8192工作、73,728次物理TX，54,718ns排空。矩阵载荷1,681,000,000→1,278,016B（减少99.924%）；两次公开CLI采样峰值RSS为2,261,610,496→591,900,672B，耗时3.972/2.747s。每模式一次，不宣称稳定加速或真实推理收益。初始准备器错误生成16ToR，headroom预检在零目标网络时拒绝；原件保留，只有ToR值修正到事前32ToR，其余输入逐字节相同，没有提高缓冲或宿主预算。
